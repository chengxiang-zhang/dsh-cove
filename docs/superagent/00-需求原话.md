## B 由原话推出的约束（按最新澄清解释）

B1 Router 是岗位，不是组件：有职责、边界、拒绝权（1、2、3）。
B2 它不亲自执行项目业务工作；但亲自组织提示词、读取会话与交接、派发、续接、观察、纠偏、回收和安排验收，这些协调操作就是它的工作（1、16、28）。
B3 要有人的工作方式：接活、拒绝、派活、主动报忧、按目标自驱出方案、批准后安排别人（2）。
B4 是代理：同时替老板与替他人办事，两个方向责任不同（4）。
B5 全自动靠交互磨合长出来，不是出厂配置（14）。
B6 老板对空跑与钻牛角尖的恐惧是设计输入，可观测与一步干预是必选项（15）。
B7 信息面 = 人的输入 + Agent 会话、汇报与协调消息 + 交接及交付文档 + 可核查的执行证据；代码调查与修改交给执行体（16、28）。
B8 记忆跨对话共享，按可见域隔离（5）。
B9 每张桌子都要像同一个人（18）。
B10 要投机执行与全双工；token 成本不是约束（19）。
B11 要知道自己的范围与存量（20）。
B12 规则要能注册，也要能自迭代（21）。
B13 模块化、插件化、能承载未知：人的细节一开始写不死（22）。
B14 系统内部故障（模型不可用、派发失败、空跑、停滞、打转、止损、重启对账）由系统自愈、降级或排队。需要老板决定时，先准备实质产品取舍、交付承诺变更、超出当前授权的动作或需本人判断的验收，给出默认动作。重要风险可以在无需决定时提前告知，不能让老板重发、重试、传话或替系统做技术选择（23、35、37、38）。
B15 续聊优先：追加输入必须被负责该事项的执行体消费；换执行体必须交接前情。临时事项与长期职责的区别是责任的结束条件，不能用会话寿命代替（1、25、28）。
B16 两种托管同时成立：有终点的事项做到验收交付；长期职责持续发现、安排、验证和再观察，不靠老板持续派活（24、25）。
B17 一个 Superagent 统筹多个项目、机器和 Agent；当前项目只是首个验证场景，不是产品边界（26、27、28）。
B18 托管的是老板完整的 Agent 操作循环；写提示词、判断进展、纠偏、结果回收与推进都不可缺失（28）。
B19 全自动不等于自动降低目标或扩大权限。技术障碍由系统处理；真正需要老板的决定必须已完成准备，已有授权持续适用（23、24，结合仓库授权边界）。
B20 首期只服务老板，代接他人请求预留；闲聊作为背景，正式接单来自明确委托或已授权长期职责（25、32、33）。
B21 方向型委托先调查、再带证据与建议集中提请决定；决定后自行拆单、调度和验收。用户参与实质变更与确需本人判断的体验验收（31、35、37）。
B22 原生执行会话连续性是交付约束；同一工单的评审退回或补充不能静默改为新会话（36）。
B23 交付风险的提前预警与到点跟进是秘书自己的责任。个人偏好跨项目，局部纠正保持局部（34、38）。
