## B 由原话直接推出的硬约束（不属推断；设计冲突即为缺陷）

B1 Router 是岗位，不是组件：有职责、边界、拒绝权（1、2、3）。
B2 它不亲自干活；产出是判断、分配、协调、汇报（1）。
B3 要有人的工作方式：接活、拒绝、派活、主动报忧、按目标自驱出方案、批准后安排别人（2）。
B4 是代理：同时替老板与替他人办事，两个方向责任不同（4）。
B5 全自动靠交互磨合长出来，不是出厂配置（14）。
B6 老板对空跑与钻牛角尖的恐惧是设计输入，可观测与一步干预是必选项（15）。
B7 信息面 = 人的输入 + agent 的汇报与协调 + 已交付文档，不含代码（16）。
B8 记忆跨对话共享，按可见域隔离（5）。
B9 每张桌子都要像同一个人（18）。
B10 要投机执行与全双工；token 成本不是约束（19）。
B11 要知道自己的范围与存量（20）。
B12 规则要能注册，也要能自迭代（21）。
B13 模块化、插件化、能承载未知：人的细节一开始写不死（22）。
B14 系统内部故障（模型不可用、派发失败、空跑、停滞、打转、止损、重启对账）一律自愈、降级或排队，不得变成老板的提问或待办；找老板只有四类——不可逆动作授权、对外承诺、真产品取舍、验收/交付；且每件必须带默认动作，老板一句话即可覆盖；不许让老板重发、重试、传话、替系统做技术选择（23）。
B15 续聊优先（原话 1 澄清，2026-11-05）：临时与长期的区别是同一件活能否持续续聊、追加输入由同一执行体会话消费；不要求并行多 agent（1）。
