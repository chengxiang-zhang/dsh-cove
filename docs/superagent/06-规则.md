# 规则：三层、三条通路、回放与自迭代

职责：把"什么能做、什么时候该问、怎么说、估多久、派给谁"从提示词里搬出来，变成可注册、可版本化、可回溯、可回放的数据；并规定只有哪一层能自己变。

边界：不执行判断（判断模块拿规则做判定），不写记忆（记忆模块的事）。规则只回答"条件成立时怎么办"。

## 三层，只有一层能自己变

| 层 | 装什么 | 谁改 | 自动迭代 |
| --- | --- | --- | --- |
| 宪法 constitution | 不执行具体事务；不替老板承诺；生产变更逐目标授权；模型不能改自己的授权与规则；交付必须带证据 | 只有老板 | 永不 |
| 策略 policy | 谁能对哪个范围做什么（allow/draft/deny）、哪些必须问、双主的两个回执 | 老板批，系统可提议 | 提议 → 人批 |
| 技巧 technique | 估时校准、执行体选择、问还是声明、异议频率、案卷瘦身、议程信号阈值 | 系统自己可调 | 自动生效 + 自动回滚条件 |

把"能不能"和"怎么做"分开迭代，是这一节的核心。混在一起，任何一次调优都可能顺手改掉权限边界——而那种错误发生时不报错，只在某天你发现它擅自改了线上配置。

## 规则的数据形状

```
rule {
  rule_id, scope_path             // 作用域用世界模型的路径
  layer                          // constitution | policy | technique
  when                           // 谓词，可机械求值
  then                           // allow | draft | deny | ask | escalate | notify | calibrate
  exceptions: [{when, then}]     // 显式例外，优先于本体
  priority
  provenance                     // config | extracted | inferred
  version, state                 // proposed | active | retired
  approved_by, rollback_if
}
```

`when` 只能由固定谓词集拼成：`sender_class`、`party`、`audience_class`、`capability`、`path_prefix`、`commitment_kind`、`prior_count`、`eta_bucket`、`budget_state`、`time_window`、`repo_visibility`。

禁止自然语言条件。一旦允许，它退回成提示词，既不能回放也不能审计。

## 三条注册通路

| 通路 | 触发 | 生效 |
| --- | --- | --- |
| config | 老板说一句或写一行 | 立即 active；宪法层只有这条通路 |
| extracted | 从一次纠正里提取（"以后这类先问我"） | 生成草案 + 出处（哪条消息、哪次推翻）→ 老板一句话确认 → active |
| inferred | 统计推出（连续 5 次这类活他都改了范围） | 永远只能 proposed，且只能落 technique |

同义合并：同 scope、同结论的多条 extracted 自动并成一条，权重相加。不做这一步，规则库三个月就长成几百条互相覆盖的碎片。

## 冲突：确定性解析，启动时挡住

解析顺序（可复现）：例外优先于本体 → 更长的 `scope_path` 优先 → 层高者优先（宪法 > 策略 > 技巧）→ `priority` 大者优先 → 仍并列即判冲突，拒绝加载，写 `rule_conflict`。

运行期不允许"看情况"。每次判定输出命中链 `rule_trace`：哪几条参与、谁赢、为什么。写进 `deliberation`，这是"为什么这次没问我"的唯一答案来源。

## 自迭代：产物是规则与注册项，不是代码

自迭代能改的只有四类东西，全部经由扩展点注册，且都不动内核与协议：

| 产物 | 谁能自动 | 怎么证明没长歪 |
| --- | --- | --- |
| technique 规则（阈值、问还是声明、案卷瘦身、议程信号） | 系统自动 | 回放 + 自动回滚条件 |
| policy 规则（谁能做什么、哪些必须问） | 只提议，人批 | 回放 + 老板一句话 |
| 新记忆类型（抽取器与默认可见域） | 只提议，人批 | 抽取器在最近 100 条上的精确率抽检 |
| 新能力清单（范围、执行体模板、完成判据） | 只提议，人批 | 干跑：只产出草案，不落账 |

四步闭环：

1. 发现规则错了。三种信号全部来自账本，不靠模型自省：`corrected`（老板明确纠正行为）、`overturn`（规则说 draft 而他总批，或说 allow 而他撤销）、`missed`（他说"你怎么没……"而当时该触发没触发）。
2. 提议。宿主统计出候选（推翻率 > 25% 的规则、missed ≥ 2 次的条件组合、30 天未命中的规则 → 退休候选）。模型只写解释，不许发明规则。
3. 回放验证。覆盖范围是明确规则：`provenance=config`（人写）的规则不参与回放，写入即 active；`extracted` 与 `inferred` 必须回放通过后才能生效（与读数的 provenance 过滤一致）。取最近 100 条同类事件，旧规则与新规则各跑一遍；输出结论改变的条数、方向、涉及谁。硬门槛：改变案例 ≤ 影响面上限（默认 10%）。
4. 生效与回滚。technique 自动 active，同时写 `rollback_if`（例如"同类推翻率回升到 20%"），命中即自动回滚并留记录；policy 走人批，旧版本保留可一键回滚；宪法只有老板能改，改动也记版本。

四条防失控硬规则：

- 规则迭代不能给自己扩权：任何 `(发送者类 × 能力 × 范围)` 从 draft 变 auto，必须走自动度梯度（人批），绕开规则引擎。
- 影响面上限：一条改动影响的历史案例 > 10% 一律挡回。
- 规则库有预算：active 规则上限 120 条，超了强制合并或退休。规则库腐烂比代码快，因为它没有编译器。
- 改动必须能跑成一次行为快照：同一批历史消息，改前改后各跑一遍，差异列得出来才准上线。

## 校准：技巧层的特例，全部由宿主算

每次判断写预测（工作类、置信度、预计分钟、预计执行体、声明或问），结案回填实际（实际分钟、尝试数、是否换执行体、假设是否被推翻）。校准 = 一次 join，每天跑一次，写回工作类。

| 不可靠的地方 | 信号 | 下次行为怎么变（宿主机械执行） |
| --- | --- | --- |
| 估时偏短 | 实际/模型估计的中位数，样本 ≥5 | 懂时系数 = 该中位数（夹在 0.5–4），受理时间 = 模型估计 × 系数；模型看不到也改不了 |
| 老选错执行体 | 首个执行体失败率、换执行体比例 | 偏好 = 近 ≥4 次成功率 ≥80% 的最低档 |
| 老理解错 | 假设被推翻 + 5 分钟内被撤销 + 自评纠正 | 误判率 ≥0.3 → 这类先问；近 5 次干净 → 回到先声明 |
| 异议常被推翻 | 近 5 次 ≥4 次被推翻 | 这类不再异议，只附一句风险，简报里报一次 |
| 判错处置 | 答完 10 分钟内被纠正 | 案卷判例段加一行"你常把这类当成 X"，计入误判 |

自动度：记账键是（工作类 × 能力），不是抽象的 `write_local`。连续 5 次 draft 被原样批准且跨 ≥2 个自然日 → auto；升级必须通知且一句话可回滚；任何一次驳回、改写、停止 → 立即回 draft、不通知、留记录。天花板由表级约束锁死：改线上、发布、替老板许诺永远不能 auto。

## 契约

```
Engine.evaluate(scope, subject, facts) → { then, trace: RuleTrace }
Registry.register(rule, provenance, by) → RuleId
Registry.merge(candidates) → RuleId[]              // 同义合并
Registry.checkConflicts() → ConflictReport         // 启动时一次
Replay.run(ruleId, sample: 'last100') → ReplayReport
Calibration.recompute(day) → ClassUpdates
Autonomy.apply(classId, capability, evidence) → { strength, demoted }
```

## 依赖方向

依赖协议（规则对象、deliberation 命中链）与世界模型的路径。被判断（闸、估时、执行体偏好）、时机与措辞（档位与阈值）读取；执行体不读规则——判断把止损线算好再交给它。规则不依赖它们，也不认识"秘书"。

## 失败模式

| 失败 | 表现 | 处置 |
| --- | --- | --- |
| 规则腐烂 | 120 条互相覆盖，没人敢改 | 上限 120；30 天未命中进退休候选；同义合并 |
| 自批扩权 | 规则把 draft 改成 auto | 扩权必须走自动度梯度，绕开规则引擎；读数查 |
| 回放自欺 | 用挑过的样本证明没坏 | 固定"最近 100 条同类"，样本口径写死；改变案例 >10% 挡回 |
| 校准噪声 | 5 个样本就调系数 | 样本门槛 ≥5，系数夹在 0.5–4；每类单独算 |
| 模型写规则 | 模型直接改规则表 | 规则表只由 Registry 写；模型只能 propose，且 inferred 永远 proposed |

## 读数

```sql
SELECT count(*) FROM deliberation WHERE rule_trace IS NULL;                                  -- 0
SELECT count(*) FROM rule WHERE provenance='extracted' AND state='active' AND approved_by IS NULL; -- 0
SELECT count(*) FROM rule WHERE provenance='inferred' AND layer<>'technique';                 -- 0
SELECT count(*) FROM rule WHERE state='active';                                               -- <= 120
SELECT count(*) FROM rule r WHERE r.state='active' AND r.provenance IN ('extracted','inferred')
  AND NOT EXISTS (SELECT 1 FROM rule_replay p WHERE p.rule_id=r.rule_id);                     -- 0
SELECT count(*) FROM rule WHERE layer='constitution' AND approved_by<>'owner';                -- 0
SELECT class_id, samples, round(eta_factor,2), ask_mode, pushback_mode, preferred_executor
  FROM work_class WHERE samples>0 ORDER BY samples DESC;
```

## 扩展点

- 新规则：数据，不是代码；三条通路写入。
- 新谓词：改本模块（加一个求值分支），不属于插件扩展；因为谓词集合是回放与审计的边界。
- 新校准维度：改 `Calibration.recompute` 的 join，属于本模块版本变更；产物写回工作类，不改协议。
- 不做"规则脚本"：允许脚本等于允许任意代码进内核路径，回放与回滚都会失效。
