# 规则：硬边界与工作方法学习

职责：把不可越过的边界与可通过磨合改善的工作方法分开，使 Superagent 越用越懂得如何替老板推进工作。目标设计。

边界：规则不执行工作、不存第二份知识真源、不以学习名义改变权限。方法好坏由行为与结果证据评估，不能仅看改动幅度小。

## 两类规则

| 类别 | 内容 | 表达与执行 | 变更 |
| --- | --- | --- | --- |
| 硬边界 | 身份、授权、目标范围、隐私、停止、资源互斥、验收必需项 | 结构化条件，由宿主强制校验 | 只从可信人类指示或项目规范更新，保留来源 |
| 工作方法 | 如何询问、组织提示词、选执行体、诊断、安排评审和汇报 | 有适用范围与反例的自然语言方法，必要时带结构化触发 | 可在既有权限内生成候选、评估、有限采用与回滚 |

硬规则可以保留 constitution/policy 的层次与命中链；学习方法不能覆盖硬拒绝。冲突顺序先检查所有适用的硬约束，再在许可集合中选择策略，不能让更细 scope 或例外优先级覆盖不可放宽的边界。

自然语言适合表达工作经验，但不作为授权求值器。模型可以学习「先明确统计口径，再派分析」，不能学习出「以后生产变更不用批准」。

## 学习对象与来源

候选来自用户明确纠正、交办被误解、验收失败、恢复成功或同类重复阻塞。保存原始例子、适用项目与工作类、方法、反例、预期改进、评价方式、回滚条件。

推断不能冒充老板原话。明确偏好可直接记录在相应范围；从一次案例推导到所有项目必须经过评估，不能把「在 A 不需要问」泛化成 B 的权限。

可移植方法和偏好按 [记忆](05-记忆.md) 进入 OV 真源，运行表保存候选、评估记录和引用。扩展能力或工具仍须走工程变更与验证，不由方法文本动态注入代码。

## 评估闭环

1. 定位错误来源：意图理解、材料不足、方法不适合、执行能力、环境或验收缺失；不能把所有问题归因到模型档位。
2. 提出一个具体方法变化及预期收益，明确哪些案例应改变、哪些不能改变。
3. 回放同类历史案例，并加入未用于生成候选的保留案例、跨项目反例、权限与隐私反例。
4. 比较任务正确性、返工、被迫介入、遗漏与恢复质量；硬边界不得退化。变化超过某比例触发更严格评估，不因改变结果超过 10% 一律拒绝。
5. 证据充分且仅影响授权内可逆工作方式时有限采用，记录使用范围与版本；监测退化后自动回滚。
6. 样本不足时保留候选，或在已授权的低风险范围做可回滚试用；不能伪造改善结论。影响授权、不可逆行为或职责目标时必须取得相应批准。

没有「推断永远不能生效」的产品约束；有「推断不能成为授权」和「无评价证据不能宣称学会」的约束。

## 运行策略

估时、检查频率、资源排序、模型选择和询问方式均可校准，但数字阈值是可调整的工程策略，不是老板需求。选择强模型或更多上下文不因 token 成本被机械否决；同时不能用不计成本作为无进展重复执行的理由。

自动度应由已授予的责任和权限决定。多次批准可以作为提出授权调整的依据，不能仅因连续五次批准就生成一项新授权。停止也可能是需求变化，不应自动被解释为工作方法错误。

方法数量治理以冲突、失效范围与使用质量为准，不为了固定数量上限删除有效的项目约束。合并时保留来源、适用差异和反例。

## 契约

```text
evaluateHardRules(actor, target, action, context) → permit/draft/deny + trace
selectMethods(workClass, project, context) → versioned methods + sources
proposeMethod(evidence, change, scope) → candidate
evaluateCandidate(candidate, replay, holdout) → accept/reject/inconclusive
activate(candidate, boundedScope, rollbackCondition) → version
```

## 依赖、失败模式与扩展

依赖协议和世界模型；知识通过记忆约定的引用访问，不复制为另一套权威。判断、托管协调和时机消费规则；执行端收到已经确定的授权与操作约束，不重新解释方法文本来扩权。

| 失败 | 防线 |
| --- | --- |
| 提示词学习成扩权 | 宿主在每次操作前独立校验授权 |
| 学会错误偏好 | 原例与推断分开，保存反例，允许回滚 |
| 用训练样本证明自己 | 保留案例与跨项目回归，固定评估来源 |
| 为减少消息而隐瞒失败 | 同时检查验收质量、遗漏和被迫介入 |
| 只修参数而无法学方法 | 自然语言方法有明确范围、证据和消费路径 |

新增结构化谓词属于硬策略实现变更，需要测试；新增工作方法是数据与知识变更，遵循评价与真源治理。验证包括正确但影响面大的纠正能采用、跨项目误泛化被拒绝、权限不因学习改变，以及回滚能恢复前一方法版本。
