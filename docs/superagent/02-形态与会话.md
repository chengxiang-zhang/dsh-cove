# 形态、候选比较、会话生命周期

> **本文属于《秘书式 super-agent 设计文档体系》**，覆盖全局 §2、§4、§16。索引与权威顺序见 `README.md`。
> 把"三层形态、为什么选乙、会话怎么生老病死"放在一起，因为它们互相牵制：改任何一处都会动另外两处。

## 2 两个候选形态，以及为什么选乙

两者都满足原话 1、5 的硬约束：每个私聊（人×bot）一个对话、每个群一个对话，这个对话就是 router（会话 + 专属记忆）。差别在"脑子在哪"和"什么推动它"。

### 2.1 候选甲：会话即秘书（v1 的形态）

每个对话一个常驻 Router 会话，会话上下文就是工作记忆；工单表记录派出去的活；消息到达起回合，回合里做判断。

- 好处：简单直观；对话里的指代（"它""这个"）由会话上下文天然消解；每条消息的边际成本只有一个回合。
- 致命处：
  1. **没有时间**。会话只在被 prompt 时存在，"这件事等了多久、该不该催、两天后风险会发生"没有落点〔推断〕。今天 19 个 proactive 回合全部 `empty`〔已证实〕，正是"让会话自己想起来说话"的结果：没有一件具体的事要它说。
  2. **真相在会话里**。换代、重启、上下文压缩都会丢前情；v1 用"账本注入 20 条 facts"补，补的是事实，不是"上次为什么这么定"〔推断〕。
  3. **判断无法被评分**。判断写在回合文本里，没有结构化的"我预测了什么"，就不可能知道自己哪类判断老错（Q4 无解）〔推断〕。

### 2.2 候选乙：账本即秘书，对话是它的办公桌（选定）

一本**承诺账本**是唯一真相；每个对话的会话是一张**桌子**（desk）：秘书在这张桌上跟这个人（或这个群）说话、在这张桌上做与之相关的判断。推动判断的事件有三种：入站消息、执行体汇报、承诺时钟到点。每次判断开始前，宿主从账本**编译一份案卷**（dossier）作为本回合输入的头部；判断的产出只能是对账本的结构化操作（工具调用）加至多一句话。

- 它解决甲的三处：时间是账本的列（`due_at/eta_at/next_look_at`）；真相在账本，会话可随时换代；判断是工具调用，带预测字段，可回填结果评分。
- 原话 1「对话本身就是router（会话+专属记忆）」在乙里的对应：桌子会话 + 该桌可用的记忆切片。原话 5 的"同一个人在私聊和群聊里记忆共享"：记忆不属于桌子，属于人，桌子按受众取用（§7）。

### 2.3 另外两个形态为什么不选

- **目标树**：19 条里没有一条是目标形状的〔已证实〕。目标是承诺的一种（`kind='goal'`，§3.7），保留其有用部分（按目标出方案），不让它成为骨架。若做骨架，每条"看下本机 ip"都要挂到某个目标下，挂不上就无处安放〔推断〕。
- **黑板**：任何 actor 都能对任何触发重跑判断。它与原话 3「项目经理或者秘书的岗位」冲突：岗位意味着有一个为判断负责的"我"；多 actor 重跑判断正是"空跑、钻牛角尖"的温床〔推断〕。乙保留了黑板的一个优点：判断可以被时钟重新触发，但只由该承诺所在的那张桌子触发。

### 2.4 选乙的代价（承认，不粉饰）

1. 每次判断多付一份案卷：上限 2,500 token〔推断，P0 测实际分布〕。对寒暄是纯浪费，所以寒暄必须不走案卷（§3.2 快路径）。
2. 受理延迟变长：今天约 8 秒回话〔已证实：brief §02 A〕，加案卷与结构化工具调用后预计 10–20 秒〔未验证〕。30 秒内受理（验收第 1 步）余量变小；兜底是 20 秒时宿主先打已读表情（现有能力，不是一条消息）。
3. 模型必须可靠地输出结构化操作。工具调用出错要重试，重试两次失败就由宿主模板兜底（§10）。
4. 不是承诺的东西（半成形的想法、情绪）在账上没有家，只能进记忆或被丢弃。这是有意的：秘书只为可交办、可验收的事负责。
5. 表比甲多（12 张）。§12 Q8 给出砍到三分之一的版本，证明骨架不依赖其余部分。

## 4 架构与边界

```
飞书事件 ─> [管道 lark-inbox] 收、去重、落库、出站发送、表情回执           (已有)
              │ 每条入站一次 CAS 认领 owner（responder | superagent）
              v
           [秘书 superagent 服务域]
              账本：承诺/假设/尝试/日志/记忆/类/出站/租约
              宿主规则：快路径、案卷编译、闸校验、预算、注意力分档、校准
              时钟：60 秒议程扫描 + 每日简报
              │ sessionController.create/prompt/cancel/inspect
              v
           [DSH 会话]  桌子会话（每私聊一个、每群一个） | 执行体会话（每 attempt 一个）
```

挂载：新服务域 `host/services/superagent/index.ts` 导出 `register(ctx)`，在 `host/services/index.ts` 的 lark-inbox 挂载之后挂载；`cordis.patch.yml` 保持恰好一行 `- id: web-all`〔已证实：`cordis.patch.yml:7-9` 与 brief 事实 23〕。上线**需要用户重启 DSH 服务后生效**，本设计任何步骤不重启 3080 服务〔已证实：brief 事实 24〕。

边界与架构承诺（每条都是选择，附为什么不是另一种）：

| 承诺 | 为什么不是另一种 |
|---|---|
| 账本是唯一真相，会话是缓存 | 真相放会话里，重启、换代、压缩都丢前情（§2.1 致命处 2）。代价：每次判断编译案卷 |
| 桌子会话没有执行工具：`restrict({allow: []})` + scoped 注册秘书工具 + `guard` 拒绝白名单外一切 | preset 只是提示词、宿主级工具对所有 agent 可见〔已证实：brief 事实 12、13〕；禁止名单遇未知名抛错〔已证实：事实 9〕。v1 此处正确，照抄且同意 |
| 秘书读交接与汇报，不读代码 | 原话 16。能读代码就会自己分析，变成第三个执行者。它读的是 `sa_journal` 的汇报、结案证据和老板投递的文档 |
| 桌子之间不直接说话，只共享账本 | R8。直连等于第二条事实通道。共享账本让"同一个人的记忆跨桌共享"成立，又不需要桌子互相知道 |
| 对人说话只有 `say` 一个出口，且发送前必须持有出口租约 | 多出口时"期间零消息""≤100 词"都无法机械检查；Hermes 事故（一条消息 8 个回复）证明出口唯一还要跨进程〔已证实：brief §02 B〕 |
| 每条入站消息恰好一个 owner（CAS 一列）| v1 保留点 1，同意：切换期两边读到旧开关值的那一秒，只有一列 CAS 是原子的 |
| 交付真相看回合结束原因 + 证据核对，不信自述 | v1 保留点 2，同意。本设计把证据按 `check_kind` 分型（§6.3），`answer` 型不要求命令 |
| 自动度按"工作类 × 能力"磨合，升要证据、降不问理由 | v1 保留点 3，保留规则，改记账键：老板信任的是"跑测试这类事"，不是抽象的 `write_local`（§8.4） |
| 生产变更、对外发布、替老板许诺，永远 draft | 用户全局规则 prod-auth：逐目标授权〔已证实〕。自动度天花板写进表级 CHECK |
| 群里"一件事"由回复链定义，不由模型猜主题 | 猜错会把两件事并进一个承诺，代价大于"一个群一条线" |
| 并发是槽位配置（默认 1），不是设计常数 | 19 条/天〔已证实〕。槽位用唯一索引表达，加槽不改代码 |

## 16 v3 修订：单一在场、投机执行、全双工

### 16.1 单一在场：把案卷拆成"公共核心 + 桌切片"

**问题**：v2 的案卷（§3.1）是**按桌编译**的，所以每张桌子读到的"我"不一样——同一个问题在私聊和群里可能得到不同答案，你换个窗口就觉得换了个人。

**"是不是同一个人"的三个可观测条件**（不靠感觉）：
1. 同一份**当前关注**：两张桌子在同一分钟被问"你在忙什么"，答案必须一致。
2. 同一套**判断偏好**：同一类事在两处触发，闸的结论相同。
3. 能**相互指涉**：群里说的 A，私聊里"按刚才那个"能接上。

**改法**：案卷从一个整体拆成两层。

| 层 | 内容 | 作用域 | 一致性要求 |
|---|---|---|---|
| **自我层 `now`**（公共核心） | 在办承诺摘要（≤8 条：编号、一句话、球权、下次看）；最近 12 次判断（跨桌：处置、一句话理由、哪张桌）；未决问题；老板今天说过的约束；校准后的"我在这类事上的已知偏差" | **全局唯一**，所有桌子共用同一份 | 两张桌子在同一判断窗口内必须拿到**同一个 `now_hash`** |
| **桌切片** | 本桌历史（最近 6 条）、按 §7 可见域放行的记忆、本桌相关判例 | 每桌不同 | 只能比 `now` 更窄，不能更宽 |

**机械保证**（不靠提示词）：
- 宿主编译完 `now` 后算 `sha256`，写进 `sa_deliberations.now_hash`。
- 验收断言：同一 5 分钟窗口内，不同桌子的 `now_hash` 必须相同——
  `SELECT count(DISTINCT now_hash) FROM sa_deliberations WHERE started_at BETWEEN ? AND ?` 应为 1。
- **模型不能写 `now`**：它只能改账本，`now` 由宿主从账本重新编译。这是"模型不能改自己的授权"的同一条纪律。

**为什么不是"回到一个常驻会话"**（v1 与文章的做法）：
- 常驻会膨胀、会漂移、重启就断；而且一个会话只能服务一个对话，别的对话要么排队要么串味。
- **"同一个人"的本质是叙事连续，不是会话连续。** 人也不是一直在线，人靠记忆和习惯保持同一性。每次开口前被重新告知"你是这个人、你在办这些事、刚刚发生了什么"，比"一直开着同一个会话"更稳、更不容易漂。
- 这条只有在 token 不是约束时才划算（R-d）：`now` 可以每次全量重编，不做相关度筛选。

**代价（诚实说）**：每次判断多一次本地编译（预计 1–2 秒，纯 SQLite + 模板，不调模型）；`now` 一旦编错会同时污染所有桌子，所以它的生成必须是纯函数 + 幂等，并有用例覆盖"账本变 → `now` 变"的映射。

### 16.2 投机执行：提前想清楚，绝不提前动手

v2 通篇没有这一层，只有"等事件"。文章有：后台先做，有价值才交付，没价值静默丢弃。

**三类投机**（宿主可分别开关）：

| 类 | 触发 | 产出 |
|---|---|---|
| 1 探询转探查 | 老板问"能不能 / 是不是 / 要多久" | 一次只读验证的结论（跑过什么、结果如何） |
| 2 排队期预备 | 承诺在 `queued` 等槽位 | 方案草案：要改哪些文件、验证命令是什么 |
| 3 空闲巡查 | 无新事件也无到期承诺的回合 | 对在办承诺的一次只读核查，发现风险则形成候选提醒 |

**边界（我强加的，你可以否）**：投机**只能产出信息与草案，不能产出改动**。改代码、改配置、对外发送一律不属于投机。
理由：投机产物没经过验收，直接落地等于绕过"交付必须带证据"的纪律（附录 A 第 3 类：错了能查）。

**落在哪**：`~/.dsh/superagent/speculations/<id>/`，登记在 `sa_speculations`，**不进 `sa_outbox`**——不采纳就一个字都不说。

```sql
-- 16 speculations：投机的产物与去向。不进 outbox；不采纳零消息
CREATE TABLE IF NOT EXISTS sa_speculations (
  spec_id     TEXT PRIMARY KEY,            -- 'S-'||自增
  kind        INTEGER NOT NULL CHECK (kind IN (1,2,3)),
  conv_key    TEXT NOT NULL,
  ticket_id   TEXT REFERENCES sa_tickets(ticket_id),
  hypothesis  TEXT NOT NULL CHECK (length(hypothesis) <= 300),  -- 它假设老板要什么
  artifact_path TEXT NOT NULL,             -- 相对 ~/.dsh/superagent/speculations/
  summary     TEXT NOT NULL CHECK (length(summary) <= 400),
  state       TEXT NOT NULL CHECK (state IN ('open','used','discarded','expired')),
  used_by     TEXT REFERENCES sa_deliberations(deliberation_id),
  created_at  INTEGER NOT NULL,
  decided_at  INTEGER,
  CHECK (state = 'open' OR decided_at IS NOT NULL)
);
CREATE INDEX IF NOT EXISTS ix_spec_open ON sa_speculations(conv_key, created_at DESC) WHERE state = 'open';
```

**静默丢弃与"它到底做了什么"**：
- 不采纳 → `discarded`，零消息，保留 7 天（老板问"你刚才在算什么"能答）。
- 采纳 → `used`，产出挂到承诺上，并在第一条回复里引用："我提前看过：会在 X 失败，因为 Y。"
- 过期（3 天未被采纳）→ `expired`，静默。

**这是投机最大的体验收益**：今天你说"看看这个能不能改"，第一句是"让我看看"；有了投机，第一句是"看过了，能改，就一个文件，3 分钟"。**它把 30 秒受理的压力从"现场想"挪到"早就想过"**。

**风险**：投机太勤会变成"秘书自己空跑"的第二种形态。判据：`discarded/(used+discarded)` 连续一周 > 80% ⇒ 收窄第 3 类。

### 16.3 全双工：桌子不等执行体

文章说全双工的异步接口"已在 DSH 实现、尚未默认开启"〔未验证：本机 0.2.1-rc.5 里没找到对应公开接口，检索无命中〕。所以本节不依赖它，用架构本身做到。

| 要求 | 怎么做 |
|---|---|
| 执行体在跑时，桌子能起新回合 | 本来就是两个会话；`turn_open` 只限制桌子自己一次一个回合，不限制执行体 |
| 议程回合不阻塞对话回合 | 时钟回合优先级低于人的消息：桌上有活人消息时，`next_look_at` 顺延 60 秒，最多 5 次 |
| 等待中的承诺不占桌子 | `ball=executor`/`ball=other` 时桌子空闲；只有球回到老板或执行体汇报才起回合 |

**验收读数**：
- 承诺在跑时老板发一条寒暄，受理 `p95` 比他空闲时差 **< 3 秒**；
- `sa_deliberations` 里 `trigger_kind='msg'` 的排队时间 > 2 秒的占比 **< 5%**。

### 16.5 三条裁定进哪一期

| 内容 | 期 | 为什么 |
|---|---|---|
| `now` 公共核心 + `now_hash` 断言 | **P0** | 它是"同一个我"的地基；晚做意味着之前的会话全是一次性的 |
| 桌子不等执行体（§16.3 三条） | **P0** | 不做就是"它一忙就不理你"，体验上比什么都糟 |
| `sa_speculations` 表（只记 discarded） | **P0** | 不建表，将来无法回答"它背后做了什么" |
| 投机第 1 类（探询转探查） | **P1** | 收益最直接；需要只读工具稳定 |
| 投机第 2、3 类 | **P2** | 第 3 类最容易变成空跑，要等校准数据再放开 |

### 16.6 "现在算 super agent 了吗"——一条可验收的判据

**算**，而且补上了文章那套的两个缺口（时间感、自我校准），同时用"叙事连续"替代了"会话常驻"。

但让它站住的判据是这两条，写在这里供验收：

> 一、你三天不说话，回来问「上次那个改完了吗」，它不查、不反问、直接答得上来。
> 二、你在群里和私聊分别问「你在忙什么」，两个答案一致（`now_hash` 断言，§16.1）。

第一条靠账本，第二条靠 `now` 的唯一性。两条都过，才叫"和同一个人说话"。
