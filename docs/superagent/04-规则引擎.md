# 规则注册、三层、冲突、自迭代、校准

> **本文属于《秘书式 super-agent 设计文档体系》**，覆盖全局 §17、§8。索引与权威顺序见 `README.md`。
> 规则是数据不是提示词；三层里只有技巧层能自己变。校准是技巧层的一个特例，所以并在这里。

## 17 规则：注册、作用域、自迭代（架构层）

> 2026-11-05 16:40 重写。前两版我把它答成了"注册表"（机器、工作区），老板两次纠正后确认：**问的是 router 的规则注册机制，以及规则怎么自迭代**。对象注册留在 §18，本节只讲规则。

### 17.1 问题：规则今天藏在四个地方，没有一处能回答"为什么"

| 藏身处 | 例子 | 后果 |
|---|---|---|
| persona 提示词 | "不替老板承诺""Router 不执行具体事务" | 靠模型自觉，违反也看不出来 |
| 配置项 | `autoReplyMode`、白名单、`superagent.repos` | 改一条要改配置 + 重启 |
| 代码 | `policy.ts` 里的三态表硬编码 | 改一条要发版，且版本与行为对不上 |
| 账本里的口头记录 | "老板说过别并发写 dsh-cove" | 只在案卷里出现一次，下次未必命中 |

四条共同的问题：**说不清"这件活是按哪一版规则被允许的"**，也**说不清"为什么这次没问我"**。所以规则必须从提示词里搬出来，变成可注册、可版本化、可回溯的数据。

### 17.2 规则的数据形状

```
rule = {
  rule_id, scope_path,          // 作用域：见 §18 的路径
  layer,                        // constitution | policy | technique（§17.3）
  when,                         // 谓词，可机械求值
  then,                         // allow | draft | deny | ask | escalate | notify | calibrate
  exceptions: [{when, then}],   // 显式例外，优先于本体
  priority,                     // 同 scope 同 layer 内排序
  provenance,                   // config | extracted | inferred
  version, state,               // proposed | active | retired
  approved_by, created_at
}
```

`when` 只能由**固定谓词集**拼成：`sender_class` / `capability` / `path_prefix` / `ticket_kind` / `prior_count` / `eta_bucket` / `time_window` / `repo_visibility`。
**禁止自然语言条件**——一旦允许，它就退回成提示词，既不能回放也不能审计，等于没做这件事。

### 17.3 三层，只有一层可以自己变（本节最重要的决定）

| 层 | 装什么 | 谁改 | 自动迭代 |
|---|---|---|---|
| **宪法 constitution** | 不执行具体事务；不替老板承诺；生产变更逐目标授权；模型不能改自己的授权与规则；交付必须带证据 | **只有老板** | **永不允许** |
| **策略 policy** | 谁能对哪个范围做什么（allow/draft/deny）、哪些必须问、双主的两个回执 | 老板批，系统可提议 | 提议 → 人批 |
| **技巧 technique** | 估时校准、执行体选择、摘要长度、什么时候先问、案卷瘦身、投机的采纳策略 | **系统自己可调** | 自动生效 + 自动回滚条件 |

**把"能不能"和"怎么做"分开迭代**，是这一节的核心。混在一起，任何一次调优都可能顺手改掉权限边界——而那种错误发生时不报错，只在某天你发现"它擅自改了我的线上配置"。

### 17.4 注册：三条通路，与实体注册同构

| 通路 | 触发 | 生效 |
|---|---|---|
| `config` 人工 | 老板说一句或写一行 | 立即 active。**宪法层只有这条通路** |
| `extracted` 提取 | 从一次纠正里提取（"以后这类先问我"） | 生成草案 + 出处（哪条消息、哪次推翻）→ **老板一句话确认 → active** |
| `inferred` 推断 | 统计推出（连续 5 次这类活他都改了范围） | **永远只能 proposed，且只能落 `technique` 层** |

**同义合并**：同 scope + 同 then 的多条 `extracted` 自动并成一条，权重相加。不做这一步，规则库三个月就会长成几百条互相覆盖的碎片，最后没人敢动。

### 17.5 冲突：确定性解析，启动时就挡住

解析顺序（无歧义，可复现）：
1. `exceptions` 优先于本体
2. 更长的 `scope_path` 优先（更具体者胜）
3. `layer` 高者优先（宪法 > 策略 > 技巧）
4. `priority` 数字大者优先
5. **仍然并列 → 判为冲突，拒绝加载**

启动时跑一次冲突检测（`sa_rule_conflicts`），运行期不允许"看情况"。
每次判定输出**命中链** `rule_trace`：哪几条参与、谁赢、为什么——写进 `sa_deliberations`。这是"为什么这么做"的唯一答案来源，也是老板最常问的那个问题的答案。

### 17.6 自迭代：四步闭环，每步可回放

**第一步 发现规则错了**（三种信号，全部来自账本，不靠模型自省）

| 信号 | 来源 | 含义 |
|---|---|---|
| `corrected` | 老板明确纠正行为（不是纠正内容） | 规则写错了 |
| `overturn` | 规则说 draft 而他总批（太严）；规则说 allow 而他撤销（太松） | 阈值错了 |
| `missed` | 老板说"你怎么没……"，而当时该触发没触发 | 条件漏了 |

**第二步 提议**：宿主统计出候选（`overturn 率 > 25% 的规则`、`missed ≥ 2 次的条件组合`、`30 天从未命中的规则 → 退休候选`），**模型只写解释，不许发明规则**。理由同"模型不能改自己的授权"。

**第三步 回放验证**（上线前必须过）：
- 取最近 100 条同类历史事件，旧规则与新规则各跑一遍；
- 输出：结论改变的条数、方向、涉及哪些老板；
- **硬门槛**：改变的案例 ≤ 影响面上限（默认 10%），超过就要求把规则拆细再提。

**第四步 生效与回滚**：
- `technique`：自动 active，同时写 `rollback_if`（例如"同类 overturn 率回升到 20%"），命中即自动回滚并留记录。
- `policy`：proposed → 老板批 → active；旧版本保留，一键回滚。
- `constitution`：不走流水线，只有老板能改，改动也要记版本。

### 17.7 四条防失控硬规则

1. **规则迭代不能给自己扩权**：任何改动若让某 `(sender_class × capability × scope)` 从 `draft` 变 `auto`，必须走 §13 的自动度梯度（人批），**绕开规则引擎**。
2. **影响面上限**：一条规则改动影响的历史案例 > 10% 一律挡回。防"一次改动把整个行为改了"。
3. **规则库有预算**：active 规则上限 120 条，超了强制合并或退休。规则库腐烂比代码快，因为它没有编译器。
4. **改动必须能跑成一次行为快照**：同一批历史消息，改前改后各跑一遍，差异列得出来才准上线。

### 17.8 收敛：这不是新加一层，是把已有的两处迭代统一

- §13 的**自动度梯度** = 策略层里 `capability × scope` 的 `draft → auto` 特例。
- §8 的**校准** = 技巧层里估时与执行体选择的特例。

两者本来各有一套状态机和各一套记录；现在它们是同一件事："规则 + 版本 + 回放 + 回滚"。
收益：**只有一套解释机制**。老板问"为什么这次没问我"和"为什么估时偏了"，答案在同一个地方（`rule_trace` + `rule_replays`）。

### 17.9 验收读数

```sql
-- 1 每次判断都有命中链（"为什么"可回答）
SELECT count(*) FROM sa_deliberations WHERE rule_trace IS NULL;                    -- 0
-- 2 启动冲突检测后运行期零冲突
SELECT count(*) FROM sa_rule_conflicts WHERE state='unresolved';                   -- 0
-- 3 提取的规则未经人批就生效的
SELECT count(*) FROM sa_rules WHERE provenance='extracted' AND state='active' AND approved_by IS NULL;   -- 0
-- 4 推断的规则跑到策略层或宪法层的
SELECT count(*) FROM sa_rules WHERE provenance='inferred' AND layer <> 'technique'; -- 0
-- 5 规则条数上限
SELECT count(*) FROM sa_rules WHERE state='active';                                -- <= 120
-- 6 每条 active 规则都有回放记录
SELECT count(*) FROM sa_rules r WHERE r.state='active'
  AND NOT EXISTS (SELECT 1 FROM sa_rule_replays p WHERE p.rule_id=r.rule_id);      -- 0
-- 7 宪法层没有被自动改动过
SELECT count(*) FROM sa_rules WHERE layer='constitution' AND changed_by <> 'owner'; -- 0
```

### 17.10 分期

| 内容 | 期 | 为什么 |
|---|---|---|
| 规则表 + 判定引擎 + `rule_trace` + 启动冲突检测 | **P0** | 一开始就要能回答"为什么"，事后再补等于重写所有判定 |
| 宪法层 6 条从提示词搬进规则 | **P0** | 它们是唯一不能用"模型自觉"兜底的六条 |
| `extracted` 通路 + 回放验证 | **P1** | 要有真实纠正样本才谈得上提取 |
| `inferred` 通路 + 自动回滚 + 退休 | **P2** | 最容易被统计噪声带偏，必须等数据 |
| 模型直接改规则 | **永不** | 这是宪法层第一条 |

## 8 自我校准：它怎么知道自己不可靠

每次判断写下预测（`sa_intake` 的 `work_class/confidence/pred_eta_min/pred_executor`、`sa_assumptions` 的声明），结案时宿主回填结果（`sa_commitments.actual_min/attempts/executor_switched`、假设 `overturned`、后续消息 `corrects`）。校准 = 一次 join，每天简报前由宿主跑一遍，写回 `sa_classes`。

| 它可能不可靠的地方 | 信号 | 下次行为怎么变（宿主机械执行） |
|---|---|---|
| 估时总偏短 | `actual_min / eta_model_min` 中位数，近 10 次，样本 ≥5 | `eta_factor` = 该中位数（夹在 0.5–4）。受理里的时间 = 模型估计 × 系数，模型看不到也改不了这一步。案卷判例段显示系数，让它自己的估计也跟着修 |
| 老选错执行体 | 本类 attempt 中首个执行体失败率、`executor_switched` 比例 | `preferred_executor` = 近 ≥4 次成功率 ≥80% 的最低档；没有则空，§3.5 规则 4 生效 |
| 老理解错 | `misjudge_rate` = (假设被推翻 + `corrects=1` 的后续 + 受理后 5 分钟内被 release) / 样本 | ≥0.3 → `ask_mode='ask-first'`：第一条假设必须问。近 5 次干净 → 回到 `declare` |
| 异议常被推翻 | `pushback_override_rate` | 近 5 次 ≥4 次被推翻 → `pushback_mode='quiet'` |
| 判错处置（该开活却直接答、该答却开活） | 处置为 answer 后 10 分钟内同线程再问且 `corrects=1`；处置为 commit 而执行体 1 回合、0 工具调用就交付 | 本类在案卷判例段加一行"你常把这类当成 X"，并计入 misjudge |

`corrects` 是秘书对下一条消息自判的，有自评偏差；所以误判率里另两项（假设被推翻、5 分钟内 release）是纯宿主信号，自判项只占三分之一权重〔推断〕。

**对老板可见**：校准改动进简报的"我改了自己"一行："run-tests 估时 ×2.1（近 6 次都慢）；analyze 类改为先问（近 5 次我理解错 2 次）"。老板看得见它在哪里不行，这是"可托付"的一部分（brief §01 E2：错了能查）。

**自动度**（记账键是工作类，不是抽象能力）：`(work_class, capability)` 连续 5 次 draft 被原样批准且分布在 ≥2 个自然日 → `auto`，升级必须通知且一句话可回滚；任何一次驳回、改写、停止 → 立即回 `draft`、不通知、留记录。天花板由 CHECK 锁死。主读数：每周 `route`/`ask` 处置数单调下降。
