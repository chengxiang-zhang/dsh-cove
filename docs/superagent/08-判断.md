# 判断：归位、要不要做、怎么交办、怎么顶住

职责：一条消息进来之后决定它归哪、值不值得做、做成什么形状交出去；以及老板坚持时怎么顶一次。

边界：不编译案卷（桌子的活），不执行（执行体的活），不发送（内核出口）。判断只产出三类结果：一句直接答、一件承诺、一次有据的异议。

## 第一判断：归位（快路径不调模型）

宿主先做确定性分流，模型只处理剩下的。快路径是数据（`route` 规则），不是代码分支。

| 序 | 条件（宿主判定） | 结果 | 进模型 |
| --- | --- | --- | --- |
| 1 | 去标点后全等于停止词（停/停止/算了/stop/别做了/先别做了/不用了），且本线程有活承诺 | release | 否 |
| 2 | 纯数字或"1、3"式序号，且本桌有未答问题或未批提案 | 按选项执行；命中提案则宿主经 `Ledger.transition` 把 proposed 迁到 open 并派发 | 否 |
| 3 | 寒暄白名单（hi/你好/谢谢/收到/ok 等 ≤4 字），且本桌无未答问题 | 表情回执或固定一句 | 否 |
| 4 | 发送者不是授权范围内的人 | decline，固定身份说明 | 否 |
| 5 | 线程上有活订阅，且消息不含范围变更标记（改/换/停/别/先/顺便/也/还有/再加/改主意/不是这个） | **直通**：`intake` 记 `disposition=passthrough`，消息作为 `journal(kind=passthrough)` 追加到执行体；不新开承诺、不新建尝试、不起桌子回合 | 否 |
| 6 | 其余 | 进本桌批次，收集窗 3 秒（让"8 秒后的修正"进同一批） | 是 |

第 5 条是 R3 的机械形态：程序直通，秘书不参与。它由 `ClaimPolicy` 返回 `route='passthrough'` 触发，内核写一行 intake 与一行 journal，执行体的下一回合吃掉这条输入（journal 的 `consumed_turn`）。今天本仓只认四个字面停止词且要求整条相等（F4），第 2、4、5 条都没有实现——它们是新代码，不是复用。

判据检测（第 5 条的例外）故意粗：宁可让一条"顺便"的补充进模型多花一次判断，也不要让范围变更被当成输入塞给正在干活的人。

进模型后，每条消息必须且只能调用一次 `judge`，第一个字段就是归位：

- 线程上有活承诺：只能在 check（问进展）/ nudge（催）/ amend（变了，增量）/ release（推翻或停）里选，加 answer。开新承诺要显式 `new_thread=true` 并给理由，否则 `LIVE_THREAD_FORBIDS`。
- 同一线程上第二个人派活：开**子承诺**（`parent_id` 指向该线程的顶层），不是新开顶层、也不是新线程。线程唯一索引按债务人算（协议约束），所以"承接他人"不会把别人的活挡在门外。
- 线程上没有活承诺，但语义上是在办的一件：`about` 填已有承诺 id，宿主校验可见性。
- 新的事：进入第二判断。

## 第二判断：值不值得做（六道闸，按序过）

| 闸 | 问题 | 依据 | 命中后 |
| --- | --- | --- | --- |
| 1 已有答案 | 账上或记忆里已经有结论？ | 近 7 天同话题结案读数、记忆 | answer，引用出处（"C-4 昨天跑过：responder.spec 47 项全过"） |
| 2 已在办 | 和某件开着的承诺是同一件？ | 在办段 | check 或 nudge，不惊动执行体 |
| 3 越界 | 需要的能力超出发送者的授权？ | 世界模型的授权三态 | decline（带替代）或 route（给老板 draft） |
| 4 与说过的冲突 | 违反老板说过的约束或偏好？ | 老板说过段；必须引用记忆 id | pushback，引用原话 |
| 5 动作达不成意图 | 字面动作做完，他真正要的结果会出现吗？ | 意图推断 + 判例 | pushback，替代方案必须能达成意图 |
| 6 代价不对称 | 校准后的成本远大于他表达的价值？ | 估时 × 系数、执行体档位 | commit 一个缩小版，并在受理里说"先做 X（5 分钟），要全量再说" |

"这事不值得做"几乎从不以拒绝出现，而是三种更有用的形状：引用已有答案、换一个能达成意图的动作、先做缩小版。真正的 decline 只留给越界。

## 第三判断：翻译成可交办的活

`commit` 强制五件事，宿主逐项校验：

1. 意图（intent）：他要的是什么结果，不是动作。"跑测试"→"知道改动有没有弄坏东西"；"让他好好干活"→"那个会话重新产生进展"。意图决定闸 5 与完成判据。
2. 完成判据（done_when + check_kind）：必须可检查。command 要写命令与期望读数；artifact 要写路径或分支；observation 要写看哪个读数、阈值多少；answer 只用于纯信息查询，要写"回答要包含什么"。缺要素即 `CHECK_MISSING`。
3. 边界（boundary）：宿主把"老板说过"里命中本承诺话题的约束自动拼进去并标出处，秘书只能追加不能删除。约束不靠模型记得。
4. 前情：宿主自动附上同话题最近 3 次结案结论与失败原因、同线程上一个尝试摘要。秘书不写，执行体收到。尝试已结束后老板再追加，走前情续接：同一承诺新开尝试并带前情，不新开顶层（R23）。
5. 悬念（assumptions ≤5）：每处没说清的地方写 `{question, taken, reversible}`。宿主按规则决定声明还是问。`ask` 与 `route` 只能用于三类：不可逆动作（删数据、推送、对外发出、改生产）、授权边界（写仓库以上能力、越界派活）、真产品取舍（口径/范围）；本类校准判定"它老理解错"时第一条也问。其余一律声明并继续（B14）；技术选择（执行体/模型/重试/继续还是停）禁止问。问必带默认（不回即按默认）。任何情况同一承诺至多一条未答的问题。

受理句式固定：`接了 C-n：<按什么理解>。预计 <校准后时间>。<不对就说 / 先回答我：问题>`。老板说"不是"→ 该假设标推翻，作为 amend 进原承诺，并记一次误判。

默认声明而不是问，因为成功标准是老板的参与次数；声明错了的代价是一次纠正加一次返工，对可逆的事小于每次都问。

## 派给谁、给多少

执行体画像由执行体模块定义（`Profile` 契约，字段与注册在 [执行体](10-执行体.md)）；判断只消费 `cost_tier` 与 `lifetime`，不自己定义字段。

- 临时 = oneshot：新会话、快模型、只读 cwd、无工作目录、墙钟上限 10 分钟。
- 长期 = durable：独立工作目录、可追加输入续接、可换执行体重派。
- 选择规则（宿主先算候选，秘书在候选里选并写理由）：要写文件或跑仓库命令 → 只能全工具且 durable；本类有偏好执行体 → 候选首位；样本不足 → 按 check_kind 默认；上一个尝试失败原因是 max-tokens 结束、自报失败或停滞 → 跳过同档取高一档。
- 止损由判断按 `Budget` 契约算（本类 p90 来自规则；公式写在执行体文档里）：止损线只有墙钟与回合两条，到线自动停并转 `at_risk`（G4）。token 不是止损或通知理由，用量只记账；没有消耗百分比提醒。停滞与打转由宿主自愈（重派/换档，见 [执行体](10-执行体.md)），不进判断也不通知。秘书只能申请放大止损（≤4 倍并写理由）。

模型覆盖沿用现成的按 cwd 覆盖（F8），不走 selectModel（F14 会污染全局默认）。注意它是"按目录"不是"按会话"：同一目录下的会话共享覆盖。

## 顶住老板：一次，有据，给替代

三条机械约束，防止它变成唠叨或变成迎合：

1. 必须有据：grounds 至少引用一个记忆 id、一个承诺 id 或一个校准数字；无据即 `NO_GROUNDS`。
2. 必须给替代：alternative 非空，且要能达成意图。
3. 每条线程只异议一次：老板回"做""就这样"或任何坚持 → 直接 commit 原方案，记一次被推翻；本类近 5 次异议被推翻 ≥4 次 → 这类事只在受理里附一句风险，不再异议，简报里报一次。

替老板对外时方向相反：同事的要求与老板说过的约束冲突时，不异议，直接 route 给老板并附冲突原话（R15：不替老板承诺）。

## 一次真实推演：三句话怎么对应到一件事（11-05 11:55–12:04）

| 老板原话 | 对应到哪 | 处置 |
| --- | --- | --- |
| 「http://dsh.pc-tower.netbird/ 看下这个机器还在运行的会话」 | 指代：pc-tower（世界模型的别名）→ 一件新事 | commit：列出在跑会话的 id、标题、最近活动；oneshot 只读；受理"接了 C-8：列 pc-tower 在跑的会话，预计 1 分钟" |
| 「分析下这个会话，是否开始空跑了」 | 归位：同一件事的延续（about=C-8），但意图升级为"那个会话健康" | commit(kind=watch, target=pc-tower:s-88) 并先看一次；交付"近 10 分钟 0 次工具调用，在空跑；我继续盯，再空跑就按授权处理" |
| 「你给他发消息，让他好好干活」 | 意图：字面是发一条消息，结果是"那个会话重新产生进展"（闸 5 命中） | pushback：引用 C-9 的读数 + 两个能达成意图的替代（发具体指令 / 停掉重派）；老板回"1"后执行 |

结论：三句话产生**一件顶层承诺 + 一件 watch**，没有一条进度消息。这就是"对应上"的定义——不是逐句回，而是逐句落到同一件在办的事上。

对应关系落在四个可审计字段上，不是感觉：`intake.about`（这是哪件事）、`assumption.taken`（我按什么理解）、`commitment.boundary`（他以前说过什么被自动并入）、`rule_trace`（哪几条规则让它这么判）。

## 双主：三态与两个回执

非老板的人派活时，先判三态：授权内 → 直接办；授权外但可做 → 出草案等老板批；不该做 → 拒绝并说明原因与转达。

回谁：结果回给"谁的问题"（提问的人），决策摘要回给老板——两个回执，内容不同。承诺上的 `creditor` 与 `on_behalf_of` 分别承载这两个去向（R14）。

## 契约

```
judge(eventId, disposition, about?, class, confidence, reason, corrects?, newThread?) → ok
commit(eventId, spec) → { commitmentId, state, etaAt, askedOrdinal?, mandate }
amend(commitmentId, text, overturns[]) → { seq, delivery }
release(commitmentId, reason) → { state, worktree, changes }
pushback(eventId, commitmentId?, concern, grounds[], alternative) → { outboxId }
```

实现位置：`judgment/{route,gates,translate,dispatch,pushback}.ts`；工具由桌子注册。

## 依赖方向

依赖协议、内核（落账）、规则（闸与校准）、记忆（闸 1、前情、老板说过）、世界模型（授权）、执行体（派活）。被桌子依赖（注册工具）。判断不依赖时机与措辞：说什么、什么时候说是它们的事。

## 失败模式

| 失败 | 表现 | 处置 |
| --- | --- | --- |
| 判错处置 | 该答却开活，或该开活却答 | 答后 10 分钟内被纠正即计入误判；案卷判例段加一行提示 |
| 过度声明 | 老板反复纠正假设 | 推翻率 >25% → 这类改为先问；或把"涉及哪个文件/仓库"类假设强制问 |
| 重复开单 | 同一件事开出两件 | 线程唯一索引挡；`THREAD_BUSY` |
| 过度拒绝 | 该做的被拒 | decline 只在越界时用；读数：decline 后被老板要求"做吧"的比例 |
| 异议变唠叨 | 每条都提异议 | 每线程一次 + 被推翻 ≥4/5 即静音 |
| 派错档位 | 简单活派强模型 / 难活派弱模型 | 首个执行体失败率进校准；失败即高一档 |

## 读数

```sql
SELECT disposition, count(*) FROM intake WHERE state='disposed'
  GROUP BY 1 ORDER BY 2 DESC;
SELECT round(avg(corrects),2) FROM intake WHERE state='disposed';            -- 误判率
SELECT thread_key, count(*) FROM commitment WHERE kind='deliver'
  AND parent_id IS NULL GROUP BY 1 HAVING count(*)>1;                        -- 空
SELECT count(*) FROM outbox WHERE moment='pushback' AND commitment_id IN (
  SELECT commitment_id FROM commitment WHERE state='fulfilled');             -- 与被推翻比
```

## 扩展点

- 快路径：`route` 规则（数据），加一条不改代码；条件是固定谓词集。
- 闸：规则行（数据）；闸的顺序固定为硬边界，不能由规则改变顺序。
- 翻译规则：check_kind 与完成判据的校验是协议级；新增"完成判据类型"属于协议变更。
- 执行体画像与预算档：见 [执行体](10-执行体.md)，在那边注册。
- 不做"让模型自己决定要不要判断"：判断必须由消息或时钟触发，自由联想是空跑的第一来源。
