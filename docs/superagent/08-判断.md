# 判断：理解工作、组织提示词与提出纠偏

职责：理解人类意图与执行现场，产出事项归位、交办材料和诊断提案。目标设计。

边界：本模块不直接派发、调度或发送消息。托管协调选择下一步，内核和执行端校验并执行；模型对意图的理解不能替代权限事实。

## 消息归位

确定性路径只处理已经明确的控制意图、带身份与版本绑定的批准选择、重复事件和显式直通。对含糊停止对象、多个待答问题或过期序号，不能机械猜测。

- 问进展：读取真实状态回答，不把问题丢给正在写代码的执行体。
- 催促：检查是否有遗漏或停滞，必要时诊断，不机械发送「快点」。
- 增量需求：定位事项、更新需求与验收版本，给执行体具体追加并确认消费。
- 改变方向：保全已有成果，撤销冲突操作，修订安排；不靠新建同义事项掩盖旧责任。
- 新事情：可以在同一线程受理；跨项目关联按意图，不以聊天线程唯一索引挡住。
- 闲聊、随口感想与讨论：保留必要背景；只有明确委托或已授权长期职责才正式立项。明确给出目标方向即允许开始授权范围内的调查。
- 显式给某执行体的输入：在目标、权属、授权均明确且不改变合同边界时可直通；任何不确定性返回语义判断。

宿主对每条事件保存唯一处置与关联事项。批次按可信发送者归属处理，不能借同一批消息混用权限。

## 理解目标与可交付结果

读取相关事项、项目、职责、记忆和交接，确定原始目标、已有成果、缺失信息与授权。旧答案只有在版本和环境仍适用时才可复用；昨日测试通过不能证明今日改动正确。

区分目标、实现方法、验收条件与交付阶段。可以自主调整技术路线和拆分执行，但不得把用户要求完整检查变成抽样、把修复变成建议、把上线目标变成本地测试，然后宣称完成。

可逆的小假设记录后继续，明显可自行调查的内容交给调查 Agent。需要用户决定的是实质目标、范围、交付承诺或授权变更，以及确需本人判断的体验验收。提请决定前完成准备，提供推荐和安全默认。

方向型委托的调查覆盖基线、实际瓶颈、原因和证据可靠性。综合各项目调查后，整理有实质差异的方案、收益、代价、风险、自身推荐及理由，集中列出需要用户裁定的选择。可逆的执行细节与已授权范围内的补证由系统判断。

调查后显式给出是否存在实质待决项及理由。没有待决项时直接提出授权内实施与验收合同，不生成形式化的「请批准」；有待决项时标明其依赖分工和可继续部分，按 [协议](02-协议.md#长期职责与事项) 推进。

执行端的提问先归位到当前事项、原请求与版本。可从前情或资料确定的内容自行补齐，需要调查则安排调查；权限请求读取真实目标与动作，不能依据 Agent 的「只是测试」或「已获老板同意」授权。形成应答或用户裁定提案后由协调者按 [反向请求契约](02-协议.md#执行端反向请求) 执行，不要求老板承担传话与技术选择。

## 交办材料

每次派发或续接生成与执行体能力和已有上下文匹配的材料：

1. 要达成的结果、需求版本与来源。
2. 目标机器、项目、工作区、当前代码/产物版本和角色。
3. 已知事实、决策理由、之前尝试及失败证据；材料按需引用，不无限复制日志。
4. 允许的动作、写域、项目规范、权限和禁止事项。
5. 逐项验收方法、交付位置、所需证据与回报格式。
6. 下一检查点、阻塞时应带回的事实、如何接收补充输入。

字段非空只是结构检查。要验证执行体是否理解正确、材料是否够用、执行反馈暴露了什么缺口。误解时先检查自己的提示词与上下文，不默认认为执行体能力差。

## 诊断提案

输入包括原目标、交办版本、会话增量、产物与验证变化、外部依赖及宿主健康。输出区分观察事实、假设、置信程度、待核实内容、建议动作与预期可观察结果。

重复命令、长时间无工具或输出相似只触发检查。诊断要判断：是否正常等待、是否有新假设、是否解决了部分问题、是否已忽略关键约束。必要时安排独立诊断角色，不能让同一错误解释无限自证。

纠偏应具体指出偏离目标之处、支持证据、应改变的方法或缺失材料，以及怎样判断纠偏有效。换 Agent 时带交接，不能从空白开始重犯同一个错误。

## 异议与他人请求

有证据的异议给出能满足原意的替代路径；用户明确纠正后更新理解。不能以估计成本高为由单方缩小范围。异议频率由上下文和历史反馈调整，不按整条线程永远只能一次机械限制。

代接他人请求是后续预留能力，本期按 [首期身份边界](04-世界模型.md#授权) 将非老板材料作为资料处理，不据此接单、采纳方案、确认验收或转移控制权。未来显式启用后才按请求者授权与所代表的老板职责判定；结果和老板摘要仍分别按实际受众过滤，不能用「老板代表」身份转发私聊信息。

## 契约、依赖与验证

```text
interpret(event, context) → disposition + subjectRefs + requirements
composeAssignment(requirementRevision, role, sessionContext) → assignment
diagnose(expectedProgress, observations) → hypotheses + proposedActions
explainDecision(decision, sources) → reason + alternatives
```

依赖协议、规则、记忆和世界模型，不依赖执行体或内核副作用接口。工具层由桌子和托管协调消费其产物。

验证同线程多事项、问进展不打扰执行体、跨机正确定位、提示词缺上下文后的纠正、旧事实拒绝复用以及不擅自缩范围。新增工作类和方法通过规则与记忆扩展，不增加无来源的特殊分支。
