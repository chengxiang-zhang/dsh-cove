# 记忆：一条日志，一个可见域函数

职责：回答"下一次为什么不用重讲"和"这件事为什么在群里说不出"。存的是同事会记住的五类东西，不是键值事实。

边界：不判断该不该做（判断模块的事），不决定什么时候说（时机与措辞的事）。它只负责：记什么、怎么合并冲突、谁能用来判断、谁能被说出来。

## 结构：追加日志 + 可见域，不是带权限列的表

```
memory（只追加）                       visibility（对受众求值的函数，不落库）
  kind            五种之一              canUse(memory, audience)   → 能否进入判断
  topic           话题键                canSay(memory, audience)   → 能否被说出
  about           关于谁                promotions                 → 私聊事实升公共的批次
  body            一句话事实
  authority       owner-said | party-said | config | observed | inferred
  source_event    来源事件
  source_quote    原话片段
  supersedes      指向被它取代的那条
  state           active | superseded | disputed | retired
  use_set/say_set 可见域原子：principal 列表（落库的只有它）
```

可见域规则（已定）：落库的只有 use_set/say_set 原子（principal 列表）；kind 只提供写入时的默认值（抽取器声明），不参与运行期裁决；升权（扩大 say）走批量批准，批准后写一行新原子，不改旧行。canUse/canSay 是对受众求值的函数，不落库：同一条"老板不喜欢长回复"，在有老板的群里可以用于判断、但不能说出；在只有同事的群里连判断都不能用。如果把"每个受众能不能看"写成列，加一个受众就要迁移表；落库原子、受众求值，加受众零迁移。

## 五种记忆（每种是一个抽取器）

| kind | 例子 | 怎么来 | 怎么用 |
| --- | --- | --- | --- |
| constraint | 「dsh-cove 是公开仓库，别并发写」 | 老板原话（必须逐字命中本批消息）或配置 | 命中话题时由宿主自动并入承诺边界，并进案卷 |
| preference | 「回复一句话能说清就一句」 | 原话，或连续 3 次同向纠正后提议、老板在简报里确认 | 进案卷；"改配置不用问"这类会转成自动度 |
| precedent | 「C-4：只跑 responder.spec 而不是全量，因为全量太慢」 | 承诺结案时宿主生成，秘书补一句"为什么这么定" | 闸 1（已有答案）与前情 |
| person | 「A 是做数据的，问的都是 StarRocks 口径」 | 观察，authority=observed | 派活补背景；理解群里谁在问什么 |
| standing | 「每天 18:30 发简报」「pc-tower 的会话空跑就叫我」 | 原话 | 由宿主经 `Ledger.propose` 生成 remind / watch / goal 承诺（origin_kind=host） |

抽取器契约：`extract(trigger) → MemoryEntry[]`，纯函数，只读触发上下文，不写库。加一种记忆 = 加一个抽取器文件 + 注册一行，不改解码、不改表。

## 不混乱、不冲突、不泄露

不混乱：同一 `topic` 下同 kind 至多一条 `active`；写入时查，冲突返回 `CONFLICTS` 让秘书带 `supersedes` 重试或放弃。

不冲突：权威序 `owner-said > config > party-said > observed > inferred`；低权威不能覆盖高权威（`SUPERSEDE_FORBIDDEN`），只能标 `disputed` 并进简报问一次。两条原话打架时新的取代旧的，且下一次用到时说一句"按你 11-06 的说法，不再是 11-04 的 A"。

不泄露：用与说分离。

- `canUse`：当桌子的受众里有 use 集合中的人时可进入案卷，标注"仅供判断，不得说出"。
- `canSay`：只有当本次出站的全部受众都在 say 集合内时才可说出。
- 默认：私聊里老板说的，use 与 say 都只有老板。扩大 say（升公共）只走批量批准：当天一条消息、最多 5 条候选、回"1、3"即可，默认不升，当天没批的过期作废（G7）；批准后写一行新的 say_set 原子，不改旧行。
- 机械兜底：出站前把正文与本桌受众不可说的记忆逐条比对（最长公共子串 ≥12 字，或数字/邮箱/手机号 token 命中）→ `DISCLOSE_BLOCKED`。
- 改写后的语义泄露抓不到，靠"不给原文、只给派生提示"降低：群桌子的案卷里，不可说记忆只以判断提示出现（"回复要短"，而不是"老板说过他讨厌长回复"）。

## 契约

```
remember(entry, trigger) → { memoryId, mergedInto? } | ConflictError
recall(query, audience, purpose: 'judge' | 'speak', limit) → MemoryView[]
visibility(memoryId) → { use: Principal[], say: Principal[] }
promoteCandidates(day) → MemoryId[]        // 供简报批量批准；默认空
applyPromotion(memoryId, approved) → void
disclosures(text, audience) → MemoryId[]   // 出站前的字面兜底
```

`recall` 只返回 `purpose` 允许的条目：`judge` 用 canUse 过滤，`speak` 用 canSay 过滤。调用方拿不到未过滤的原文。

## 依赖方向

依赖协议与世界的路径（可见性原子用路径前缀表达）；被桌子（案卷切片）与判断（闸 1、前情）读取。记忆不依赖判断、不依赖时机；出站兜底由组合根把 `disclosures` 接进内核的 `OutletPolicy`，记忆模块本身不发送任何东西。

## 失败模式

| 失败 | 表现 | 处置 |
| --- | --- | --- |
| 私聊内容进群 | 群里说出只有老板知道的事 | 字面兜底拒发；语义泄露靠"不给原文"；列为每周抽检项（抽 10 条群出站交只读评审） |
| 记忆打架 | 同一话题两条 active | 唯一索引挡；写入返回 CONFLICTS，要求带 supersedes |
| 记忆腐烂 | observed 类越攒越多，永远不被用到 | 60 天未使用的 observed/inferred 自动 retired；原话类只能被新原话取代 |
| 升级刷屏 | 每天问一次"要不要公开" | 每天至多一条批量消息、至多 5 条候选；未批过期作废 |
| 抽取器自造事实 | 把推断写成 owner-said | owner-said 必须逐字命中本批消息（QUOTE_NOT_IN_TRIGGER）；推断只能落 inferred，永远只能 proposed |

## 读数

```sql
-- 同话题同类只能一条 active
SELECT topic, kind, count(*) FROM memory WHERE state='active' GROUP BY 1,2 HAVING count(*)>1;  -- 空
-- 升公共请求每天至多一条
SELECT date(created_at/1000,'unixepoch','localtime') d, count(*) FROM outbox
  WHERE moment='ask' AND body LIKE '%要不要在群里%' GROUP BY d HAVING count(*)>1;              -- 空
-- 未批准内容出现在群出站（金丝雀）
SELECT count(*) FROM outbox o JOIN desk d USING(chat_id)
  WHERE d.chat_type='group' AND o.body LIKE '%CANARY-%';                                       -- 0
-- 记忆引用来源覆盖率
SELECT count(*) FROM memory WHERE authority IN ('owner-said','party-said')
  AND (source_event IS NULL OR source_quote IS NULL);                                          -- 0
```

## 扩展点

- 新记忆类型：`memory/types/<name>.ts` 实现 `extract` 并声明默认可见域；注册一行；不改表、不改解码。
- 新抽取触发：抽取器订阅协议的三种事件（inbound / executor_report / tick），不直接读宿主会话。
- 不做"记忆即检索服务"：检索是 `recall` 的一个参数，不是独立模块；否则会出现第二个可见域实现。
