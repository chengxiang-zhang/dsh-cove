# 世界模型：机器、项目、会话与授权

职责：回答老板指什么、东西在哪里、有哪些可用能力、这次能做什么。目标设计；注册事实与操作权限必须分开。

边界：世界模型提供可核验实体与约束，不决定跨项目优先级，不因发现新机器自动授予权限。

## 对象关系

```text
人 / 通道身份
项目 project ── 多个仓库与工作区 workspace ── 宿主 host
长期职责 ── 多个项目；事项 ── 多个项目与分工
会话 binding = host + provider + session_id ── 工作区 / 尝试
产物 artifact ── 项目 + 版本 + 执行来源 + 访问范围
```

项目 id 稳定，不等同仓库名、路径或机器。一个项目可有多个仓库，一个仓库可承载多个职责；归属显式登记。同名目录与会话 id 在不同机器上互不等价。

存量项目接入先核对仓库身份、实际 checkout、项目规则、现有工作和允许的交付位置，再登记别名、工作区及可用能力。新项目先登记稳定身份与拟定归属，再按已确定的目标、方案和授权分阶段创建或绑定仓库、工作区，并初始化约定的模板、测试与 CI。拟定归属与已核实资源分别显示。创建仓库、推送、公开暴露或配置外部环境按实际目标逐项授权；已成功阶段保留回执，重试前对账。

每个实体记录 canonical、aliases、addresses、source、observed_at、fresh_until 与 manifest。查询返回事实的新鲜度及候选，而不是把扫描结果包装成永远正确的世界状态。

## 范围与注册

范围表达主体、目标路径与能力，例如 local/<workspace>、netbird/<host>/<workspace>、external/<service>/<resource>。路径规范化并按分段前缀匹配，不能让 `/repo-a` 授权覆盖 `/repo-ab`。

- config：可信配置和已有授权导入，保留来源。
- enroll：明确登记，带可信身份与租约。
- discover：只形成待核实实体；可见、可达、可发现不等于可读或可写。

发现与命名由系统先整理现有配置、项目记录与用户上下文；只在歧义会改变目标且无法自行消除时询问。确认的别名写回来源明确的映射，不要求老板每次重讲。

存量会话发现先登记观察对象；缺少控制授权时不得发送任何指令。读取会话本身同样受授权限制，不能以「只读」跳过边界。

## 能力声明与实际验证

manifest 描述 OS、运行器、模型、工具面、工作区和服务。选择执行体前核验所需能力：创建、读取增量、输入续接、消费确认、反向请求类型与应答/对账、定向纠偏、取消、产物获取、模型隔离，以及任务需要的候选环境准备能力。

自报与实测分开存储并带版本/时间。冲突产生 manifest_drift；缺能力返回 CAPABILITY_MISSING，不能用貌似成功的降级替代需求。新增机器或 provider 不要求重写托管逻辑，但适配器必须通过其声明能力的验证。

专业 profile 另记录责任范围、领域知识引用、必需工具/环境、能力评估与已知限制，按 [专业团队协作](14-专业团队协作.md#按风险组队与能力边界) 选择。能创建会话不等于能担任架构、安全或质量角色；能力不足由秘书组织补齐，不能让老板临时替代专业人员。

HTTP transport 的网络可达与远程 network-gate 不等于业务授权；特权宿主路由仍遵守 [远程访问契约](../remote-access.md)。

## 授权

Mandate 保存 principal、scope、capabilities、conditions、policy_revision、granted_by、source_event/config、有效期与撤销。授权不可原地扩写，变化生成新版本。

可信老板的明确请求可以作为该请求范围内的授权依据，已有职责授权可持续覆盖后续工作；不要求每个子任务再确认。宿主必须解析并保存目标与动作范围，不能仅凭 sender=owner 就把所有 draft 升为 allow。

首期人类交办、裁定、本人体验确认和停止/接管只接受可信映射到同一老板 party 的入口身份；群内其他成员、转发文本和执行体引用的「老板说」均不能代替。非老板材料可按已授权观察源作为证据，由长期职责的原有目标和权限独立决定是否调查或发起事项，不能转成人类指令或新增授权。代接他人请求须未来显式启用并定义其身份/授权关系，本期不因老板在群或已授权该项目而启用。

- 老板身份只能由可信配置与身份映射确定；对话自称无效。
- 生产或可能生产的破坏、重启状态数据库、公开暴露、跨主机操作按现有规则取得逐目标授权；SSH 别名只覆盖对应目标。
- 授权内的分工、提示词、重试与更换已授权执行体可自主完成。
- 执行前现查授权与撤销，不能永久依赖缓存。目标、目的或能力变化必须重新求值。
- 缺授权时准备完整方案与默认不执行动作；沉默不等于批准。
- 操作会话的权限不能放大执行体本身权限；委派材料也要限定可使用与可披露的信息。

发布使用 [候选绑定的显式授权](02-协议.md#发布授权)，不能从维护职责、技术方案或本人体验确认推导。

长期职责是要负责的工作，不是授权凭证；登记职责不会自动获得其中所有项目、机器和外部服务的访问权。

## 会话控制权

控制模式为 observed、assisted、delegated、human_controlled：

| 模式 | 允许的行为 |
| --- | --- |
| observed | 在授权范围读取和诊断，不发送控制指令 |
| assisted | 只执行明确委托且逐项证明安全的动作；不能向无执行围栏的会话发送可能触发工具的 prompt/steer |
| delegated | 在明确事项与授权内自主续接、纠偏、取消或替换 |
| human_controlled | 已确认人类接管，保留观察，暂停自主控制，等待明确归还 |

接续已有会话先核对宿主、provider、目录、原目标与用户已有指令，再取得控制租约。不通过核对不能仅凭同目录或同名 id 把会话认作自己的。

人工接管、外部取消或授权撤销提升 epoch 并使旧操作失效。停止可能已跨网络在途，需核实远端结果；不能承诺仅靠本地标记就立即撤销已经发生的动作。

外部取消来源未明时，绑定仅保留 observed 能力，事项记录 [权属待核实的暂停](02-协议.md#长期职责与事项)；不把无法识别操作者等同于已确认人工接管。归因结论和其他控制意图共同决定能否恢复原模式，授权撤销不因故障归因而解除。

## 落点与资源

归属选择先看数据与产物实际使用位置，再看已有会话、工作区、能力、授权和资源。能续接就不无故新开会话；需要新目录时走受控 provision，记录目录所有者和清理条件。

同一 checkout 的写、分支整合和共享环境修改由资源锁保护。使用独立目录、分支或 worktree 必须符合目标项目的规则；不把一种隔离方式强加给所有项目。

## 契约与依赖

```text
resolve(reference, context) → candidates + provenance + freshness
inventory(scope, cursor) → projects/workspaces/sessions/capabilities
authorize(actor, target, action, purpose) → permit/draft/deny + source
place(requirement, candidates) → target + resource requirements
bindSession(identity, controlMode, mandate) → binding + control epoch
```

依赖协议；适配器由组合根注入。上层读取世界模型并通过内核持久化相关运行事件；发现适配器只能提供事实，不绕过授权授予控制权。

## 失败模式与验证

验证同名仓库、跨机同 id、路径前缀、过期 manifest、撤销授权、老板请求的范围解析、人工接管与受控 provision。读取失败保留不确定性；不能把没读到会话判成会话已消失。扩展世界适配器只增加事实来源，不能改授权含义。
