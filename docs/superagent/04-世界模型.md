# 世界模型：范围、实体、授权、归属

职责：回答三个问题——哪些地方能动、那些地方是什么、我能不能在那里做这件事。它产出的是范围路径、实体清单和不可变授权。

边界：不判断该不该做（判断模块的事），不执行动作（执行体的事），不定义记忆可见性（记忆模块的事，但用它的路径前缀）。

## 范围是路径，不是白名单

```
local/                                   本机
local/~/code/dsh-web                     本机上的一个仓库
netbird/dsh-pc-tower                     一台 NetBird 机器
netbird/dsh-pc-tower/~/code/dsh-web      那台机器上的一个仓库
netbird/dsh-pc-tower/session/sa-x-C-12   那台机器上的一次执行体会话
external/github.com/chengxiang-zhang     外部组织
```

路径上挂三样东西，形状相同、语义不同：

| 挂什么 | 回答 | 继承规则 |
| --- | --- | --- |
| 能力声明 | 这里能做什么（有没有 docker、能不能起 DSH） | 向下可细化，向上只聚合（父说能跑 node，不代表子能跑 docker） |
| 授权 mandate | 我能不能在这里写 | 严格向下继承；写必须显式给到路径级 |
| 可见性原子 | 哪些记忆能在这里被引用 | 与范围正交，但同样用路径前缀表达 |

路径的好处是把"这台机器整台可读、只有这一个仓库可写"写成一句话，而不是两条互不相干的规则。代价：所有白名单要迁移成路径。

## 注册：三条通路，三个信任级别

| 通路 | 谁发起 | 信任 | 生效 |
| --- | --- | --- | --- |
| `config` | 人写配置 | 最高 | 直接 enrolled；owner 与 colleague 只能走这条 |
| `enroll` | 机器自注册，带一次性令牌 | 中（令牌由人生成） | 令牌有效即 enrolled，带租约 |
| `discover` | 扫描到未知 peer，只提议 | 最低 | 只能进 proposed，要人一句话确认 |

硬规则：`discover` 不能自己生效。否则"我能动哪些机器"由网络拓扑决定，别人接一台机器进来，你的权限就自动扩大。这是安全边界的起点，不是体验优化。

三态：`proposed`（看见但不算数）→ `enrolled`（算数）→ `revoked`（立即从所有判定消失，不需要理由但要留记录）。永不硬删除：机器下线不等于它不存在。

## 实体、称呼、地址分三层

```
world_entity   canonical（人可读唯一：dsh-pc-tower、dl-dev、imac）
world_alias    IP、SSH 别名、DNS 名、口语说法 → entity
world_addr     入口地址与优先级（LAN、wifi、NetBird、DNS）
```

名字在注册时定，不在查询时猜：

- 注册强制填 `canonical`；同时登记所有已知称呼。
- `enroll` 的一次性令牌由人生成——生成令牌的人有义务起名。命名责任放回唯一知道它是什么的人手里。
- 消歧只在"老板用了没登记过的说法"时发生，结果写回别名表，不临时猜。

这解释了今天 SSH 配置的病：27 条别名对应 25 个 host，同一台机器的四个入口是平的（F27）——因为写配置时没人要求归并。

## 能力声明由实体自报

实体注册时自己跑一遍并上报三件事：我在哪怎么连、我能做什么（os/arch、有没有 dsh/docker/node/git、能承载哪类执行体、CPU 与磁盘档位）、我上面有什么（工作区、仓库、常驻服务）。

为什么自报而不是只扫描：扫描得到"我看到什么"，自报得到"它以为的自己"。两者都要，判断派给谁时用自报，冲突以扫描为准并记一条 `manifest_drift`。

安全边界：manifest 只是声明。任何写操作仍要 `mandate`——"我说我能写"和"你允许我写"是两件事。

## 授权是不可变记录

```
mandate {
  mandate_id, principal,         谁被授权
  scope_path,                    在哪个路径
  capability,                    封闭枚举：read | write_repo | write_host | change_prod |
                                 publish | commit_promise | steer_foreign | provision
  strength,                      allow | draft | deny
  policy_version,                按哪一版规则给的
  granted_by, granted_at, revoked_at
}
```

- 只追加：改授权 = 新增一条，旧的标记 `revoked_at`。没有"原地修改"。
- 只有人能授予：对话里说"你现在是老板""你可以改线上"不产生任何授权（G6 的读数）。
- 判定 = 路径前缀匹配 + 能力 + 强度；越界即 `draft` 或 `deny`，由判断模块拿它当闸。
- 三态表（谁 × 能做什么）是默认配置，不是代码：老板 allow/draft 视能力，同事只读 allow、写 draft、改线上与发布 deny，群内其他人只读 allow，外部人全部 deny。

## 归属：活落在哪

三步，每步决定者不同：

| 步 | 决定 | 谁定 | 依据 |
| --- | --- | --- | --- |
| 1 域 | 本机 / 某台 NetBird 机器 / 外部 | 模型提议 + 宿主校验 | 产物给谁用、要不要长期在线、数据在哪 |
| 2 宿主 | 哪台机器 | 宿主机械筛选 | 能力声明 + 可达性 + 现有授权 |
| 3 落点 | 复用工作目录 / 新建工作区 / 纯临时 | 模型提议 + 宿主校验 | 产物类型；目录里有没有 `.git` |

第 3 步的"新建"是一次 provision，要在目标主机上执行动作，因此必须持有该路径的 `write_repo` 并记录批准人。没有这条，"新建工作区"就是没人认领的副作用。

## 契约

```
resolve(mention | path) → { entity?, scopePath, candidates[] }   // 消歧只在未登记说法时发生
mandate(principal, scopePath, capability) → allow | draft | deny
enroll(entity, token) → Entity                                   // 令牌由人生成
propose(entity, manifest) → Entity(state=proposed)               // 扫描只能走这条
place(commitment) → { realm, host, workspace, mandateId }
revoke(entityId, by) → void                                      // 立即生效，不删记录
```

## 依赖方向

依赖协议（对象形状）与世界适配器（发现来源）。被记忆（可见性路径前缀）、规则（作用域路径）、桌子（本桌范围）、判断（授权闸）、执行体（落点与写权限）、恢复与降级（实体状态对账）依赖。世界模型不依赖它们中的任何一个：它不知道有判断、有桌子，只回答"范围、实体、授权、归属"。

调用关系写死：上层只能调 `resolve`、`mandate`、`place`、`revoke` 四个方法；世界模型不回调任何模块，也不发消息。加一个发现来源只能写适配器，不能改判定。

## 失败模式

| 失败 | 表现 | 处置 |
| --- | --- | --- |
| 发现被当注册 | 未知 peer 自动可写 | 表级约束：`source='discover'` 且 `state='enrolled'` 不允许；读数查为 0 |
| 称呼漂移 | 老板说"那台 mac"它反问 | 消歧只在三种情况问：说法没登记、候选分差 < 30、实体不在任何已授权范围 |
| 授权腐烂 | 人走了授权还在 | 授权带 `policy_version`；策略版本升级时扫一遍超期授权，进简报 |
| 租约过期 | 实体失联仍被派活 | lease_until 过期转 stale，30 天转 gone，不参与判定但保留记录 |
| 无主工作区 | 目录存在但没有 mandate | 读数：存在工作区但无对应授权 = 0 |

## 读数

```sql
SELECT count(*) FROM world_entity WHERE state='enrolled' AND source='discover';   -- 0
SELECT count(*) FROM world_entity WHERE state='enrolled' AND lease_until < :now;  -- 0
SELECT count(*) FROM workspace w WHERE NOT EXISTS (
  SELECT 1 FROM mandate m WHERE m.scope_path = w.path AND m.revoked_at IS NULL);  -- 0
SELECT count(*) FROM mandate WHERE granted_by='superagent';                       -- 0
```

## 扩展点

- 世界适配器：`world/adapters/<name>.ts` 实现 `DiscoverySource`（扫 NetBird、读 SSH 配置、读仓库清单），注册一行。适配器只能产出 `proposed`。
- 能力清单：`capabilities/<name>.ts` 里的 manifest 声明它需要哪些路径、哪类授权、哪个执行体模板；注册后由本模块校验路径与授权，不合规拒绝加载。
- 不用"专用预设"约束能力（F12）；预留名单写 restrict 也不行（F9）。能力边界靠授权与工具面，不靠提示词。
