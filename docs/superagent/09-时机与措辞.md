# 时机与措辞：什么时候说、说什么

职责：决定什么时候开口、以哪一档打扰老板、每条消息长什么样；维护议程来源、简报、命令与只读面板。

边界：不判断该不该做（判断是判断模块的事），不发送（所有出站都经内核出口，它只提供模板与档位建议）。它不能绕过出口直接发消息。

## 议程来源：主动只有四个，全部挂在承诺上

没有"随便想起来说点什么"。今天 19 次主动回合全部以"沉默"结束（F32），正是让会话自己想起来说话的结果。

| 来源 | 机制 | 开口条件 |
| --- | --- | --- |
| 交付预警 | deliver 承诺到点，宿主先算信号：已用墙钟 > 校准 ETA、10 分钟无工具调用（停滞）、同一命令或同一文件编辑 ≥3 次（打转） | 有信号才请求回合；首次超 ETA 且老板 2 小时内问过 → 打断一次"比预计慢，卡在 X，再给 10 分钟还是换强模型"；否则进简报 |
| 盯会话 | watch 承诺：目标是某台机器上的某个会话（不一定是自己派的）。探针每 10 分钟读一次事件计数与最近工具调用名 | 两个窗口零工具调用，或打转命中 → 打断一次并给两个选项（给具体指令 / 停掉）；目标结束 → 结案，简报一行 |
| 提醒 | remind 承诺：老板对别人许下的事也是承诺 | 到期前提醒一次 |
| 目标推进 | goal 承诺：每周一次请求回合，产出 ≤3 件提案，球在老板 | 只进简报，"回 1、3 批"；批准后自动派活 |

探针怎么读：优先走目标机 DSH 的只读会话接口；没有则由 oneshot 只读执行体读会话持久化文件尾部。本仓 `inspect` 会返回全量事件（F2），探测侧必须自己限流，不能每次拉全量。今天仓库零处统计事件计数，探针是新代码。

## 投机执行：提前想清楚，绝不提前动手

三类投机，宿主可分别开关：

| 类 | 触发 | 产出 |
| --- | --- | --- |
| 1 探询转探查 | 老板问"能不能 / 是不是 / 要多久" | 一次只读验证的结论（跑过什么、结果如何） |
| 2 排队期预备 | 承诺在等槽位 | 方案草案：改哪些文件、验证命令是什么 |
| 3 空闲巡查 | 无新事件也无到期承诺 | 对在办承诺的一次只读核查，发现风险则形成候选提醒 |

边界（强加，可被老板否）：投机只能产出信息与草案，不能产出改动。改代码、改配置、对外发送一律不属于投机——没经过验收的产物直接落地，等于绕过"交付必须带证据"。

落点：`~/.dsh/superagent/speculations/<id>/`，登记在 `speculation`，不进出口。不采纳 → `discarded`，零消息，保留 7 天（老板问"你刚才在算什么"能答）；采纳 → `used`，第一条回复引用"我提前看过：会在 X 失败，因为 Y"；3 天未采纳 → 过期，静默。

风险：投机太勤是秘书空跑的第二种形态。判据：`discarded/(used+discarded)` 连续一周 > 80% ⇒ 收窄第 3 类。

## 全双工：执行体在跑，桌子照常说话

- 执行体与桌子是两个会话；`turn_open` 只限制桌子自己一次一个回合。
- 议程回合不阻塞对话回合：桌上有活人消息时，`next_look_at` 顺延 60 秒，最多 5 次。
- 等待中的承诺不占桌子：球在执行体或其他方时，桌子空闲。
- 读数：承诺在跑时老板发寒暄，受理 p95 比空闲时差 < 3 秒；`trigger_kind='intake'` 排队 > 2 秒的占比 < 5%。

## 注意力：四档，由宿主定，模型只写内容

| 档 | 进什么 | 上限 |
| --- | --- | --- |
| reply | 对刚收到消息的受理、直接答、异议、问题、他在等的交付 | 每条入站至多一条 |
| interrupt | 球到老板手里且有钟在走（预算到线、别人在等、24 小时内有风险）；不可逆风险预警；watch 判定空跑；他在等的交付首次超 ETA | 每天 3 条；超额降入简报，并在下一条回复末尾附"另有 N 件进了简报"；静默时段 22:00–08:00（沿用现有配置，F28），只有不可逆风险可破例 |
| brief | 不在等的交付、等老板但不急的决定（≤5，带编号）、校准与自动度变化、记忆升权提议、目标提案、被降级的打断 | 每天一条，≤100 词：每行 ≤15 词、至多 6 行，溢出写"另有 N 件，回'全部'展开" |
| silent | 进度、成功的重试与换执行体、"看一眼"、内部核查、失败后自动恢复成功的事 | 只在 `status` 与账本里 |

简报同时是心跳：账上有开着的承诺而当天没收到简报，老板就知道它死了。账上无事且当天无事，不发。

## 措辞：模板是数据，发送是内核的事

| 时刻 | 模板要求 |
| --- | --- |
| 受理（ack） | 固定句式：接了 C-n：按什么理解。预计 N 分钟。不对就说 / 先回答我：问题。≤100 词 |
| 交付（deliver） | 改了哪、跑了什么、退出码、读数。未验证的必须前缀"做完了，但没验证"。≤100 词 |
| 异议（pushback） | 引用原话或数字 + 一个替代方案；每条线程一次 |
| 提问（ask） | 只问一个具体问题，给选项与默认值 |
| 无法完成（cannot） | 停在哪一步、已产生的改动怎么处理、下一步选项 |
| 简报（brief） | 编号清单，每行 ≤15 词，≤6 行 |
| 告警（alert） | 只由议程回合在宿主报告信号后使用；不可逆风险可破静默 |

发送前由出口做三项机械检查：词数 ≤100；未授权承诺词（时间点、范围扩大、对外发布）拒发；不可说记忆字面命中拒发（R15、R7）。非老板对话的首条消息带身份说明（R16），对外动作标"由代理执行"。

今天的停止词只有四个字面量且要求整条相等（F4），承诺词检测、身份前缀、未验证前缀都没有实现——模板与检查是新代码。

## 命令与面板

`status [--json]`、`stop C-n`、`brief --now`、`calibration`。只读账本；`stop` 写一行释放意图由服务执行。退出码 0 成功、1 失败、2 参数或 IO 错、3 无数据（F31 的真实约定；照抄旧脚本会漏 2）。

面板是 `status --json` 的只读渲染层：什么在办、什么在等老板、今天打断了几次、空跑率。它不是新状态源，也不进第一期（原话 15）。

## 防空跑（秘书自己的）

- 时钟到点先做无模型信号计算；无信号机械后推，不起回合（内核 `TickSignal`）。
- 每日秘书回合上限（默认 200）；超了只剩宿主模板与快路径，并在简报里报。
- `deliberation.ops=0` 的回合占比是空跑率读数；>30% 收紧信号阈值。
- 承诺在简报里出现 3 次仍未处理 → 自动升为一次打断，并把每日额度从 3 调到 4。

## 契约

```
Agenda.due(now) → CommitmentId[]                    // 供内核 TickSignal 使用
Attention.tier(subject, context) → reply | interrupt | brief | silent
Templates.render(moment, data) → { text, words, expectsReply }
Brief.build(day) → { body, items }                  // 每天一次，兼心跳
Commands.run(name, args) → { json, exitCode }
Panel.render(statusJson) → html | null              // 只读，不进 P0
```

## 依赖方向

依赖协议、内核（提交出站提案、读账本）、规则（注意力额度与模板条件）。被内核的 `OutletPolicy` 接口注入（由组合根接线）。不依赖判断与执行体：它只看账本里的承诺状态。

## 失败模式

| 失败 | 表现 | 处置 |
| --- | --- | --- |
| 打扰过多 | 一早起来十几条 | 每日额度 + 静默时段 + 超额折叠进简报 |
| 打扰过少 | 该叫没叫，老板说"怎么没告诉我" | 扫描"怎么没/为什么不早说"进校准；简报里 3 次未处理自动升打断 |
| 简报被无视 | 连续多天无人回复 | 计数；把"在简报里出现 3 次"升为打断 |
| 承诺词泄漏 | 说出没被授权的时间或范围 | 出口机械扫描；命中即拒发并要求改写 |
| 投机烧钱 | 采纳率低 | 采纳率 <20% 连续一周收窄第 3 类 |
| 空跑 | 回合多、动作少 | 信号预检 + 每日上限 + 读数 |

## 读数

```sql
SELECT tier, count(*) FROM outbox WHERE state='sent'
  AND created_at > strftime('%s','now')*1000 - 86400000 GROUP BY 1;
SELECT date(created_at/1000,'unixepoch','localtime') d, count(*) FROM outbox
  WHERE tier='interrupt' GROUP BY d HAVING count(*)>3;                       -- 空
SELECT date(created_at/1000,'unixepoch','localtime') d, count(*) FROM outbox
  WHERE moment='brief' GROUP BY d HAVING count(*)>1;                         -- 空
SELECT trigger_kind, round(avg(ops=0),2) FROM deliberation
  WHERE started_at > strftime('%s','now')*1000 - 86400000 GROUP BY 1;        -- agenda < 0.3
SELECT kind, round(avg(state='used'),2) FROM speculation GROUP BY 1;         -- 采纳率
```

## 扩展点

- 议程来源：`timing/agenda/<name>.ts` 实现 `AgendaSource.due`，注册一行；只能读账本，不能直接发消息。
- 模板：`surface/templates/<moment>.ts`，注册一行；模板不能自己发，只能被出口调用。
- 命令：`surface/commands/<name>.ts`，注册一行；只读账本或用一行意图。
- 面板：`status --json` 的一种渲染，不是独立模块；换前端不改后端。

## 为什么不是另一种

- 为什么不做"消息一来就回"：Hermes 事故是一次消息 8 个回复（F34；出口唯一与租约的由来，见 [恢复与降级](11-恢复与降级.md)）；回复慢不是问题，抢答和刷屏才是。
- 为什么简报是心跳而不是日报：老板要判断的是"它还活着吗"，不是读新闻；一天一条、超了折叠。
- 为什么投机不能产出改动：没有验收的改动落地，等于把"交付必带证据"这条宪法绕过去。
