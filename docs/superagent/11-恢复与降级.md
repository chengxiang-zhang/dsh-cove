# 恢复与降级：责任持续，副作用可核对

职责：在重启、热更、通道故障、远端失联和控制权变化后恢复事实与操作连续性。目标设计。

边界：恢复不是业务重规划器，不自行更改目标、恢复人已停止的工作或通过降级扩大权限。诊断与下一策略交托管协调。

插件升级是有计划的版本切换，故障恢复是对实际事实重新对账；二者共用控制围栏与持久状态，不能互相冒充成功。热更中的安全点、在途请求、旧回调、schema 迁移与不可逆回退按 [热更与迁移](16-架构与扩展.md#热更与迁移) 执行，整域重载同样适用。

## 启动与持续对账

启动顺序：协议兼容检查与迁移 → 获取相应租约 → 重建角色和会话绑定 → 对账未知操作/在途尝试/未交付成果 → 恢复订阅与复查 → 接受新协调写操作。

持续对账同时覆盖 active 职责、非终态事项、父子版本与成果组合、专业责任/交接及能力版本、未决专业决定/审查问题/改进项、尝试、控制租约、资源锁、未消费输入、待答执行端请求、候选环境、操作回执、验收与出站状态。不能只检查「会话还在不在」。

| 观察 | 处置 |
| --- | --- |
| 远端可读，会话仍在运行 | 补游标并更新事实，不重复 prompt |
| 明确不存在 | 保存前情与成果，结束该尝试，交系统诊断是否换执行体 |
| 远端超时或无权限 | unknown，不等同不存在；保留可能有副作用的锁 |
| 原生线程恢复失败或 ID 不匹配 | 保留原绑定及待投输入，标记恢复阻塞并对账；不得自动换线程。确证需换执行体时，由托管协调走显式交接 |
| 会话结束但事件丢失 | 回读终态与产物，走相同验收入口 |
| 操作已发送、回执缺失 | 依幂等键和远端事实确认，不先重放 |
| 新输入未消费 | 保留输入及事项版本，不按旧报告结案 |
| 原生待答请求或响应结果不明 | 按 [反向请求协议](02-协议.md#执行端反向请求) 核对原请求与原生代次；仍有效才应答，失效不重放，未解决问题交协调者在原线程衔接 |
| 父目标与子单绑定版本不符 | 保持旧动作不可发送，恢复版本门禁及撤销意图，提交影响判定；不能只恢复子单 running 状态 |
| 候选环境被覆盖、失效或反馈版本不匹配 | 不采用过期体验证据；补读实际环境与候选，安排授权内恢复或新候选，已发生正式交付独立对账 |
| 已确认人工接管或用户取消 | 撤销自主控制，保留观察与成果，按归还或取消语义处理，不自动拉起 |
| 取消来源未明或归因证据补到 | 恢复权属待核实的暂停及原控制意图，按协议核实；确证非人工故障且满足全部恢复条件才自主续接，不能以日志缺失推断无人接管 |
| 专业角色失联或交接中断 | 保留责任、产物及原绑定，核查控制权后由秘书接续或显式交接；不能以角色消失关闭缺陷或跳过专项 |
| 旧审查、发布授权或改进记录恢复 | 按合同/候选/目标版本核对适用性，恢复未关闭问题和改进复查；不能重启后遗失质量阻塞或再次采用已回滚方法 |
| 方法/profile 资格撤回或验证环境污染 | 恢复资格失效门禁及历史影响复查，按协议阻止相关旧 pass 放行；不能仅因合同和候选未变恢复有效性 |
| 验收通过但未交付 | 检查产物版本与交付回执后续接，不重复有副作用的发布 |

不得仅因来源是老板就把 proposed 批量升 ready。要重新核对该事项的实际授权来源与范围、提案性质、待决项和是否已有执行；老板明确委托且授权有效、无实质待决的工作不应陷入重复请示。

## 租约与活性

出口租约、会话控制租约和资源锁分别管理。心跳与调度定时器由同一生命周期装配，启动中止必须清理；不能留下持租约却无人服务的进程。轻量看门狗检查调度是否推进，并按生命周期恢复定时器。

同库 epoch 防止多个进程重复控制；跨宿主需明确一个操作控制者和幂等身份。发现同一通道另一实例时不能宣称本地租约已防住所有重复；限制本方冲突写入并保留事件，必要时告知实际影响。

服务健康不能只靠老板观察有没有简报。部署级进程故障需独立健康检查与既定运维机制；它的安装或重启权限不由本设计自动授予。

### 独立活性恢复

声明无人进程恢复前，须登记部署恢复绑定：受控实例及持久账本身份、现有 supervisor、进程外健康检查者与恢复执行者、逐目标运维授权、业务活性判据和检测/恢复预算、旧写者隔离办法、审计回执及人工停止抑制。复用已存在的 LaunchDaemon/systemd 等托管机制，但进程存在、端口可达或配置了自动重启不证明业务活性；分别验证异常退出、不会自动拉起的退出和进程存活但事件循环挂死。进程内修定时器、模型协调席位换代与部署级恢复是不同能力。

外部健康检查及恢复执行者必须位于被检查进程的故障域之外，不能依赖该进程的事件循环或模型同意才触发。其权限仅限登记的观察和恢复操作，不承接项目调度或产生第二业务账本；先检查持久的人工停止/运维维护意图，按既定机制隔离旧写者，再从同一账本恢复。恢复发现事件、授权、操作与结果均有独立可回读的回执；控制面恢复后纳入对账。事项暂停或有效等待不等于进程故障，明确停服/维护不得被自动拉起。

授权或所需恢复能力缺失时，列为该部署的自治能力缺口，不宣称满足 M1 的进程恢复门槛。故障实验只在已授权的独立实例进行，不能中断当前运行的 DSH；本设计不更改现有重启禁令。验收时测试设施只注入故障与观察，由登记的运维恢复者实际恢复，测试脚本或人代为启动属于救援，必须判该无人恢复案例失败。

## 工具与权限退化

每回合校验协调座席的可执行能力边界，执行前再验证目标端能力、授权与控制 epoch。热更后工具面异常时停止新增副作用，尝试授权内恢复座席；停止意图、只读查询与对账尽可能保留。

能力缺失是明确退化状态，不能通过换 standard 预设、放宽 guard 或相信报告自述来制造成功。权限撤销后缓存立即失效；最后一次成功授权不能作为无限期执行凭证。

## 降级矩阵

| 故障 | 可继续 | 必须保留的限制 |
| --- | --- | --- |
| 判断模型不可用 | 已授权执行继续、事件入账、控制路径、备用判断模型 | 不让模板猜新的语义操作；恢复后补处理，不要求重发 |
| 某执行宿主不可达 | 其他项目工作、只读状态、等待与替代方案准备 | 未核实旧写者停止前不能并发替代写入 |
| 规则/知识服务不可用 | 使用有版本和适用范围的缓存、记录新运行事实 | 无法确认的授权不补造，不发布未经验证的学习 |
| 发送失败 | 执行与验收继续，持久出站并退避 | 不把未送达标已通知；恢复后丢弃过期消息 |
| 验证器不可用 | 收集成果、安排其他可信验证 | 结论 inconclusive，不能降成「路径存在即成功」 |
| 数据库不可写 | 只读状态与已运行执行体观察 | 无法先持久意图则不发新副作用；通道无法持久化时不得确认已受理 |

常规恢复不变成老板待办。故障确实影响结果、截止或授权时如实沟通，提供系统已做的准备；不要求老板重发消息、换模型或替执行体传话。

账本不可写时的停止/撤销使用 [内核](03-内核.md) 的紧急控制日志和目标端 epoch，不视为新业务执行。所有持久化都不可用时只能报告未确认，不承诺恢复后一定记得；目标端租约围栏及恢复对账必须防止旧任务无授权复活。

## 停止与恢复的优先级

停止和人工接管意图必须跨重启持久化。恢复后的第一件事是落实尚未确认的停止、撤销与权限变化，而不是按旧 running 状态重派。

恢复同时重建 paused/human_controlled 控制状态、职责暂停范围和 finding 的停止抑制记录；没有新用户委托或职责边界变更，不重开相同已取消工作。事项保持 waiting/at_risk 时必须有下一次复查与恢复触发。最终无法满足约束的结论需要证据，不以尝试次数判定，也不无限排队掩盖失效。

## 契约、依赖与验证

```text
startup() → reconciled state + active capabilities + unresolved actions
reconcile(now) → observations + safe repairs + diagnosis requests
selfCheck(scope) → capability status
degrade(reason, scope, recoveryCondition) → degrade record
```

依赖协议、内核、世界模型；通过注入端口读取宿主事实，输出诊断事件，不直接调用桌子或执行体业务逻辑。安全修复限于已确认事实的投影、游标、租约和订阅恢复；外部副作用仍经 Action。

扩展对账检查项要声明读取来源、可自动修复范围与不确定性。验证注入断线、丢回执、丢 turn/end、重复消息、时钟停摆、人工停止、权限撤销及迁移失败；检查无重复副作用、无责任丢失、无误杀和无假完成。

`scripts/superagent-check.mjs` 是现有只读账本检查入口，退出码语义保留 0 成功、1 失败、2 参数/IO、3 无数据。当前脚本尚未覆盖目标协议；新增运行验收应按 [验收与评估](13-验收与评估.md) 落地，不能把旧脚本退出 0 当作新设计已经实现。
