# 秘书式 super-agent 设计

这套文档定义 `packages/dsh-web-all` 里飞书秘书能力的形态、判断、规则与数据模型。它是一条长期演进的能力：机器人不只应答，它替使用者管着干活的执行体。

文档按**读者与变更频率**划分，不按篇幅。同一条事实只在一个文件里写，其他地方用全局节号引用：`§5.3` 指全体系连续编号的第 5.3 节，不指某个文件的相对章节。

## 权威顺序

1. [需求与原话](00-需求与原话.md)：使用者原话逐字，含笔误。最高权威。
2. 其余文档：平级，各自覆盖不同节号。互相冲突时以节号大的为准。
3. 任何转述与子代理产出：最低。

正文与原话冲突时以原话为准，并把冲突交回使用者。

## 三条阅读路径

- 只判断值不值得做：目标与边界 → Roadmap 与验收 → 需求与原话。
- 要动手实现：形态与会话 → 数据模型与接口 → 判断与协调 → 规则引擎 → 世界模型与作用域。
- 要做评审：可靠性与观测 → 设计问答 → 抽查判断与协调、规则引擎。

## 编写规则

1. 同一事实只在一处。表结构只在数据模型，规则模型只在规则引擎，范围路径只在世界模型；别处引用节号。
2. 跨文档引用一律用全局节号，不写「某文件的某节」，否则调整文件划分会打断全部引用。
3. 改任何一份，同一次改动更新上面的文件表。
4. 需求与原话只增不改：新裁定追加为新条目，旧条目保留，笔误标〔原文如此〕。
5. 标注纪律：〔已证实〕要有代码行号或命令读数；〔推断〕要能看出由哪条已证实事实推出；〔未验证〕要写清在哪一期验收里测。
6. 描述当前状态，不写变更历史；历史留在 Git 提交与 Issue。
