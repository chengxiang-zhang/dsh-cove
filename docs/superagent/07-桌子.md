# 桌子：同一个秘书的多对话入口

职责：把持久责任、事实和记忆编译成当前判断所需的上下文，使换窗口、换代和冷恢复不需要老板重讲。目标设计。

边界：桌子是对话入口和模型运行上下文，不是每个项目各自的负责人，也不拥有独立真相。判断、托管协调与执行端各有职责。

## 案卷

每次回合包含身份与授权摘要、当前用户意图、相关项目与职责、事项及检查点、父子合同和成果组合引用、待答执行端请求及当前体验候选、近期决策理由、已发生操作与回执、适用工作方法、本批消息及引用。

上下文按当前问题组织，不机械限定「老板说过最多八条」。硬边界、停止意图、当前验收条件和未消费输入不可丢失；大体量在办清单摘要化并保留可展开索引，不把所有项目日志塞进每个回合。

每个来源记录事实版本、时间、用途和可见性。过期快照明确标注；模型需要更多信息时通过 look 获取有权限的资料，不能靠猜测补全。

案卷作为动态 user/context 输入，不把原始动态文本直接拼到静态 system section。模型看到的日志、文档和执行体输出标为资料，不能改变身份与工具规则。

## 连续性与隔离

同一个人的连续性体现在同一目标理解、纠正生效、决策理由、事项前情与承诺接续。案卷 hash 只辅助诊断，同一事实 revision、同一实际受众与用途才要求投影一致。

不得强制五分钟内所有案卷相同：新事实、纠正、授权撤销必须立即可见。受众不同允许看到不同内容；公共事实应在相同来源版本下相容，不要求私聊与群聊共享私有案卷。

共享的是可追溯状态，不是桌子之间私下转述。多个入口对同一事项的修改用版本校验；一个线程可以讨论多个项目，每条消息可关联多个事项。

首期仅服务一位老板。飞书与网页入口将各自认证后的身份映射至同一 `party`，经相同的入站认领、事项归位与消息出口契约工作，各自保留会话来源和受众。网页上的项目目录或会话展示不能单独视为已接通秘书入口。代老板受理他人请求保留为后续能力，指令与资料的边界遵循 [世界模型](04-世界模型.md#授权)。

## 回合与全双工

每桌一个正在输出的对话回合，执行体运行不占用对话回合。长时间的调查、模型推理或远端操作必须可被停止与接管通道抢占；不能因为桌子忙就延迟落实明确停止。

人类消息优先进入响应路径；职责检查由独立持久调度保障，不因用户持续聊天无限后推。多个项目协调可以并行读取，对共享状态的变更必须序列化。

会话懒创建、可驱逐与换代；具体寿命由上下文和宿主能力决定。驱逐前确认关键状态持久化，恢复时重编译，不能要求老板复制旧提示词。

## 网页输入框的下一句预测

拟议的网页对话增强，沿用面板低优先级约束。秘书回复完成后，预测老板此刻最可能接着发的一条消息，减少重复输入。预测应承接老板已经表达的意图，例如询问刚提到的回滚条件或纠正候选方案；秘书按职责应自行推进的工作仍走 [托管协调](12-托管协调.md)。

采用回合结束后独立、异步的只读推理。把建议写进主回复可以省一次推理，但会混淆秘书的行动建议与老板的输入。固定快捷短语延迟低，适合常用命令，难以承接具体对象和约束。独立推理可以单独限时、限频和关闭，代价是额外的推理延迟与成本。交互参考 [Codex Composer Predictions](https://learn.chatgpt.com/docs/features/composer-predictions)。

1. 网页桌子有已完成的可见秘书回复，且线程空闲、输入框为空时，才请求预测。首版仅在老板的网页私聊启用，每个回复版本最多发起一次，打开旧线程时暂不补算；飞书维持原有对话交互。
2. 宿主按当前身份、受众和用途构造同一线程的可见对话快照，保留最新意图、纠正和具体约束。预测请求禁用工具和副作用，只携带这份快照与版本化提示词。可见消息作为资料传入；私有案卷、未展示的跨项目事实、后台执行输出和凭据均排除。
3. 返回 `{ suggestion: string | null }`。提示词要求预测老板最可能输入的具体动作和对象，用老板的语言与口吻写一条自然消息，保留影响意图的限制；措辞不确定时选最有依据的一条，无依据才返回 `null`。建议限制为一行、最多 240 个字符。宿主校验输出，并丢弃替用户批准、扩大授权或作出外部承诺的候选。
4. 用身份、受众、线程、回复版本及权限版本绑定预测。网页仅在这些条件仍匹配且编辑器空闲时显示灰字。开始输入或输入法组字、切换线程、新回合开始、权限变化或关闭预测时撤下建议并取消在途请求；迟到的结果丢弃。按 `Tab` 只把建议放进可编辑草稿，用户显式发送后才进入现有入站认领与授权校验。

预测是短时展示状态。生成、展示、接受和忽略均不产生人类消息、事项、裁定或学习样本。超时、模型不可用或输出无效时安静降级为空输入框，正常对话、停止和后台托管继续。观测记录提示词版本、耗时和展示、接受、发送计数，默认不记录预测文本或原对话。

上线前在真实网页入口验证：多轮纠正后建议指向最新对象；无依据的闲聊不产生建议；后台私有信息无法进入候选；用户抢先输入、组字、切线程、撤权或开始新回合时，迟到的结果不会出现或覆盖草稿。分别检查只展示、按 `Tab`、显式发送三个阶段的消息与账本变化，并验证已有待裁定事项只按原裁定协议处理。

## 受控工具面

桌子可以读取项目/会话/材料，理解、组织交办、安排、续接、纠偏、回收、请求验收、记录经验和提议消息。允许哪些逻辑能力见 [协议](02-协议.md)。

它不拥有任意 shell、业务仓库文件写、凭据读取或绕过受控端口直接发送外部消息的入口。代码调查与业务执行交给执行体；写提示词与协调简报是它自己的工作。

工具限制必须由宿主机械执行：隔离继承工具、注册受控能力、执行 guard 与每回合自检。预设只是提示词，不能单独证明权限隔离。目标是无未授权执行能力，不固化为「恰好九个工具」。宿主工具可见性与可执行性均需实测，已知退化不能悄悄降标。

## 契约与依赖

```text
compileContext(desk, events, factRevision, audience) → context + sourceRefs
runTurn(trigger, context) → decisions + coordination proposals
rotate(desk, reason) → generation
selfCheck(desk, allowedCapabilities) → safe / blocked
```

依赖判断、托管协调、规则、记忆、世界模型和内核。后台协调回合与人类对话回合共享事实版本与隐私规则；组合根只负责触发和端口接线。

## 失败与验证

模型调非法工具时拒绝并记录，技术修复由系统承担；保留停止、只读查询和已运行执行体的观察能力。上下文不足先补读或交接，不将「案卷过长」变成老板整理材料的工作。

验证跨窗口纠正、旧决定不被重提、同名项目不混淆、事实更新即时进入回合、群资料隔离、冷恢复以及长任务中的讨论/停止。可扩展上下文段和桌子画像，不能让画像扩大工具权限。
