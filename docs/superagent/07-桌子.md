# 桌子：案卷、单一在场、会话生命周期

职责：把账本编译成一次判断所需的全部上下文（案卷），跑一个模型回合，保证"每次和它说话都像和同一个人说话"。

边界：不判断该不该做（判断模块的事），不发送任何消息（内核出口的事），不拥有真相（账本是真相；桌子会话是可丢弃的缓存）。

## 桌子不是什么

- 不是"一个常驻的聪明会话"。常驻会膨胀、会漂移、重启就断；一个会话只能服务一个对话。
- 不是真相。桌子换代、重启、上下文压缩都允许；丢了就从账本重建。
- 不是出口。桌子说完的话只是提案，经内核出口才成为一条消息。

## 案卷：六段，固定顺序，每段有上限

```
[案卷 桌:p2p:老板 第3代 2026-11-05 周三 12:05 本地]
在办(球权)    C-12 只看responder.spec列用例 | 球:执行体x:fast | 已3分/预计2分 | 下次看12:06
              C-9  盯 pc-tower 会话 s-88    | 球:我           | 下次看12:10 | 上次:10分钟0次工具调用
等老板        C-7  是否允许改 dsh-cove 主仓（问于 11-05 10:02，已等2小时）
老板说过      M-3 「dsh-cove 是公开仓库，别并发写」(11-04 21:50 原话)
              M-5 「生产变更必须逐目标授权」(配置)
判例(同类)    run-tests: 近6次 估3分 实7分(系数2.1) | x:fast 成功6/6
              watch-session: 近2次 均空跑后人工叫停
注意力        今日打断 1/3 | 静默 22:00-08:00 | 老板上次说话 12:04
本批          [#e19 老板 线程:p2p:oc_x:m17 引用:无] 你给他发消息，让他好好干活
```

| 段 | 来源 | 为什么必须有 |
| --- | --- | --- |
| 在办（球权） | 本桌可见且未结案的承诺 | 归位判断没有它只能猜；**永不截断** |
| 等老板 | 球在老板的承诺 | 老板说"批"时知道批的是哪件 |
| 老板说过 | 约束与偏好，带原话与日期，≤8 条 | "下一次不用重讲"只能靠这段；带原话才能引用 |
| 判例 | 工作类校准与最近同类结案 | 估时、选执行体、要不要先问，要有数可依 |
| 注意力 | 今日出站计数与配置 | 决定这句话现在说还是进简报 |
| 本批 | 待处置事件，带发送者、线程、引用；**进桌前按发送者切成子批**，一个回合只处置一个发送者 | 修"prompt 只拼文本不含发送者"（F21）与"批次混进多人"（F33） |

超预算时按"判例 → 老板说过 → 等老板"的顺序截断；在办永不截断。案卷作为本回合 user message 的头部，不进 system prompt：system prompt 的 section 必须静态或走注册变量（全仓门禁 `system-prompt-audit`），而案卷每次不同。

## 单一在场：同一份投影，按受众裁剪

问题：案卷按桌编译，每张桌子读到的"我"不一样，换个窗口就像换了个人。但它又不能把所有桌子编成一样：R7 要求私聊里的内容不出现在群桌。

解法：now 分两层，隐私与一致各管一层。

| 层 | 内容 | 作用域 | 一致性要求 |
| --- | --- | --- | --- |
| 公共核心 `pub(now)` | 在办承诺的公共字段（编号、一句话、球权、下次看，≤8 条）、最近 12 次判断的公共结论、未决问题、`authority=config` 或对所有人可用的约束、已知偏差 | 全局唯一 | 同一判断窗口内，所有桌子拿到同一个 `pub_hash` |
| 受众投影 `aud(now)` | 在公共核心之上叠加本受众 `canUse` 允许的条目；不可说的记忆只以派生提示出现（"回复要短"），不给原文 | 每个受众类一份 | 同受众类指纹唯一；不得比公共核心更宽 |

受众类 = 受众集合的等价类（老板私聊、老板在的群、无老板的群、外部）。指纹 = `hash(pub(now)) + hash(aud(now))`，写进 `deliberation.dossier_hash` 并记受众类。

机械保证（不靠提示词）：

- 宿主编译后写两个 hash；同一 5 分钟窗口内，`pub_hash` 对所有桌子唯一，`aud_hash` 对同一受众类唯一。
- 模型不能写 now：它只能改账本，now 由宿主从账本重新编译。这是"模型不能改自己的授权"的同一条纪律。
- now 的生成必须是纯函数且幂等：同样的账本状态与同样的受众必须得到同样的投影。
- 投影函数出错时降级为只含公共核心的案卷：宁可信息少，也不给两个互相矛盾的答案，也不把私聊内容带进群桌。

为什么不是"回到一个常驻会话"：同一个人靠的是叙事连续，不是会话连续。人也不是一直在线；每次开口前被重新告知"你是这个人、你在办这些事、刚刚发生了什么"，比一直开着同一个会话更稳。

"像同一个人"的验收因此拆成三条：同一受众类指纹一致；跨受众对同一件公共事实的回答一致；私聊原文在群桌案卷里零命中。

## 会话生命周期

- 懒创建：第一条消息到达时才建会话；没消息不占会话。
- 空闲驱逐：30 分钟无事件即可关闭会话（R1 读数）；再来消息冷恢复，状态全从账本重建，记忆不丢。
- 换代：桌子按事件数 4000 或跨日换代，换代零成本；`/new` 是同一机制的手动版。
- 一个回合：每桌同时至多一个回合（`turn_open`）；人消息优先于议程回合（议程在桌上有活人消息时顺延 60 秒，最多 5 次）。执行体在跑不阻塞桌子——这是 R19 的全双工，它本来就是两个会话。
- 挂载：作为 `host/services/superagent` 服务域的一部分（挂载点从 lark-inbox 换成 superagent，见 [内核](03-内核.md) 的通道并入）；`cordis.patch.yml` 保持恰好一行（F22）；上线需要用户重启服务（F23）。

## 工具面：机械约束，不是提示词

桌子会话必须满足 R2：没有写工具、没有执行工具，只有桌面工具（judge/commit/amend/release/pushback/look/remember/propose/say）。

做法（三件套，缺一不可）：

1. `restrict({ allow: [] })` 屏蔽全部继承来的工具（F9 证明空白名单合法；禁止名单会在缺工具的机器上抛错）。
2. 在本层 scoped 注册桌面工具（restrict 过滤不到本层注册，F10）。
3. `guard(exec => DESK_TOOLS.has(exec.name) ? undefined : 'desk-has-no-such-tool')` 兜底，任何 guard 不能推翻另一个 guard 的拒绝（F11）。

必须先做的 spike：本仓今天零处使用 restrict/guard/scoped 注册（F30），插件行只有 host ctx。要拿到 agent 级 ctx，得挂 agent 事件或 `createScope`。这是 R2 落地前唯一的未知，第 0 天第一件事。

## 契约

```
compileNow(ledger, audienceClass) → { pubHash, audHash, snapshot }   // 纯函数、幂等
compileDossier(desk, subBatch, now) → Dossier                        // 六段，带 token 上限
runTurn(trigger) → { deliberationId, ops, endReason }                 // 一桌一会话，turn_open 互斥
evictIdle(now) → DeskId[]                                            // 空闲 30 分钟
rotate(desk, reason: 'events' | 'day' | 'manual') → generation
```

## 依赖方向

依赖协议、内核（读账本）、规则（校准系数与判例）、记忆（可见域切片）、世界模型（本桌范围）、判断（注册工具）。被恢复与降级（对账时读会话状态）依赖。内核只把回合请求写成一行 deliberation，由组合根接到 `runTurn`；时机与措辞不依赖桌子。桌子不依赖执行体：执行体是另一个会话，桌子只通过账本看见它。

## 失败模式

| 失败 | 表现 | 处置 |
| --- | --- | --- |
| 案卷截断掉了在办 | 它开始问"你说的是哪件事" | 在办段永不截断；截断顺序固定，超限即告警 |
| 模型不合规 | 调未知工具、非法状态迁移 | guard 拒绝；错误进案卷下一轮；连续 2 次失败由宿主模板兜底 |
| 会话漂移 | 同一问题两桌答案不一致 | now 指纹断言；不一致降级单桌案卷并记一条 |
| 桌子空跑 | 回合 ops=0 占比高 | 台账读数；收紧议程信号、后推 next_look_at |
| 会话只增不减 | 会话数持续上涨 | 懒创建 + 空闲驱逐 + 换代；读数查无消息的会话数 |

## 读数

```sql
-- 同一窗口、同一受众类只有一个指纹（窗口内至少两张桌子才可证伪）
SELECT window_id, audience_class, count(DISTINCT dossier_hash) FROM deliberation
  WHERE started_at BETWEEN :a AND :b GROUP BY 1,2 HAVING count(DISTINCT dossier_hash) > 1;  -- 空
-- 公共核心跨受众一致
SELECT window_id, count(DISTINCT pub_hash) FROM deliberation
  WHERE started_at BETWEEN :a AND :b GROUP BY 1 HAVING count(DISTINCT pub_hash) > 1;        -- 空
-- 案卷大小分布与空跑率
SELECT round(avg(dossier_tokens)), round(avg(ops=0),2) FROM deliberation
  WHERE started_at > strftime('%s','now')*1000 - 86400000;
-- 在办永不截断：本桌在办超过 8 条应当是告警，不是截断
SELECT count(*) FROM desk d WHERE d.session_id IS NOT NULL
  AND (SELECT count(*) FROM commitment c WHERE c.desk_id=d.desk_id
       AND c.state IN ('proposed','open','at_risk')) > 8;                                    -- 0
-- 群桌案卷不含私聊原文：金丝雀 + 抽查（派生提示里不得出现原话片段）
SELECT count(*) FROM outbox o JOIN desk d USING(chat_id)
  WHERE d.chat_type='group' AND o.body LIKE '%CANARY-%';                                     -- 0
```

## 扩展点

- 案卷段：新增一段 = 加一个 `DossierSection` 提供者（读协议对象，返回 ≤N token），注册一行；不改桌子核心。段的顺序与上限是产品决定，写在配置里。
- 桌子画像：不同受众（私聊/群/同事）可以用不同的段组合与 token 上限，属于配置，不是新模块。
- 不做"桌子之间的直连"：R8 要求跨桌协调只经账本或人；加直连等于开第二条事实通道。
