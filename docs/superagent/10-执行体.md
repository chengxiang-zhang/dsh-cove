# 执行体：跨宿主 Agent 操作与结果回收

职责：让 Superagent 能定位、创建或接续 Agent，会话内追加与纠偏，观察、停止、回收成果并支持独立验证。目标设计。

边界：执行端只执行经授权且有权属的协调操作，不决定跨项目优先级、不自行宣布事项完成、不直接代表秘书对人发消息。

## 执行体、会话与分工

profile 描述引擎适用能力与 model_route（API provider/model/effort）、工具能力、宿主支持、专业适用范围、能力评估版本、已知限制与预算。一次会话可承接连续分工；一个事项可有多个专业分工，每项分工可有调查、设计、实施、评审、验证等尝试；专业角色与活动类别分开，绑定协议的 team_assignment。长期职责的寿命独立于会话。

引擎默认优先级为 Codex → DSH → Claude，协调运行时与专业执行均适用。前一引擎不满足该角色必需能力或资格时，才选择后一引擎并记录证据与原因；不能以降标换取可用。

选择基于真实能力、任务复杂度、上下文连续性和历史质量，不把临时等于弱模型、长期等于团队写成产品规则。Agent Team、原生会话、外部 harness 是适配器能力，不强制所有项目使用同一组织形态。

项目业务工作由专业执行体完成；Superagent 亲自编写交办和纠偏，并可核查受控原始证据。独立质量/专项复核使用与被审产物生成者分离的绑定和上下文，工具权限按角色限制，不能在同一实现会话换头衔自签验收。角色合并、交接和职责覆盖按 [专业团队协作](14-专业团队协作.md) 执行。执行体不得获得超出事项授权的能力，也不能用子 Agent 或直接对外发送绕过统一控制。

执行引擎经 ExecutorPort 接入，模型路由、传输及宿主分别配置；DSH 的 http/inproc 不是两个引擎。DSH、Codex、Claude Code 各自适配规范事实与请求，不能将 Codex 专有 RPC 写入协调核心。Worker、分工、绑定和尝试按 [领域协议](02-协议.md#领域模型与扩展) 区分；换引擎、复用 external-session 与能力差异遵循 [引擎替换契约](16-架构与扩展.md#agent-与宿主可替换性)。

## 端口与能力协商

```text
list / inspect(cursor, limits) → session facts + next cursor
create(assignment, identity, idemKey) → session identity + receipt
attach(session, expectedIdentity, controlGrant) → binding
sendInput(requestId, revision, payload) → accepted / consumed / unknown
inspectRequests(session, cursor) → native pending/resolved request facts / unknown
respondRequest(requestRef, response, expectedEpoch, idemKey) → receipt / unknown
steer(action, expectedEpoch) → receipt
cancel(action, expectedEpoch) → requested / confirmed / unknown
collect(assignmentRevision) → artifact references + execution evidence
```

每个适配器声明支持哪些操作、消费回执如何证明、反向请求的支持类型及有效性/解除如何核实、取消是否结束实际工具子进程、模型覆盖是否污染全局。端口是逻辑能力，不假定 provider 有同名 RPC；inspectRequests 可由原生事件与经验证的回读能力实现，无法证明完整性时返回 unknown。缺能力显式返回，不以 prompt 已接受冒充 consumed，不以 API 返回 200 冒充完成。

轮询增量与推送均按事件游标去重；发现缺口回读补齐，不能因热更丢 turn/end 就永远不回收。限制单次日志读取并保留展开入口。

## 目标端执行围栏

采用单一逻辑控制面管理职责账本、授权版本、会话控制 epoch 与规范资源锁；多个机器运行执行端。本阶段不设计跨机器 active-active 协调者。控制面故障转移必须读取同一持久账本并隔离旧写者，不能两个副本各自管理相同任务。

执行信封绑定任务、角色、实际主体、目标路径/外部资源、允许动作、目标/拆解版本引用、epoch、有效期和资源锁。目标端必须验证信封，并把限制施加到真实工具调用、子 Agent、凭据和子进程，而不只检查收到 prompt 的时刻。可采用目标端受控操作代理与操作系统沙箱/文件系统和网络隔离；具体实现留给适配器，但能力测试必须证明绕过提示词仍无法越界。

不能靠字符串扫描 shell 命令证明路径和网络隔离。若某宿主只能接受任意高权限 prompt 而无法强制委派边界，则不声明完整 delegated 写能力；已有会话仅可使用逐项已证明安全的读取或独立受控取消；assisted 不是绕过围栏的通路。只要 prompt/steer 可能触发未受限工具或子进程，就不得向该会话发送，哪怕提示词声称只读。写任务改派满足要求的已授权端。没有满足要求的端是待解决能力缺口，不静默降低验收。

共享 Git 整合目标按仓库身份与分支加锁，共享环境按环境资源 id 加锁，不能仅按本机路径锁定。短期执行租约在目标端续期；撤销/接管时撤掉工具许可并取消子进程，断连到期停止新增写入并保全现场。已经在途的外部副作用仍须对账确认，不声称可瞬间撤回。只有确认旧执行停止或被目标端隔离，才允许新写者接管。

### 验证执行隔离

候选代码、构建插件、测试初始化代码及其子进程属于不可信被测对象，不能继承质量角色准备验证资产的写权限。质量角色先生成并独立审定测试、判据和必要样本，封存版本后再执行候选；需修订资产时建立新验证上下文，不能运行中悄悄改判据。候选仅可写获准的临时产物区，不能写封存判据、保留样本、采证组件、已收集证据或获取采证身份凭据；子进程、挂载、网络及可复用缓存也必须保持该边界。

采证端位于候选无法修改的信任域，绑定实际执行身份、候选与验证资产版本，持久保存原始观察及完整性检查。只读测试文件仍不能证明同进程判定可信：被测代码可改变测试框架内存或拦截结果。同进程单测可作为证据，但不能单独证明候选未污染判定；放行所需关键结论须有候选进程外的独立观察或经验证的隔离判定路径。无法提供这条路径时明确限制可证明范围，由秘书补验证能力，不把退出 0 当成可信判定。

发现越界、资产失配或采证不完整时保留原始事实，将受影响验收置 inconclusive 并创建审查问题；未消除前不得交付。完整性正常也只证明取证可信，不证明业务正确，仍需逐项验收。角色名称、独立会话或独立目录不能代替上述隔离；端口须用污染验证资产与伪造结果的负控证明该能力。

当前离线 JSON 方法由 `createVerificationService` 提供宿主组合接口，未直接挂为模型工具。独立准备进程封存输入和期望，受控 collect Action 启动独立 collector，再由 collector 在 macOS 单层 Seatbelt 内运行候选模块的同步或异步导出函数；数据经有界管道返回并在候选进程外比较。方法禁止候选联网、fork、读取采证资产或写候选快照，原始 stdout/stderr 超限、退出或帧缺失、资产失配均不能通过。资格撤回立即影响当前适用性和 Action 围栏，历史 evaluation 保留，关联交付通过持久分页影响记录复查。普通事项进度变更不修改验收绑定的语义版本。

审查复验上下文须显式绑定问题的准确版本、解除条件和 resolve/dismiss 用途，并包含原复现的输入与期望摘要。封存、执行、评估和关闭均检查该绑定及原执行入口、导出、环境和运行时身份；旧证据重新评估、无关样例或替换 API 不能解除问题。修复复验允许更换候选内容；误报撤销要求同内容、同 API 和另一独立审查者的实际复验。关闭问题保留原失败，且不使本次有效复验因问题状态推进而失效。此固定比较方法不支持以修改 expected 代替误派生判据的专业裁决；判据纠正须另有原意映射、版本失效与重新验收。

该方法仅验证已封存、至多 32 MiB/10000 个普通文件的离线候选切片；快照准备依赖本机 `/usr/bin/python3` 的目录描述符遍历，执行依赖已验证的 Darwin sandbox-exec。它不提供全仓依赖安装、构建、网络 fixture 或完整项目门禁资格。完整门禁仍需合格的外部隔离后端，不能裸跑候选、跳过必测项或开放全部 loopback 端口补齐。任意 JSON 报告不能创建验收事实；资格授予与独立角色身份由可信宿主组合确认，专业语义覆盖和实际 Agent 轨迹仍需独立证明。

## 接续已有会话

核对 host/engine_id/runtime_namespace/session_id、目录、原目标、已有指令、当前产物、工具能力和控制者。已有会话先只读观察，获得明确作用域的控制授权后才转 assisted/delegated。无法确定目标就不发送指令。

已有提示词与仓库规则需要纳入交接；不能通过重建会话消除不方便的约束。接管时记录基线与控制 epoch；确认人工重新操作或明确 takeover 后暂停自主写入并等待归还控制，来源未明的取消按协议调查归因。

创建撞 id 时读取既有会话核验创建意图与幂等身份。仅目录相同或宿主不报目录不足以证明是本次尝试；不能 cancel 一个未知既有会话来抢 id。

## 交办与输入

保存交办版本、目标与验收合同引用、提示词引用、材料可见性、期望检查点和执行端能力。先持久化意图，再派发；受理只表示承担责任，不虚称已经启动。

输入 request_id 去重并跟踪 accepted/consumed，正证据按协议的宿主输入记录与回合绑定契约。回合结束时仍有新增需求未消费或当前版本未知，不能按旧报告进入最终验收。换执行体须携带成果、未消费输入、已失败方法与控制边界。

远端报告 blocked 是诊断材料，技术问题交系统处理；报告 ready 是回收入口。收集工具调用及产物来源，验证报告里的命令是否真实发生，但命令真实也不等于结果满足需求。

## 进展、预算与停止

记录时间、回合、工具活动、产物版本、测试变化、待答请求和外部等待。工具次数与重复签名是观察信号；不能直接「三次编辑同文件即打转」。有效原生请求等待不能当作空跑，但须由秘书接答或跟进。语义诊断由判断与托管协调负责。

单次尝试可设墙钟与回合预算，到线采取保全、取消或有证据的续期；不得自动将整个事项 broken 或让老板选模型。token 用量只记账，不作为用户已排除的费用止损理由。

cancel 先持久化停止意图并撤销旧控制 epoch，再发送并核验工具/子进程实际停止。断连时状态 unknown，资源锁保留；不能在旧执行体可能仍写入时创建替代写者。

外部取消保留 `cancel_origin=external`，先撤销控制并进入 [权属待核实的暂停](02-协议.md#长期职责与事项)，适配器提供原生事件和可信归因材料，不自行宣布人类已接管或已归还。核实为非人工故障后的自主恢复、已确认人工控制及来源未知分开处理，不自动重派。只取消登记且有控制权的执行体，不扫描并终止所有账本外会话。

## 执行端 transport 与现有接入信息

保留 `executors/transport/` 的 http/inproc 分层：

| transport | 目标与观察 | 限制 |
| --- | --- | --- |
| http | 目标 web 宿主 `/api`，本机 loopback 或已授权 peer；会话在目标 GUI 可见 | 远程访问与业务授权分别校验 |
| inproc | 本进程 sessionController，直接 inspect 与事件订阅 | 不能承担远端目标，必须显式拒绝 |

既有 HTTP 接入涉及 session/create、session/selectModel、session/prompt、session/cancel；推送经 `/api/remote.mux` 的 session/follow，轮询经 session/projections 与 session/page。它们是现有接入信息，实施本目标设计前必须逐宿主验证版本及副作用，尤其不能污染全局默认模型。

现有接入对缺少 superagent-executor 预设会记录 presetDegraded 并尝试 standard，对缺 report 工具会解析末条围栏 JSON。目标验收不能把这类报告回退当权限或证据等价：必须确认工具隔离、必需能力和真实工具日志仍成立；不成立则明确能力缺口，不继续伪装完整托管。

网络免凭据路径不免除 Host、会话与 accessTrustOf 围栏。不得修改或重启运行中的 DSH 来让本轮文档验证通过。

### Codex App Server 适配

目标适配器复用 Codex App Server，并纳入同一执行端能力协商和控制租约。首次派发持久化原生 `threadId` 及恢复所需的宿主、Codex home、工作区和权限配置引用；账本的 worker id 与 `turnId` 不能代替原生线程身份。重连时用 `thread/resume` 恢复并核对返回的 thread ID。空闲线程在原 ID 上用 `turn/start` 发补充，活跃回合用带 `expectedTurnId` 的 `turn/steer` 或按能力排队。回合已经结束时重新读取事实后向同一线程交付，不能通过新建线程补偿竞争或恢复错误。

适配器必须为 [协议要求的消费证据](02-协议.md#分工与执行尝试) 提供可复核的原生输入与回合对应记录，成功投递的 RPC 回执本身不算消费。消费证据、取消实际子进程、真实工具围栏及跨重启恢复都须在目标宿主验证后才声明能力。单独的 App Server 或 broker 原型证明协议路径可行，不能代替本仓接入证据。

App Server 是双向协议。适配器须处理版本支持的 `item/tool/requestUserInput`、命令/文件/权限审批和 `mcpServer/elicitation/request` 等 server request，并将原生 request id、thread/turn/item 和连接代次映射到 [反向请求契约](02-协议.md#执行端反向请求)。按原生响应格式答复原请求，不能用 `turn/start` 或 `turn/steer` 文本冒充协议应答。启用动态工具时，其调用也须有注册的受控处理器；无法处理的请求类型显式拒绝或按协议解除，不静默悬挂。具体类型与响应格式以部署版本生成的 schema 及 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server) 为准，不宣称所有版本能力一致。

原生 `serverRequest/resolved` 可表示已作答或请求被清除；保留原因和证据，不当作工具执行成功。重连先补读请求与回合事实：仍有效的原请求按当前权限处理，已失效的请求保留未解决内容并在同一线程重新衔接。若无法核实待答状态，由协调者安排诊断；确需中断时先受控取消并确认实际停止，再在原线程续交问题/上下文，使需要审批的动作重新产生有效请求。不能复制旧审批响应到新请求、清空请求后假称已回答，或为恢复另建线程。

能力验收必须覆盖秘书自动答复技术问题、授权内审批、真实授权缺口的用户裁定、断线期间请求被清除/被他端回答、响应回执丢失和审批目标变化。需要本人登录或原生机制明确要求本人操作时，秘书提供具体入口与影响并跟进，其余工作继续；不得冒充本人完成。这些交互能力与消费证明、执行围栏一起决定是否可承担全自动托管角色。

### 受控原生端接线与限制

macOS 原生引擎的外层沙箱为模型传输开放系统信任服务 `com.apple.trustd` 与用户信任服务 `com.apple.trustd.agent` 的 Mach lookup，使交互式用户进程和 LaunchDaemon 宿主均能执行系统证书验证。这两项许可仅属于已有原生运行时；普通文件或校验执行不获得该许可或模型网络权限。引擎继承最小环境并使用独立认证状态，不关闭 TLS 验证，也不继承宿主代理、密钥或日志指令。

本包的 `executors/engines` 提供 Codex 原生 App Server 和 DSH 原生会话适配器；Claude Code 适配端明确拒绝尚未获得写入资格的任务。受控原生端与现有 transport 的能力分别登记，协调者通过端口选择合格实例，不能把旧连接层的 HTTP/inproc 可达性当作原生执行资格。Codex 协调运行时只返回经宿主校验的结构化 proposals，业务工具为空。

DSH 的可选宿主配置为 `nativeExecutors: { bootstrapFile }`，由单个 `web-all` 根装配读取私有 bootstrap。文件声明 ledgerPath、sourceRef、nodeExecutable、runtimeNamespace，以及 sessionId、launchRef、role 绑定；不能授予组或其他用户写权限。worker 的真实 SDK 工具限定为 read/write/check/ask，coordinator 不获业务工具。所有工具请求先记录原生待答事实，外部 broker 经独立 P2 helper 执行并逐 Action 应答；引擎的模型网络和认证状态不传入 helper，模型代码不在宿主求值。

同一候选目录的固定文件 helper 使用有界串行队列和账本原子子租约；借用会话 owner 锁不会取消 helper 之间的互斥。未知停止结果保留子租约，重复原生请求不能自动重做写入。队列、RPC 待答数、stdio 帧及 HTTP 响应均有界；超过边界保留拒绝或未知事实，不补写成功回执。

DSH restrict/guard 归属于原生 Agent 生命周期。web-all 退役时保留拒绝状态的 guard，卸下工具定义，取消并等待原有回调结束后关闭账本；热更新不会自动获得活跃模型迁移资格。新 handler 接管前须按插件生命周期建立安全点或停止、隔离旧模型。DSH 的 children 取消回执不能证明脱离进程组的后代停止，因此保留 unknown 和旧写域锁；继续执行依赖独立候选隔离与封存证明。普通 native RPC response 只确认该操作返回，不证明输入已消费、工具完成、引擎停止或事项兑现。

## 整合、交付与工作区创建

provision 由受控端口完成 [项目接入或初始化阶段](04-世界模型.md)，其中工作区创建由带目标路径授权的宿主端口承担。integrate 为指定产物版本安排受限整合角色；deliver 仅执行合同内的明确阶段（本地提交、推送、合并、发布或部署），每一阶段单独验证授权；发布须满足 [发布授权协议](02-协议.md#发布授权)。执行角色与交付端口都返回 Action 回执和可独立读取的成果引用，不以报告 ready 直接确认。

prepare_preview 在 verifying 阶段安排候选环境准备，返回实际产物/环境版本、访问范围和可用证据；与正式 deliver 分开。复用的创建、整合、部署步骤仍逐步记 Action 和回执，适用 [候选体验契约](02-协议.md#候选体验与用户验收)。预览覆盖同样获取环境资源锁；保留与清理由既有授权和保留策略决定，不能为供人体验绕过公开暴露或生产变更边界。

当前项目的提交分支与门禁按仓库规则；需要真实环境验证或重启时遵循该环境现有约束。默认交付阶段来自职责画像或具体委托，不因为 Agent 能调用发布工具就扩展阶段。部分成功和追加需求的语义统一归协议的 delivery_step，不在 provider 适配器内自行补偿。

## 工作区与成果

保留项目原有改动，按项目规则隔离写域与整合。目录、分支和产物记录所有权、当前使用者、事项与保留策略。连续两次扫描无人认领不构成删除授权；未验证成果、人类已有目录及不确定远端写者都不能自动清理。

经明确授权的临时空间可按保留策略回收；其余先生成可审阅清理记录，优先采用可恢复形态。

## 依赖、扩展与验证

依赖协议、内核与世界模型；托管协调调用本模块。新增 provider/宿主适配器需验证身份命名空间、模型隔离、输入消费、断线补读、取消和产物回收；不只验证「能创建会话」。

错误分为权限、目标身份、能力缺口、临时不可达、控制权丢失与操作结果未知。保留原始原因供诊断；无论尝试是否结束，事项责任由托管协调继续管理。
