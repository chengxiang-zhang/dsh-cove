# 执行体：派出去的手

职责：把一件承诺交给一个能干活、能被打断、能重派的会话，管它的预算、证据、结案与升级。

边界：不判断该不该做（判断的事），不直接对人说话（它只会 report），不拥有真相（账本才是）。执行体是消耗品：坏了就换，换掉不影响承诺。

## 画像：一类执行体，不是一次会话

```
profile { id, provider, model, effort, cost_tier, lifetime, tools, budget_tier }
```

| 维度 | 取值 | 含义 |
| --- | --- | --- |
| lifetime | oneshot / durable | 一次性（新会话、只读、10 分钟上限）或长期（独立工作目录、可追加输入、可换执行体重派） |
| tools | read / full | 只读（观察、查询）或全工具（改代码、跑命令） |
| cost_tier | 1–3 | 由判断的"选谁"规则消费；校准会改偏好 |

执行体用 `standard` 预设，cwd 为本次尝试的目录。宿主 scoped 注册 `report` 工具；`guard` 拒绝 lark-inbox 工具、worktree 工具与带预设的 subagent 调用；oneshot 只读执行体另拒一切写工具。

为什么用会话而不是 subagent 派活：要独立工作目录、要能重派、要能换档；subagent 是 one-shot 且没有目录生命周期（F6）。注意这是当前依赖面（0.2.0-rc.2 无 subagent 包）的结论；运行时 0.2.1 的 subagent 已有 interrupt（F5），升级 cohort 后这条论证要重写，不是永久结论。

## 尝试：先受理，再派发（三段）

问题（FMEA-3）：先说"已派出"，再建会话；建失败时老板已经看到"接了"，后续消息又被"线程上有活承诺"挡住，卡死。另一个方向也错：把受理压到会话建好之后，30 秒受理会被建会话的尾巴拖死。

三段：

1. `commit` 在一个事务里写承诺（state=open）+ 尝试（state=pending），**同回合立即 `say(ack)`**："接了，预计 N 分钟"。这句只承诺"我接了"，不承诺"已派出"。
2. 派发异步进行：建会话 + 第一次 `prompt(queue)` → 尝试转 `running`。
3. 派发失败 → 尝试标 `failed(cancel_origin=dispatch)` → 宿主发一条终止句"没派出去，原因 X" → 按升级规则换档重试一次；仍失败就进升级第三档（问老板一个问题）。

这样七步链第 1 步与第 5 步都不依赖派发速度：受理在 30 秒内必然发出；说停走即时路径，取消 pending 或 running 的尝试都算真停。

20 秒内没有 ack 只有一个原因：桌子回合本身慢。那时先打一个已读表情（现有能力，不是一条消息），并在 60 秒内由宿主模板兜一句"收到，正在判断"。

## 预算

宿主算，秘书只能申请放大（≤4 倍，须写理由）：

- 墙钟 = clamp(预计 × 校准系数 × 2.5, 5, 120) 分钟。
- 回合 = 本类 p90 × 1.5；样本不足时 12。
- token = 本类 p90 × 1.5；样本不足时 200 万。

80% 报一次并说明还剩多少；100% 自动取消，承诺转 `at_risk`，打断老板："到线了，做到 X，1 再给 N 分钟 / 2 停"（G4）。

## 结案：不信自述

执行体回合结束（`turn/end`）到达时，有未消费的输入（journal 里 request_id 未被吃）→ 不判定，留给下一回合。否则按结束原因与完成判据：

| 条件 | 结果 |
| --- | --- |
| completed + ready + command 判据，且某条证据能在会话事件里找到同命令、同退出码的工具调用 | fulfilled |
| completed + ready + artifact 判据，且宿主能读到该路径或分支有提交 | fulfilled |
| completed + ready + answer/observation 判据，且摘要覆盖 done_when 列出的要素 | fulfilled |
| completed + ready 但核对不过，或无终态报告 | unverified（交付前缀由宿主强制写"做完了，但没验证"） |
| completed + blocked | 问题转成 asked 假设，球回老板 |
| completed + failed/dropped，或 interrupted/error/max-tokens/未知 | 升级 |
| 我方 aborted | 释放 → released；预算或期限触发 → at_risk 并问 |

未知的结束原因一律当失败（协议 P4 同规则）。今天的 `reply_jobs` 状态机把"结案"分成 replying 与 replied 两步（F18），执行体这边同理：回合结束不等于交付成功。

第三个分支：执行体用 `report(ready)` 提前交了报告，但回合还没结束（或热更丢了 `turn/end`）。宿主记一条"待结案"，等 `turn/end` 或超时后按同一张表判，并把等待原因写进 journal。既不能把 report 当提交成功，也不能因为缺 `turn/end` 就判失败——那是"不知道该信谁"时唯一不撒谎的落点。

## 升级：三选一，按序

1. 同执行体重派：原因是 interrupted/error/停滞，且尝试数 < 2。
2. 高一档执行体：超 token、自报失败，或已经重派过一次。
3. 问老板一个问题：尝试数 = 3，或没有更高档。

每次升级写 journal 与尝试的 `executor_switched`；找人时只问一个具体问题（R13）。

## 工作目录

durable 才有独立目录与分支；oneshot 用临时目录、不保留。释放时返回 `kept` 或 `removed`，并在回执里写"已产生的改动怎么处理"（G2）。

泄漏是已知缺口：没有定时清扫者（历史评审点过）。补法是恢复模块的每日清扫：列出无人认领的目录与分支，dry-run 报告，连续两次报告一致才删。

## 观察器

watch 承诺需要探针。探针是只读执行体的一种特例：oneshot + read 工具 + 固定墙钟 5 分钟，只允许调用 inspect 类只读接口，产出结构化读数（事件计数、最近工具调用名、最后文本的相似度）。

探针不写代码、不改状态；读不到就记一次失败，连续 3 次进简报，承诺转 broken，不无限重试。

## 契约

```
dispatch(commitmentId, profileId, budget) → { attemptId, sessionId }   // 两阶段：pending → running
sendInput(attemptId, requestId, text) → { consumedTurn? }              // 追加输入，等执行体消费
cancel(attemptId, origin) → void                                      // release|budget|deadline|stall|loop|reconcile
close(attemptId, turnEnd, report) → { state, evidenceOk }             // 结案判定
escalate(commitmentId, reason) → { action: 'retry'|'upgrade'|'ask', attemptId? }
sweep(now) → SweepReport                                              // 每日目录/分支清扫
```

## 依赖方向

依赖协议、内核（写尝试与 journal）、世界模型（落点与授权）。被判断（派活）、桌子（不依赖它，只从账本看它）、恢复与降级（对账与清扫）依赖。执行体不依赖桌子与时机：它不知道谁在跟老板说话。

## 失败模式

| 失败 | 表现 | 处置 |
| --- | --- | --- |
| 派不出去 | 说了"接了"但会话没起来 | 三段：受理句只说"接了"不说"已派出"；派发失败发终止句并换档重试一次 |
| 假完成 | 报 ready 但没做 | 结案核对证据与会话事件；核对不过只能标未验证 |
| 无主算力 | 有会话在跑但没有账本行 | I3 读数；不在账本里的会话一律取消 |
| 目录泄漏 | 磁盘涨、分支多 | 每日清扫 dry-run，两次一致才删 |
| 卡死 | 长时间零工具调用 | 议程信号（停滞两窗口）→ 取消并升级 |
| 预算跑飞 | 一件活烧掉一天预算 | 80/100 两个闸；100% 自动停 |
| 档位选错 | 简单活派强模型 | 失败率与换档率进校准，改偏好 |

## 读数

```sql
SELECT state, count(*) FROM attempt GROUP BY 1;
SELECT count(*) FROM attempt a JOIN commitment c USING(commitment_id)
  WHERE a.state='running' AND c.state NOT IN ('open','at_risk');              -- 0
SELECT round(avg(executor_switched),2), count(*) FROM commitment WHERE closed_at IS NOT NULL;
SELECT count(*) FROM commitment WHERE state='fulfilled' AND evidence_json IS NULL;  -- 0
SELECT count(*) FROM attempt WHERE state='running'
  AND last_tool_at < strftime('%s','now')*1000 - 600000;                       -- 0
SELECT count(*) FROM attempt WHERE cancel_origin='reconcile';                  -- 孤儿对账次数
```

## 扩展点

- 新执行体画像：`executors/profiles/<name>.ts` + 一行注册；只声明 provider/model/effort/工具面/预算档，不改调度逻辑。
- 新观察器：`executors/probes/<name>.ts` 实现 `probe(target) → Reading[]`；只读，不能改账本。
- 不允许执行体自己决定结案：结案判定在内核与宿主，执行体只能 report。这是"不信自述"的机械形态。
