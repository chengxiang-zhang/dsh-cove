## 18 实体注册：范围、机器与归属（作用域的实现）

> 本节是 §17 规则引擎的**作用域实现**：规则挂在路径上，路径由这里的实体拼出来。原写于 2026-11-05 16:35，上一版把这个问题答成了"注册表怎么建"——三张表、字段、消歧打分，那是数据模型。老板指出「我提的问题是一个架构问题」，重写如下：**范围如何抽象、机器如何加入、名字在哪一步定、活落在哪里**。四者决定系统边界与信任结构，不是一张表能表达的。

### 18.1 核心抽象：范围是路径，不是白名单

今天的做法是白名单（`superagent.repos: [...]`）——它只回答"能不能"，回答不了"在哪、归谁、能不能继承"。这三件事在接口、授权、可见性上要同时成立，所以范围必须是**有层次的路径**：

```
local/                                  本机
local/~/code/dsh-web                    本机上的一个仓库
netbird/dsh-pc-tower                    一台 NetBird 机器
netbird/dsh-pc-tower/~/code/dsh-web     那台机器上的一个仓库
netbird/dsh-pc-tower/session/sa-wk-...  那台机器上的一次会话
external/github.com/chengxiang-zhang    外部组织
```

路径上**挂三样东西，形状相同、语义不同**：

| 挂什么 | 回答 | 继承规则 |
|---|---|---|
| 能力声明 capability | 这里能做什么（有没有 docker、能不能起 DSH） | 向下可细化，向上只做聚合（父说"能跑 node"，不代表子能跑 docker） |
| 授权 mandate | 我能不能在这里写 | **严格向下继承**：给了 `netbird/host-a` 的读，其下所有路径可读；要写必须显式给到路径级 |
| 可见性 visibility | 哪些记忆能在这里被引用 | 与范围正交（§7），但同样用路径前缀表达 |

**为什么是路径而不是表**：路径是唯一天然支持"继承 + 最小授权 + 可审计"的形状。文件系统、K8s RBAC、OAuth scope 都用它，不是巧合。它让"这台机器整台可读、但只有这一个仓库可写"成为一句话，而不是两条互不相干的规则。

**这条改动的代价**：所有现有的 `superagent.repos` 白名单要迁移成路径；`sa_mandates.scope_json` 现在是自由 JSON，要收成"路径 + 能力"的规范形式。

### 18.2 注册 = 加入范围，三条通路、三个信任级别

| 通路 | 谁发起 | 信任级别 | 典型场景 | 生效方式 |
|---|---|---|---|---|
| `config` | 人写配置 | 最高（人担保） | 最开始那几台 | 直接 `enrolled` |
| `enroll` | 机器自注册，带一次性令牌 | 中（令牌担保） | 给新机器装 DSH | 令牌有效即 `enrolled` |
| `discover` | 控制面扫描到并**提议** | 最低 | NetBird 里出现未知 peer | **只能进 `proposed`，要老板一句话确认** |

**架构上最重要的一条：`discover` 不能自己生效。**

如果扫描能自动扩大范围，那么"我能动哪些机器"就由网络拓扑决定，而不是由你决定——**别人把一台机器接进 NetBird，你的权限边界就自动扩大了**。这在安全上是反向的，也是"我到底被允许做什么"这个问题的唯一可信来源被稀释的起点。

所以三态是硬的：`proposed`（看见但不算数）→ `enrolled`（算数）→ `revoked`（吊销，立即从所有判定里消失）。

### 18.3 注册的产物是能力声明，不是字段堆

一台机器注册时要回答三件事，**由它自己跑出来上报**，不是控制面去猜：

1. **我在哪、怎么连**：多个地址 + 优先级（LAN / wifi / NetBird / DNS）。
2. **我能做什么**：`os/arch`、有没有 `dsh` / `docker` / `node` / `git`、能承载哪类执行体、CPU 与磁盘档位。
3. **我上面有什么**：工作区、仓库、常驻服务清单及其路径。

为什么自报而不是扫描：扫描得到的是"我看到什么"，自报得到的是"**它以为的自己**"。两者都要，但**判断该派给谁时用自报**（它知道自己的盘快满了），冲突时以扫描为准并记一条 `manifest_drift`。

安全边界：manifest 只是**声明**。任何写操作仍然要拿 `sa_mandates`——"我说我能写"和"你允许我写"是两件事，这条不变。

### 18.4 名字在注册时定，消歧前移

上一版把消歧放在查询时（打分排序）。**架构上这是错的**：名字应该在加入的那一刻就定清楚，而不是每次让人猜。

- 注册时**强制填 `canonical`**（人可读、唯一：`dsh-pc-tower`、`dl-dev`、`imac`）。
- 同时**要求登记所有已知称呼**：IP、SSH 别名、DNS 名、口语说法。
- `enroll` 通路的一次性令牌**由人生成**——生成令牌的人有义务给它起名。这一步把"命名责任"放回了唯一知道它是什么的人手里。
- 消歧只在"老板用了没登记过的说法"时才发生；结果**写回别名表**，不临时猜。

于是"那个机器"的歧义从"每次都要猜"变成"注册时就已经唯一"。这也解释了今天 SSH 配置里的问题：27 条别名对应 25 个 host，同一台机器的四个入口是平的——因为注册（写 ssh 配置）时没人要求它归并。

### 18.5 归属（placement）：活落在哪，是独立的一层

不是判定树，是**三步定位**，每步有不同的决定者：

| 步 | 决定 | 谁定 | 依据 |
|---|---|---|---|
| 1 域 | 本机 / 某台 netbird 机器 / 外部 | 模型提议 + 宿主校验 | 产物给谁用、要不要长期在线、数据在哪 |
| 2 宿主 | 哪台机器 | 宿主（机械筛选） | 能力声明（有没有 docker、盘够不够）+ 可达性 + 现有授权 |
| 3 落点 | 复用已有 worktree / 新建 workspace / 纯 scratch | 模型提议 + 宿主校验 | 产物类型；目录里有没有 `.git` |

第 3 步的"新建"是**一次 provision**：它要在目标主机上执行动作，所以要持有该**路径上的 `write_repo`**，并记录是谁批准的。
没有这条，"新建工作区"就会变成没人认领的副作用——和临时目录的区别只是它恰好留下来了。

### 18.6 失效与吊销：注册有租约

- `enroll` 的实体带 `lease_until`（默认 7 天），心跳续租；过期转 `stale`，30 天后 `gone`（**保留记录**，只是不参与判定）。
- `config` 的实体**不自动过期**：人担保的东西不该被自动删。
- `revoke` 立刻生效：从所有 scope 判定里移除，相关 mandate 同时失效。吊销**不需要理由**，但要留记录。
- **永不硬删除**：机器下线不等于它不存在。删了之后你问起它，秘书会说"没这东西"，比不知道更糟。

### 18.7 落地：上一版三张表是对的，但只是实现

`sa_world`（实体，含 `state ∈ proposed/enrolled/stale/gone/revoked`）、`sa_world_alias`（称呼）、`sa_world_addr`（入口）三张表仍然要——它们承载上面这套架构的**实现**，不是架构本身。scope 路径由 `(realm, host, path)` 拼出，`sa_mandates` 与可见性判定都用它做前缀匹配。

### 18.8 三个必须能答的问题（也是验收）

1. **新机器接进 NetBird，它会不会自动认为可以动它？** → 不会，停在 `proposed`，要你确认。读数：`SELECT count(*) FROM sa_world WHERE state='enrolled' AND source='discover'` 应为 0（discover 永远不能自己进 enrolled）。
2. **你说"那台 mac"，它会不会问？** → 只在三种情况问：说法没登记过、两个候选分差 < 30、或那个实体不在任何已授权范围里。读数：歧义率 < 15%。
3. **一个需求新建了工作区，谁批的？** → `sa_mandates` 里能查到 `scope_json` 带 `new:` 的那条，含批准人。读数：存在工作区目录但没有对应 mandate 的数量 = 0。

### 18.9 进哪一期

| 内容 | 期 |
|---|---|
| `local` 范围 + `config` 通路 + 能力声明（本机） | P0 |
| 名字在注册时定（本机实体的 canonical + 别名） | P0 |
| `netbird` 范围 + `enroll` 通路（一次性令牌）+ `discover` 只进 proposed | P1 |
| 租约、心跳、`revoke` | P2 |
| 跨机 placement（第 2 步选机器） | P1（与 netbird 同批） |
