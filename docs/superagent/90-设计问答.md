# 八个问题逐条回答、否定了哪些假设

> **本文属于《秘书式 super-agent 设计文档体系》**，覆盖全局 §12、§15。索引与权威顺序见 `README.md`。
> 为什么长成现在这样：它当初被问的八个问题，以及它推翻了什么。

## 12 八个问题逐条回答

**Q1 推动它的是消息还是目标？** 都不是：是账上承诺的时钟。消息、执行体汇报、时钟到点是三种改账事件；目标是 `kind='goal'` 的承诺，它的时钟是每周一次。消息进来前它脑子里跑着的是案卷六段（§3.1）：在办与球权、等老板的、老板说过的、判例与校准、今日注意力余额。

**Q2 工作对象要携带什么？四字段够吗？** 不够。承诺携带：债务人/债权人/代谁出面/球权（谁对谁负责、现在等谁）；意图与可检查的完成判据（不是动作描述）；悬念及其处置（声明还是问）；边界（宿主自动并入老板说过的约束）；时间三元组（due/eta/next_look）；预测与结果（校准原料）。多出来的部分里，前情和约束**不存进承诺**，由宿主在每次判断时从 journal 与 memory 现编（所以不会过期）；悬念存 `sa_assumptions`，在被确认、推翻或承诺结案时失效；ETA 在每次议程看时可被宿主重算。维护者：秘书写意图与悬念，宿主写时间、边界、预测系数，执行体只写汇报。

**Q3 记忆存什么？** 五种同事式记忆：约束、偏好、判例（上次为什么这么定）、人、常设安排，每条带原话出处与权威等级（§7）。不混乱靠"同话题同类至多一条 active"；不冲突靠权威序与 supersede 链；不越权靠"用与说分离"：能用于判断不等于能说出，说出时要求全部受众都在可说集合里，加字面比对兜底。

**Q4 它怎么知道自己不可靠？** 每次判断写成预测，结案回填结果，每日一次 join 写回 `sa_classes`（§8）：估时系数机械乘进受理时间，执行体偏好改候选首位，误判率高的类改成先问，异议常被推翻的类停止异议。信号以宿主可观测项为主（假设被推翻、受理后速撤、实际耗时），秘书自评只占小头。改动进简报让老板看见。

**Q5 注意力怎么分配？** 四档（§9）：reply 是他刚问的；interrupt 每天 3 次额度，只给"球在你手里且钟在走"、不可逆风险、空跑；brief 每天一条 ≤100 词编号清单；silent 是一切进度与自动恢复成功的事，永不出现。档由宿主规则定，模型改不了。

**Q6 72 小时后什么必须成立？** I1–I5（§10.1）：不遗忘任何承诺、一问一处置一答、没有无主算力、一个声音、账本即真相。靠 60 秒议程扫描、启动对账、租约心跳、会话可随时换代、简报兼作心跳。

**Q7 三个月里逐月发生了什么？** 代码按 Roadmap 在第 6 周前全部上线（§13）；三个月的成长不来自新代码，来自账本里攒下的数据把参数推过阈值。每个月可以数出来：

| 月 | 它多了什么 | 为什么这个月才有 | 读数 |
|---|---|---|---|
| 第 1 月：接得住 | 七步链全过；受理带假设；"顺便""停""重启"都对；盯别的机器的会话；每日简报 | 这些只依赖机制，第一天就完整 | 七步链 check 退出码 0；每件承诺的老板参与次数（受理后到结案间老板的消息数）基线 |
| 第 2 月：看得准 | 估时系数生效（受理里的"预计"开始准）；执行体偏好生效（少一次重派）；某几类自动转为"先问"或转回"声明"；判例让"上次怎么定的"被引用；第一次异议被老板接受 | 一类要 ≥5 个结案样本才校准；19 条/天里动手类约 3–5 件，常见类第 3–4 周攒够〔推断〕 | ETA 误差中位数（`|actual-eta|/actual`）从第 1 月值下降；首执行体成功率上升；`overturn_rate` 下降 |
| 第 3 月：替你挡 | 第一批 `(类, 能力)` 升 `auto`：盯会话时自己发具体指令、按目标提的方案经一次确认就自动派；同事进来后，它替老板接活、拒活、两个回执、不替老板许诺；老板对别人的承诺被它提醒 | 自动度要连续 5 次原样批准且跨 ≥2 天；同事与群在 P3 上线 | 每周 `route/ask` 处置数下降；`draft` 占比下降；承诺中"老板零参与结案"比例 |

三个月后老板说"它确实像个秘书"，可检验的意思是：**同一类事他只交代过一次，它估时准，它敢说"这个不值得"且多数时候说对，它替他挡掉了别人的活而没替他许诺**。

**Q8 复杂度砍到三分之一，砍哪三分之二？** 保留 4 张表加 1 张单行租约（12 → 4+1）：`sa_intake`（处置 + 预测列）、`sa_commitments`（把 attempt 与单条问题假设内联成列）、`sa_journal`（输入、汇报、证据、看）、`sa_outbox`（唯一出口）、`sa_lease`。桌子映射复用现有 `conv_bindings`〔已证实：`reply-store.ts:224-233` 已有 conv_key → session_id〕。工具 9 → 5：`judge/commit/amend/release/say`。砍掉：parties 与一切多人能力（同事、群、受众、用与说、两个回执、承诺词检测）；memory 表（只剩"老板说过"清单作为 journal 里挂在常设承诺 C-0 上的 note 行）；classes 表（校准退化为一个 SQL 视图，按固定 8 个种子类算 `eta_factor`）；autonomy；异议的校准；目标与提案；盯外部会话；简报（只剩 reply 与 interrupt 两档）；deliberations 日志。
立得住的理由：成功标准是老板的参与次数，而单人私聊里减少参与次数的只有五件事——受理带假设（少一次追问）、期间沉默（少一次被打断）、带证据交付（少一次验收追问）、不遗忘（少一次"那件事呢"）、一句话能停。剩下的三分之一全覆盖这五件，七步链一步不缺。最关键的是**预测与时钟是列而不是子系统**：`pred_eta_min/actual_min` 和 `next_look_at` 留下了，系统就仍会长大（数据第一天开始攒），砍掉的部分以后加回来都是加表，不改这 4 张的语义。
