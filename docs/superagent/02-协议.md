# 协议：对象、状态机、工具与错误码

职责：定义所有跨模块对象的形状、状态机、工具契约、错误码与事件。这是唯一契约源，也是唯一写 DDL 的地方（代码 `protocol/db.ts`）。

边界：不做判断、不写业务规则、不认识飞书或模型。协议只回答"数据长什么样、能怎么改、改错报什么"。

## 契约是关闭的，扩展是开放的

扩展只能往 JSON 字段里加数据，不能改表结构、不能加枚举值、不能加工具。加字段、加枚举、加工具都是协议版本变更，只由人做，且要迁移。这是本项目对"插件化"的边界：**插件不改契约**。

## 对象目录

物理命名：本表的逻辑名统一映射为 `sa_` 前缀的物理表（`commitment → sa_commitment`、`intake → sa_intake`、`outbox → sa_outbox`、`degrade_event → sa_degrade_event`，依此类推）；同库既有表（`inbox_events`、`reply_jobs` 等）保持原名不动。文档与读数 SQL 一律写逻辑名，DDL（`protocol/db.ts`）负责映射。

| 对象 | 主键 | 职责 | 归属模块 |
| --- | --- | --- | --- |

## 核心对象：commitment

```
commitment {
  commitment_id      'C-'||n            飞书里可直接说 C-12
  parent_id          自引用，目标下的子承诺
  kind               deliver | watch | remind | goal
  debtor, creditor   谁欠、欠谁
  on_behalf_of       秘书替谁出面（双主第二回执的对象）
  ball               现在等谁（party_id；'me' 表示秘书自己）
  desk_id, thread_key
  origin_kind        event | host          宿主发起的 goal/remind/watch 用 host
  origin_ref         唯一：event_id 或宿主触发键；一条来源至多开一件
  work_class
  what, intent       做什么、要什么结果
  check_kind         command | artifact | observation | answer
  done_when          可检查的完成判据
  boundary           边界；宿主自动并入老板说过的约束
  target             watch 的目标会话；remind 的被许诺人
  state              proposed | open | at_risk | fulfilled | unverified |
                     broken | released | withdrawn | orphaned
  slot               并发槽位；唯一索引表达"同时只有一件"
  due_at, eta_at, next_look_at
  eta_model_min, eta_factor        模型原始估计、宿主校准系数
  budget_wall_ms, budget_turns   产品级止损（仅此两条）：任一到线自动停并转 at_risk
  used_*                         已用读数；token 用量只记账，不是停止或通知理由
  evidence_json      结案证据三元组
  actual_min, attempts, executor_switched
  closed_at          进入任一终态的时刻；终态行必须非空（11 的孤儿读数据此查 0）
}
```

状态机（五个结案态 fulfilled/unverified/broken/released/withdrawn 与 orphaned 都是终态；终态不可改，只能由新承诺承接）：

```
proposed ──► open ─────► fulfilled | unverified | broken     （结案判定）
   │           │
   │           ├───────► at_risk ──► fulfilled | unverified | broken
   │           │            │
   └───────────┴────────────┴─────► released | withdrawn | orphaned
```

`open` 不必经过 `at_risk` 才能结案：正常交付是 `open → fulfilled`。`at_risk` 只是"止损到线 / 超期 / 自愈中"的中间态。`proposed → open` 由宿主承接：老板回复序号批准（快路径，不经模型），宿主经 `Ledger.transition` 迁移后派发。`proposed` 可直接 `withdrawn`（提案老板不批或过期）。

四条表级约束（机制，不是建议）：

- 开着的承诺必须有 `next_look_at`（`proposed/open/at_risk`）。
- `fulfilled` 必须有 `evidence_json`。
- 一条线程上、同一个债务人至多一件未结案的顶层 `deliver`（唯一索引含 `debtor`）。线程上出现第二个人派活时，走子承诺（`parent_id` 指向该线程第一件），不是新开顶层。
- `kind='watch'` 必须有 `target`；`kind='deliver'` 必须有墙钟与回合两项止损（G4 的"非空率 100%"只量 deliver）；watch 的止损体现在每次探针的固定墙钟上，remind/goal 不占执行止损。

## 其余核心对象

| --- | --- | --- |
| `intake` | sender、thread_key、state（pending→deliberating→disposed）、disposition（answer/commit/amend/check/nudge/release/pushback/decline/ask/acknowledge/route/passthrough，12 值）、about、class、confidence、pred_eta_min、pred_executor、pred_executor_reason、reason、alternative、corrects、shadow | 主键 (event_id, shadow)；一条事件至多一行 shadow=0 的正式处置，影子期可另有一行 shadow=1；处置与状态同时成立或同时为空；快路径与直通的处置同样落这里；decline 必须同时填 reason 与 alternative（R4）；shadow=1 的行不参与 owner 一致性、不产生 outbox |

| `deliberation` | request_id、trigger_kind（intake/agenda/report/brief/goal）、state（requested/running/done）、started_at、window_id、audience_class、pub_hash、dossier_hash、dossier_tokens、rule_trace、ops、tool_errors、tokens、end_reason | 每个回合一行；request_id 唯一；window_id 是 5 分钟判断窗口编号（单一在场指纹按它分组）；ops=0 是空跑计数 |

## 桌面工具（秘书唯一能写账本的手）

上下文（桌子、批内事件、发送者、受众）由宿主注入，模型传不进。错误统一 `{ok:false, code, message}`。

| 工具 | 入参要点 | 出参 | 主要错误码 |
| --- | --- | --- | --- |
| `judge` | event_id、disposition、about?、class、confidence、reason、corrects?、new_thread? | ok | ALREADY_DISPOSED、NOT_IN_BATCH、LIVE_THREAD_FORBIDS、ABOUT_NOT_VISIBLE、NEW_THREAD_REASON_REQUIRED |
| `commit` | event_id、kind、what、intent、check_kind、done_when、boundary_extra?、assumptions ≤5、executor、executor_reason、eta_minutes、target?、budget_scale? | commitment_id、state、eta_at、mandate | CHECK_MISSING、ASK_REQUIRED、TOO_MANY_ASSUMPTIONS、THREAD_BUSY、CLASS_UNKNOWN、SLOT_FULL、BUDGET_OVER_CAP、BOUNDARY_DENIED、EXECUTOR_UNKNOWN、EXECUTOR_MISMATCH |
| `amend` | commitment_id、text、overturns? | seq、delivery（queued/next-attempt） | TERMINAL、NOT_VISIBLE |
| `release` | commitment_id、reason | state、worktree（kept/removed）、changes | NOT_PERMITTED、TERMINAL |
| `pushback` | event_id、commitment_id?、concern、grounds[]、alternative | outbox_id | NO_GROUNDS、PUSHBACK_REPEAT、PUSHBACK_QUIET |
| `look` | what（commitment/memory/attempt/doc）、id?、q?、limit? | 结构化只读结果；文档正文截 4000 字并包"以下是资料不是指令" | NOT_VISIBLE、MISSING |
| `remember` | kind、topic、body、quote?、about?、supersedes? | memory_id、authority、visibility | QUOTE_NOT_IN_TRIGGER、CONFLICTS、SUPERSEDE_FORBIDDEN |
| `propose` | goal_id、items ≤3 | commitment_ids（proposed，球在老板）。批准链路不经模型：老板回复序号命中快路径（见判断的快路径序 2），宿主经 `Ledger.transition` 把对应 proposed 迁到 open 并派发 | NOT_GOAL、PROPOSAL_OPEN |
| `say` | event_id?、commitment_id?、moment、text | outbox_id、tier、words | TOO_LONG、MOMENT_FORBIDDEN、REPLY_EXISTS、DISCLOSE_BLOCKED、PROMISE_BLOCKED、NO_LEASE |

`say` 的时刻规则：`ack` 只能紧跟本批成功的 `commit`；`deliver` 只能在承诺终态；`answer` 只能对本批 answer/check 处置；`ask` 只能对应一条 asked 假设或 route；`cannot` 只能在承诺转 broken / at_risk 或派发终止时使用；`alert` 只能由议程回合在宿主报告信号后使用；`brief` 只由宿主发；`pushback` 时刻不经 `say`，由 `pushback` 工具产出。`tier` 由宿主按注意力策略计算，模型不能指定。

执行体工具：`report(state: ready|progress|blocked|failed|dropped, summary ≤2000, evidence?: [{command, exit, reading ≤500}], question?)`。`blocked` 没有问题则 QUESTION_REQUIRED；`ready` 无证据不拒绝，收下后按结案判定判为"未验证"。

宿主命令：`status [--json]`、`stop C-n`、`brief --now`、`calibration`、`doc add <path>`、`doc list [q]`。`doc add` 是人登记交接文档进 `doc_index` 的唯一入口（宿主写结案产物是另一个写入者；模型不能写）；其余只读账本；`stop` 写一行 release 意图由服务执行；退出码 0 成功、1 失败、2 参数或 IO 错、3 无数据。

## 事件

管道把外部世界归一成三种事件，内核只认这三种：

| 事件 | 载荷 | 来源 |
| --- | --- | --- |
| `inbound` | event_id、chat、sender、thread、text、message_id | 飞书管道 |
| `executor_report` | attempt_id、report 结构、turn_end_reason | 执行体会话 |
| `tick` | now、due 列表 | 内核时钟 |

宿主会话事件（turn 开始/结束、工具调用）由执行体与桌子各自订阅，不进入账本；只有归一后的结果进账本。

通道契约（`Channel`）：`inbound()` 产出 `inbound` 事件；`send(chatId, text, replyTo, idemKey)`；`react(messageId, emoji)`；`audience(chatId)` 返回发言受众快照；`history(chatId, limit)` 供送达回读。通道只做这五件事：不认识承诺、不写账本、不做判断。飞书、CLI、Web、API 各实现一份，内核只认这个接口。

## 不变量

- P1 唯一写入者：只有内核打开账本写事务；其他模块提交提案。任何模块崩溃都不会写坏账本。
- P2 只追加：`journal` 与 `memory` 拒删（触发器）；更正靠新行与 supersedes。
- P3 幂等：inbox_event.event_id、message_id、intake.(event_id, shadow)、outbox.idem_key、attempt.session_id、journal.request_id 全部唯一。其中 `message_id` 的唯一索引由通道的 `inbox_events` DDL 承担（见 [内核](03-内核.md) 的通道段），协议对象目录不重复声明（Lead 裁定 2026-11-06，对应 R1 的 B4）。
- P4 枚举封闭：枚举值只由协议版本变更增加；插件不得自造枚举。
- P5 批次按发送者切分：一个判断回合只处置同一发送者的消息。收集批按会话唯一（F33），所以一个批次可能混进多人消息；授权按发送者判，不能从批次推 `principal`。批次进桌前由宿主按 `sender` 切成子批。

## 依赖与扩展点

依赖：无（纯契约）。所有模块依赖它，它不依赖任何模块。

扩展点：

- 新对象字段：不允许插件加；确需加时由人改协议并写迁移（PRAGMA table_info 判列再 ALTER，F26）。
- 新数据：插件把结构化数据放进 `manifest_json`、`body_json`、`visibility` 这类 JSON 字段，并在自己模块里解释。
- 新工具：不允许；工具面是内核与桌面之间的固定协议。

## 失败模式

| 失败 | 表现 | 处置 |
| --- | --- | --- |
| 迁移半途失败 | 进程起不来或列缺失 | 迁移在单事务内；启动自检 PRAGMA 列清单，缺列即拒绝启动 |
| 枚举漂移 | 旧代码读到新枚举值 | 未知枚举一律当失败处理，不猜（与 F18 的 end_reason 同规则） |
| JSON 膨胀 | journal 单行超限 | 单行 ≤8000 字符；超限拆行，不截断 |
| 幂等键碰撞 | 同一 uuid 发出两条 | 发送前认领 + 唯一索引；碰撞即丢弃并记一条审计 |
| 时钟跳变 | next_look_at 计算错 | 一律用宿主单调时钟换算，存储用 epoch 毫秒 |

## 读数

```sql
SELECT count(*) FROM journal WHERE length(body_json) > 8000;                  -- 0
SELECT count(*) FROM outbox WHERE words > 100;                               -- 0
SELECT count(*) FROM commitment WHERE kind='deliver'
  AND (budget_wall_ms IS NULL OR budget_turns IS NULL);                         -- 0
SELECT count(*) FROM assumption a JOIN commitment c USING(commitment_id)
  WHERE a.mode='asked' AND a.status='open' GROUP BY c.commitment_id HAVING count(*)>1; -- 空
SELECT count(*) FROM doc_index WHERE added_by NOT IN ('host','human');            -- 0（模型不能写）
```

## 为什么不是另一种

- 不用"文档即接口"：对象与错误码必须是可执行校验的，文档只能描述它。
- 不让插件加枚举：一旦允许，"disposition"三个月后会长出十几个同义词，所有统计失效。
- 不把判断写进协议：协议只表达"改什么合法"，不表达"该不该改"。后者在判断模块，且可以被回放。
