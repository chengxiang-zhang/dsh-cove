# 托管协调：代替老板推进 Agent 工作

职责：持续承担事项与长期职责的结果责任，统筹多个项目、机器和 Agent，把观察转成有依据的下一步。目标设计，尚未声明实现。

边界：不亲自调查或修改业务代码，不绕过执行端操作机器，不自行扩权，不直接发送对人消息。模型进行理解与计划，宿主校验操作并持久化。

## 承接与持续责任

接到事项时建立目标、可验证结果、交付位置、项目范围与授权引用。可从上下文和仓库规则确定的内容自行补齐并留出处；实质产品分歧给出推荐方案，不能让老板选择执行器、重试次数或技术故障处理方法。

长期职责还需要期望状态、观察来源、允许自主发起的工作、复查时机与暂停条件。接管时由系统盘点已有项目、会话和约束形成可审阅的职责描述，不把初始化变成老板填写配置表。

一个 Superagent 统一负责；项目、职责、事项分别有状态，不强制每项目常驻一个 Agent。委派临时协调者时必须限定事项、可用资源、回报方式及停止条件；不能转授超出原授权的能力。

## 从方向到执行

1. 明确的方向型委托进入事项，保留原始目标，安排授权内调查与方案分工。讨论和随口想法按 [判断](08-判断.md) 归位。
2. 汇总跨项目证据和候选方案。将实质产品取舍集中成版本化裁定请求，说明推荐及默认动作。等待期间推进授权内且不依赖该裁定的工作。
3. 用户采纳后，将决定映射到需求版本、验收和交付合同，再拆出带项目、依赖和检查点的工单。涉及新项目时按 [世界模型](04-世界模型.md) 逐阶段接入或初始化。
4. 系统在已采纳目标、范围、承诺和授权内调整分工、方法与顺序。新证据显示方向可能需要改变时，先调查和准备方案，涉及实质变更再请用户决定。
5. 发现评审退回或验证失败，按 [协议](02-协议.md#分工与执行尝试) 回投原生会话并跟踪消费，修复后按新产物版本复核。最终按原目标汇报证据；改善类目标安排效果复查，技术交付和实际改善分别记录。

自动维护发现经去重和价值判断即可正式受理，不每次产出待批提案。某次委托明确包含更高交付阶段时，仅该目标与阶段按其授权处理，不全局改写职责。

跨项目验证增加第二个受控项目及授权宿主的画像；不以本机当前项目授权推导另一机器的控制权。此设计稿不会启用任何画像。

## 完整操作循环

| 环节 | 核心判断 | 必须留下的事实 |
| --- | --- | --- |
| 定位 | 人指哪件事、哪个项目、哪个宿主或已有会话 | 目标引用、消歧依据、观察时间 |
| 理解 | 目标、约束、完成条件和隐含依赖是什么 | 需求版本、假设及来源 |
| 组织提示词 | 执行体已有何上下文、缺什么、要交付什么 | 交办版本、材料引用、验收合同 |
| 安排 | 复用谁、何时并行、哪处需要隔离 | 分工、资源占用、依赖与理由 |
| 观察 | 与预期检查点相比是否有真实进展 | 产物变化、测试变化、阻塞与新证据 |
| 纠偏 | 误解、缺信息、环境故障、方法无效还是正常等待 | 诊断假设、备选方法、操作及预期读数 |
| 回收 | 结果在哪里、与哪次执行和需求有关 | 产物版本、执行记录、未消费输入 |
| 验收交付 | 满足要求了吗、进入约定交付位置了吗 | 验收结论、交付回执或继续工作的原因 |
| 继续 | 是否推进后续依赖，职责效果是否改善 | 下一步或带触发条件的等待，经验引用 |

工具执行与事实快照可能过期；每个会改变外部状态的提案都带 expected_revision/epoch。失败重新观察再判断，不对同一过期快照重复操作。

## 主动工作从哪里来

观察源可包含 CI/测试、运行异常、Issue/反馈、已有 Agent 会话、依赖和安全维护信息，以及授权内定期检查。观察源注册时声明读取权限、范围、时效、去重键和最晚复查，避免「只要没有新事件就永远不看」。

发现先进入 finding：可复现证据、影响、所属职责、已有事项关联。根据影响与可处理性选择并入、正式受理、继续观察或有理由地不做。无证据的改进想法可先只读调查，不直接生成无限维护队列。

在职责授权内、目标明确的缺陷修复由系统自行受理执行。新产品方向、扩大职责或外部承诺不能借「主动维护」越权。没有值得处理的问题时保持观察；主动性不以任务数或工具调用数评分。

## 跨项目安排

统一看老板显式优先级、实际风险、期限、依赖、受影响范围、等待时长及资源可用性；具体排序是可解释的策略，不写死成项目轮询。老板未排序时系统根据已有目标排序，不把日常调度交回老板。

- 独立项目、独立写域可以并行；共享 checkout、分支整合或外部环境变更必须获得资源锁。
- 工作区形态服从各项目自己的规则；不得假定所有仓库都允许 worktree。
- 高优插单前先保全进展和资源；不能让被挤出的事项失去 next_review_at。
- 跨项目依赖显式保存满足条件和成果版本；检测环后重新安排或缩小单次分工，不擅自缩小总目标。
- 每件延期事项记录原因、替代动作、最晚复查。持续延期触发重新排序，不能无声饥饿。
- 项目授权分别求值；同属老板或同属 NetBird 不代表可以跨目标执行。

资源争用的实施形态是宿主可执行的锁与租约，不是提示词里要求「别冲突」。

## 诊断与自主恢复

低工具调用、重复命令、耗时超过预计只是信号。先检查事件新鲜度、执行器是否仍活跃、产物与测试是否变化、是否等待外部动作，再形成诊断。

| 诊断 | 处置 |
| --- | --- |
| 正常调试或明确等待 | 保持执行，更新下一检查点；不因重复编辑杀掉会话 |
| 理解偏差或交办缺上下文 | 修订交办，给出具体纠偏，确认新输入被消费 |
| 可修复环境问题 | 安排环境修复或切换已授权环境，随后继续原事项 |
| 方法无效 | 切换方法或请求独立调查，带上已失败的方法与证据 |
| 执行器故障或上下文失真 | 保全成果、交接，再更换执行体 |
| 资源或外部依赖不可用 | waiting，保存恢复触发与最晚复查，继续推进其他工作 |
| 当前约束确实无法满足 | 用证据说明障碍及已考虑路径，保留成果；确实无法继续时 broken，不能假完成 |

同一失败签名无新证据或不同策略时禁止盲目重试；尝试预算到线先停止或保全该尝试，再诊断责任如何继续。等待要周期性重新评估可行性，不用定时空回合冒充推进。策略重试预算由可解释策略控制并可在有新证据时调整，不采用「固定三次等于目标失败」。

系统不能以恢复为名自行降低验收、取消需求或创建同义事项重置失败计数。无法自主消除的授权缺口与真实产品取舍才找老板；其余失败可以如实交付无法完成结论，但不要求老板接手诊断。

## 人工介入与职责暂停

用户的明确停止优先于调度。暂停与进度状态正交，默认范围按协议：暂停职责阻止新事项并暂停专属在途工作，不误停独立委托的共享事项；明确停止事项转 released，原始成果与输入保留。含糊的「停」先用当前明确焦点定位，无法唯一定位时只问范围，不猜测全局停机。

用户停止的事项及关联 finding 保存抑制记录：同一目标、同一问题与同一事实版本不能被主动扫描立即重开。新证据可以记录和评估，但要重新执行已取消工作，须有明确新委托或职责范围调整；不得借新 id 绕过停止。普通归还控制只解除 human_controlled，不解除 released 或 finding 的取消抑制；归还同时明确重新委托时才建立关联新事项。新出现的独立高风险事实可告知用户，不等于自动恢复已取消操作。

人在 GUI/CLI 接管会话或外部取消，系统停止自动写入并标为 human_controlled；继续只在明确归还控制后。单纯查看页面不算接管。不能用诊断循环把人停止的 Agent 再拉起来。

## 契约与依赖

```text
accept(intent, context) → commitment + contracts
reviewResponsibility(id, facts) → findings + decisions
schedule(snapshot) → versioned assignments + resource claims
advance(commitment, observations) → next action / wait / evaluation request
recover(commitment, diagnosis) → revised strategy with expected evidence
```

依赖判断、执行体、验收、规则、记忆、世界模型与内核。判断生成解释与交办，执行体完成协调操作，验收给结论，内核保真；本模块统一决定下一步。没有任何下层模块直接调用本模块形成环。

## 失败模式与验证

最危险的失败是「账本没丢，但事情没人推进」。检查非终态事项与职责是否有可执行下一步、有效等待或确证的无法完成；仅 next_review_at 非空不够。

验收应证明无人催办闭环、跨项目插单不遗忘、错误提示词能被修正、同一失败不盲重试、坏产物被退回以及人工接管不被夺回。可扩展观察源和协调策略，但不能绕过授权、资源锁、验收或停止语义。
