# 双语文档契约（i18n）

本仓库面向中英双读者，根入口文档与包 README 都维护英文与简体中文两份，规则见 [docs/AGENTS.md](AGENTS.md)。本文件定义配对机制、维护流程与门禁。

## 配对机制

一对双语文档是一组三个文件，同目录平铺：

| 文件 | 内容 |
| --- | --- |
| 英文文件 | 权威英文版本，例如 `README.md`、`CONTRIBUTING.md` |
| 中文文件 | 同等权威的中文版本，例如 `README.zh.md`、`CONTRIBUTING.zh.md` |
| 配对记录 | `.i18n.yaml`，记录两侧在「最后确认一致」时点的 git blob hash |

当前配对集合在 `scripts/verify-docs.mjs` 的 `pairSets()` 中声明：

| 标签（`--write` 用） | 英文文件 | 中文文件 | 配对记录 |
| --- | --- | --- | --- |
| `root` | `README.md` | `README.zh.md` | `README.i18n.yaml` |
| `CONTRIBUTING` | `CONTRIBUTING.md` | `CONTRIBUTING.zh.md` | `CONTRIBUTING.i18n.yaml` |
| 包目录（如 `packages/dsh-web-all`） | `README.md` | `README.zh.md` | `README.i18n.yaml` |
| `tools/` 下成对目录（如 `tools/dsh-netbird`） | `README.md` | `README.zh.md` | `README.i18n.yaml` |

配对记录使用 git hash-object 的内容寻址，不依赖提交。编辑任一侧后，配对记录与另一侧即失同步，`pnpm docs:check` 变红。

## 维护流程

1. 编辑任一侧（中英同等权威，先写哪侧都行）。
2. 同一次改动内把另一侧同步成同一事实，保持结构镜像。
3. 确认两侧表达一致后重录配对记录：

```sh
pnpm docs:write-pair root              # 根 README 对
pnpm docs:write-pair CONTRIBUTING      # CONTRIBUTING 对
pnpm docs:write-pair packages/dsh-web-all   # 某个包的 README 三件套
```

不带标签运行 `pnpm docs:write-pair` 会重录全部配对。重录产生的 yaml diff 就是「我确认了这次一致性」的可审查动作。

## 结构镜像要求

两侧除语言切换行与正文文本外，结构必须一一对应：

- 标题层级与顺序一致；
- 代码块（围栏与内容）一一对应；
- 表格行数与列数一致；
- 列表种类与条目数一致；
- 链接目标一致（切换行除外）。

语言切换行：英文 H1 后 `English | [中文](<中文文件>)`；中文 H1 后 `[English](<英文文件>) | 中文`。

## 门禁

`pnpm docs:check`（scripts/verify-docs.mjs）机械校验：配对三件套完整、记录 hash 与当前内容一致、切换行存在、结构签名匹配，以及对根入口文档、社区健康文件与 `docs/` 的相对链接与锚点。门禁只证明「记录时两侧一致」，不判断翻译质量——忠实与通顺由评审负责。

## 范围

- 覆盖：根 `README` 对、根 `CONTRIBUTING` 对、`packages/` 下所有包的 README 三件套，以及 `tools/` 下同时存在中英 README 的目录；
- 不含：构建产物与第三方代码；`docs/` 深度文档以中文单语维护，语言策略见 [README.md](README.md)；
- 新增配对：`packages/` 与 `tools/` 下只要同时放置 `README.md` 与 `README.zh.md` 就自动纳入门禁，必须同 PR 补 `README.i18n.yaml`；根目录新增配对需在 `pairSets()` 中显式声明。
