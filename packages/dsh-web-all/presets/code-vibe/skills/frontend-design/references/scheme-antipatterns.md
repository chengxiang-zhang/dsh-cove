# Scheme antipatterns（≤12 · 只增须替换）

> Shape / Spec / Verify 共用。命中 → 不得请人确认方案；不得把该 Oracle 当 T-001 成功。
> 可感主路径卡：[`perceptible-path.md`](./perceptible-path.md)。

| # | 反模式 | 失败信号（观察方式若仅此则 Fail） |
|---|--------|----------------------------------|
| 1 | **Tour / 引导遮罩当教育** | 播完 Tour / 点完「下一步」即算学会 |
| 2 | **纯 Checklist 教育** | 勾完 lesson / checklist / 完成率 = 成功 |
| 3 | **假沙箱** | 沙箱无真实后果，出沙箱即「已掌握」 |
| 4 | **状态机冒充教学** | 状态位翻转 / flag 置位 = 学会 |
| 5 | **深链 = focus textarea** | 打开抽屉 / focus 输入框 / 点击 CTA 单独当教育成功 |
| 6 | **使命膨胀** | 常青账本 / 增长使命写进方案却无首日可感表面 |
| 7 | **齐套灌水 / 文档对齐冒充设计** | 五层产品包或 docs 章节齐套但无代码锚点、无可证伪断言、无机制/主路径提案 |
| 8 | **软回退关「学会」** | 出错软退回仍标教育完成 |
| 9 | **residual 装过** | live-deferred / residual 冒充主路径已证 |
| 10 | **形式走查** | UX 走查只对 rule ID，无对可感主路径 |
| 11 | **懒 Done when** | Done when 仅「打开 X / 点到 Y」无用户结果 |
| 12 | **把人当 CI** | 把「Codex 行不行 / 再跑一遍脚本」甩回用户当主验收 |

**硬上限 12 条。** 新增须替换一行并说明替换理由。
