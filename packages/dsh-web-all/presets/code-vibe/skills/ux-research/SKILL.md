# 用户体验研究（UX Research）

> 先归类问题，再选方法；写清前提与失效形态；发散要有底账。

## 何时用

- "用户到底要什么/为什么不用/体验差/做个访谈或问卷/验证一下"；
- 设计方案缺乏证据、或需要验收体验。

## 四类问题 → 方法

| 问题 | 方法 |
|---|---|
| 是不是在解错题 | 访谈、情境调查、需求验证 |
| 用户在想什么 | 访谈、日记研究、同理心地图 |
| 过程卡在哪 | 可用性测试、认知走查、任务分析 |
| 结构找不找得到 | 树测试、卡片分类（交给 IA skill 执行） |
| 满意度/效果 | HEART、SUS、NPS、任务成功率 |

## 工件（`docs/design/<id>/ux-research.md`）

1. 研究问题（可回答、可证伪）；
2. 方法与**前提/失效形态**（样本偏差、场景偏差、诱导）；
3. 样本与招募口径；
4. 发现（分条，带证据：原话/读数/录像时间戳）；
5. 对设计的含义（做/不做/改哪）；
6. 度量：指标定义 + 基线 + 目标。

## 评审（ux review）

- reviewer：ux-reviewer（+ pm）；
- 判据：方法-问题匹配、样本交代、发现可追溯、含义可执行；
- 无证据的"用户会觉得"不许写进结论。

## 反例

- 先有方案再找用户证成；
- 只写"建议优化体验"；
- 用 SUS 总分代替具体问题定位。
