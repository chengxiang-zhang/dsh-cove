# 1. 角色边界（硬表，违反即"作弊"）

| 角色 | 能做 | **不能做** |
|---|---|---|
| **Lead（主会话）** | 派工；独立验门；裁决技术问题；提交/推送；窗口 apply 与回读；对用户汇报；**只写程序级控制文件**：账本、宪章、批次台账、`docs/specs/<program>/{INDEX,INTERFACES,INTEGRATION,EFFICIENCY,EXECUTION-LOOP,BATCH-STATE,HANDOFF}.md`、板卡、commit | 写包内文件（`VERSION/contract/tests/plan/run` 及任何 `scripts/**`、`deploy/**`、`installer/**`）；改真源后不同批重生成投影/锚点；替 worker 排查实现细节 |
| **worker（teammate）** | 只写自己写域内的文件；先自证"问题是否还存在"；跑门取证；回执 | 改账本/INDEX/宪章/批次台账；commit；push；改他人文件；把"绿"当证据 |
| **verifier（独立复核）** | fresh context 只读复核 diff + 证据 + 结论；投"同意/不同意+理由" | 改任何文件；复用执行者的记忆或结论；**判完同一包再去做该包的施工者** |

**三条不可合并**：写的人不验自己；验的人不改；账本只有一个人动笔。
**判者不得变造者**：提出「已解决/可关条」的 agent 不得成为该包施工者；必须复用时，派工单写明
"你此前判定不得作为本轮依据"，并另派第三人复核其补丁。

**Lead 越界的三种真实形态**（全会话 830 次 edit 的主要来源）：
① 顺手补实现（窗口写动作旁边有门/脚本时，**必然**顺手改）；
② 改真源忘同批投影/锚点（`RETAIN_DAYS`、revert、提锁三次都留坑，靠 worker 抓出）；
③ 把"我改一处更快"当理由（最后一天仍复发，被用户当场点出）。
**半成品例外**：若确实由 Lead 写了半成品，必须披露、由 worker 反签、且**不计入 Lead 的交付**；
用户原话是"写代码是你应该干的事情吗"——这不是允许项。
