# 批次台账模板（`BATCH-STATE.md`）· 证据可机器校验版

> 位置：与宪章同目录。**批次收尾的唯一机器可读真源**；配一个契约测试（见 §3）。
> **只追加，不改旧行**；一行一批。
>
> **为什么这么严**：全量审计发现 38 个批次行里，D1 的 13 行 12 个成立、D2 的 13 行只有 7 个成立；
> 典型失真 = 拿 teammate 回执当一级证据（B-010）、命令与读数不是同一条（B-001）、命令实跑 `exit 1`（B-005）、
> 证据行自身含竖线打红台账门（B-006）、17 条关闭 0 条当轮证据（B-015）、四个采样键只在写台账的 heredoc 里（B-022）、
> 计数命令从未执行（B-023/B-024）、标题说 4 行表里 5 行（B-021）。

## 1. 表头（证据拆三格）

```markdown
# 批次状态台账 · <program-id>

> 只追加；状态只有 `open / closed-by-closure / closed-by-effect / closed-by-decision`。
> `closed-by-closure` 必须账本条数减少且有当轮读数；`closed-by-effect` 必须给生效证据；
> `closed-by-decision` 只用于"裁决不做/KILL"（必须带 KILL 五条件，且不得与 blocked 状态并存）。
> 最后一条 `closed*` 的"后"值必须等于当前账本条数。
> 证据三格：命令（当轮执行原文）/ 读数（该命令输出片段，禁竖线）/ 复跑校验（Y/N+命令）。

| 批次 id | 标题 | 状态 | 账本条数(前→后) | 命令(当轮执行原文) | 读数(输出片段，禁竖线) | 复跑校验 | 读于 | 提交 sha | 材料(包内路径) | 回滚(可执行命令) |
|---|---|---|---|---|---|---|---|---|---|---|
| B-001 | … | closed-by-closure | 71→70 | `<本批真正执行过的命令>` | `<该命令输出中的原样片段>` | Y：`<重放命令>` 读数一致 | T099 | abc1234 | `docs/specs/x/optional/...` | `<命令>` |
```

**列的硬要求**

1. **命令**必须是**当轮实际执行**的那一条（原文）；不能写"等价形式"，不能写打算执行的命令。
2. **读数**必须是该命令 `tool/result` 里的**原样片段**；禁竖线 `|`（会打红台账门），写入时自动转义/替换。
3. **复跑校验**：事后（下一个静默点）重放一次，读数一致才写 `Y`；不一致写 `N` 并开新批次修正。
4. **读于**：`T###`（哪一轮读到的）。跨轮引用必须标来源轮次——审计发现多例"把上一批的读数挪到这一批"。
5. **材料**：包内真实路径；**时间戳必须早于集群动作**（审计发现"集群写早于材料 5 分钟"）。
6. **回滚**：可执行命令；派生可重建的给重建命令。
7. **一次关 N 条**：每条须有自己的只读判据；共用探针必须显式声明"该命令覆盖哪 N 条"。
8. **两种合法证据模式**（审计发现"worker 批次无合法证据格"）：
   - **Lead 自执批次**：命令 ∈ 当轮 `tool/call`，读数 ∈ 同一 call 的 `tool/result`；
   - **worker 执行批次**：`source=receipt:<sender>` + **`verified_by:`**（Lead 或第三人重跑过该命令的读数）；
     回执本身不得单独充当一级读数。窗口类批次优先 worker 执行；若 Lead 执行，状态记 `closed-by-effect(Lead-executed)` 并披露。
9. **窗口类**：执行者≠Lead；若 Lead 执行，状态记 `closed-by-effect(Lead-executed)` 并在标题披露。

## 2. 状态语义

| 状态 | 允许条件 | 禁止 |
|---|---|---|
| `open` | 批次已开、未收 | — |
| `closed-by-closure` | 账本减条 + 当轮读数 + 复跑 Y | 只改标签/措辞；无新读数 |
| `closed-by-effect` | 生效证据（命令 + 读数） | "apply 成功"当生效；无回读 |
| `closed-by-decision` | KILL 五条件齐 + 重开条件 | 与 `blocked` 状态并存；P0 静默降级；判据放宽 |

**KILL 五条件（全预设唯一版本）**：① 能力/对象确实不存在（只读命令 0 命中）；
② 证据当轮可复跑；③ 不由越权/无授权实验得出；④ 判据不放宽；⑤ **merge 目标存活且 P0 未被静默降级**。
KILL 行状态写 `closed-by-decision:<原因码>`，不得与 `blocked(...)` 并存；行内须有 `cmd…rc=0 hits=0`、`not_from:`、`p0_after:`。

## 3. 契约测试（建议 8–10 条判据）

| # | 判据 | 说明 |
|---|---|---|
| 1 | 表头列齐 | 必需列齐，允许额外列 |
| 2 | 状态闭集 | 只允许 §2 的四个状态 |
| 3 | closed 必有证据 | `closed*` 行三格非空 |
| 4 | **读数可回溯** | 读数字符串必须出现在**同一 turn 的 tool/result** 中（拦"从未执行""事后回填"） |
| 5 | **命令当轮存在** | 命令字符串必须出现在同一 turn 的 `tool/call` 参数中 |
| 6 | 减条自洽 | `closed-by-closure` 前→后递减；最后一条 closed 的"后" == 实际账本条数 |
| 7 | 禁竖线 | 任一单元格不得含 `|`（防列错位） |
| 8 | 材料存在 | 材料列路径在树内存在 |
| 9 | 回滚可执行 | 回滚列含可执行命令（含"派生可重建+重建命令"） |
| 10 | 负控 | 人为改一行成"无证据 closed" ⇒ 必须变红 |

> 判据 4/5 是关键：它们把"抄进台账的文字"和"真的跑过并拿到读数"机器区分开。
> 如果做不到自动取 tool/result，退一步：要求每行附 `读于 T###` 并把该轮的原始输出片段粘在批次附注里（人工可核）。

## 4. 正反例

**好（B-017 式）**：四条存量数（`table_owner=49 / assertion_result=13418 / policy_state=10 / asset_snapshot=49`）
+ 两条行为探针（不允许 UPDATE / 不允许 DELETE）+ `BEGIN…ROLLBACK` 零残留，全部同轮实测、同一条命令输出。

**坏（审计实测）**：

- `grep -rn 'default="minioadmin"' scripts/ ⇒ 0`——**该命令一次没跑过**，同期实际是命中。
- `grep -c 'flock -n' ⇒ 25`——`flock -n` 只出现在写台账的 heredoc 里。
- `container_mem_limit_bytes=12884901888`——四个键只在写台账的文本里出现，无测量输出。
- `71 passed`——实测出自**另一批**（B-026 挪用了 B-022 的读数）。
