# 主会话 · Agent Team 长跑协议

> **Entry tier: T3 only.** T2 uses at most one implementer + one independent verifier, no charter/batch/board.

主会话不是施工队，是**项目协调面**：派工、独立验收、裁决、提交、账本、窗口、汇报、出口。
本 skill 把"一个目标跑几十上百轮"变成可判定的机器：每轮有准入、有硬指标、有收尾信号、有反空跑检测。

> **一句话**：领导只做三件事——**把活派出去、独立验回来、把账记真**。任何需要你亲手写实现文件的时刻，都是流程出错的信号。

## 0. 先决条件（不满足就先补，别开环）

1. **能力探测**：有 `spawn_teammate` / `team_task_*` / `send_message` / `wait_agent` ⇒ 用 Agent Team；
   只有 `subagent` / `subagent_fork` ⇒ 用 subagent 承担同样角色（写域与验收协议不变）；
   两者都没有 ⇒ 先说明无法并行，按单线执行并向用户报风险。
2. **开环四件套存在**（否则先做 `large-backlog-program`）：唯一账本、可独立验收的任务/包、
   宪章 `EXECUTION-LOOP.md`、批次台账 `BATCH-STATE.md`（模板见 `references/`）。
3. **写域清单**已登记；共享文件只有 Lead 写。
4. **机械计数起点**：记下"Lead 对 `scripts/**`、`deploy/**`、`installer/**`、`**/run.md` 的 edit/write 次数 = 0"这个基线；
   它每轮都要被复核（见 §1）。

## 2. 开环四件套（抗压缩的真正载体）

对话会被压缩，磁盘不会。开环前把四件写进仓库，之后每轮从磁盘恢复：

1. **宪章 `EXECUTION-LOOP.md`**：§0–§9（出口/单位/单轮协议/选卡/写域/证据/记账/预算/停止/抗压缩）+ 轮次日志。
   模板见 `references/project-charter.md`（含证据三件套、关条锚点扫描、KILL 五条件、写令牌、S0 摘要作废）。
2. **批次台账 `BATCH-STATE.md`**：一行一批，只追加；四种状态 `open/closed-by-closure/closed-by-effect/closed-by-decision`；
   **证据三格**（命令当轮/读数同源/复跑校验）+ `读于 T###`；一次关 N 条每条一据；worker 回执标 `source=receipt:`。
   模板与契约测试见 `references/batch-ledger.md`。
3. **任务板**：一卡一任务、写域随卡登记、`blocked` 用 `[BLOCKED: 原因]`；**板卡是"切片→owner→状态"的单一真源**
   （退出回路 = 重复派工）；每轮 S1 对账。派工模板见 `references/card-dispatch-report.md`。
4. **goal objective 只放判据 + 纪律**：出口判据、5–9 条硬约束、收尾信号、状态卡路径；不写计划；
   自撰出口条款标「待用户确认」，与账本证据冲突取更严者。

**R0 开环轮**：建四件套/板卡/写域登记的那一轮允许以"四件套齐 + 一条可复跑读数"收尾（轮日志标 `R0=setup`）；
空转与关条计数器从第一条 `closed*` 之后开始计。



## 3. 建队与分片

- **上限以运行时为准**（本环境实测 `active child limit: 5`；成员名单上限 8 ≠ 并发上限）。满了复用 inactive 成员，**不新建**；
  不要把"8 人"当既定事实（审计发现 6/6 摘要复述 8 人却无出处）。
- **分片按认知边界与写域**，不按文件数：一个 worker 一片，片上写域互斥。
- **角色基线**：每张派工单开头写「本轮角色 = …；与上一角色不同则声明作废旧写域」。
  （反例：`spec-author-m0-m5` 从"只写设计件"变成"改 Rust 并 push"；`m2cdc-m3` 跨 5 模块 33 切片。）
- **命名 ≠ 职责**：汇报并行度按"承接模块/活跃 lane 数"，不按成员数（真实：名义 8 人、实际 ≈2）。
- **`queued` ≠ 唤不醒**：改派前先 `list_agents` + 查该成员最近产出时间；真实翻车是 m4 已醒 36 分钟
  仍被宣布"唤不醒"并改派。
- **零回执成员**：同一成员 ≥3 次派工 0 回执 ⇒ 标"不可用"换人；"已投递"不等于"已委派"（真实：41 次仪式性投递）。
- **必配一个独立 verifier**（fresh context，只读）：maker ≠ grader；每 10 轮抽 1 个已关项重挖一遍。

## 4. 派工（模板见 `references/card-dispatch-report.md`）

派工消息必须自足，worker 不该反问你。八段：

1. **现状（事实区）**：读数 + **生成它的命令 + 时间戳** + 明确写"可推翻，先复算"。
   （真实翻车：切片映射 4/6 错、3 次硬证据假归因，每次代价 1–2 轮。）
2. **是否已做**：`git log --since=<上次回执> -- <写域>` + 包 `run.md` + 板卡；已有 owner/已完成就改复核，不重派。
3. **任务编号与目标**：一句话可判定；写"可关/还差什么"的判据。
4. **要做什么**：编号步骤；每步给入口命令或 file:line。
5. **验收门**：命令 + 期望读数 + **负控**（注入什么必须红）；覆盖/集合类判据必须 `--require-nonempty`。
6. **写域与禁令**：只可写这些路径；禁改账本/INDEX/宪章/批次台账；禁 commit；禁 push；禁改他人文件；
   **禁自造规则/上限**；**禁脚本批量改文档**。
7. **回执格式**（按类型）：交付型五段（写域 / 每条处置 / 未证实 / 需裁决 / 判定）；快答型可三段（结论 / 证据 / 风险）。
   真实：<1000 字的快答回执 0/6 写了五段——不要用五段误判快答。
8. **停手条件**：超时、同一问题卡 2 轮、发现需裁决、环境写令牌被占 ⇒ 停手回报，保留现场，不许硬猜。

**纪律**：派工即 claim（Lead 先 `reassign` 再 worker `complete`——`in_progress` 卡不能 claim）；
一次一片；只读发现类可扇出；写域冲突按"归属/时间"裁定并留档；未答的 needs-decision 进清单，下轮优先清。

## 5. 回执与独立验收

### 5.1 worker 回执必须包含

```
① 写域清单（逐文件，"未改账本/他人文件"）+ git status 只含这些路径
② 每条目处置（id → 处置 → 命令 + 读数）
③ 未证实项（Unverified: 缺什么）
④ 冲突/需裁决（needs-decision=）
⑤ 判定：可关 / 还差什么
```

### 5.2 Lead 验收（不采信"绿"）

1. **自己跑门**：worker 说 23 passed，你就跑一遍；读数以你的为准。
2. **检查覆盖**：验收要看**动作本身是否覆盖完整判据**（真实翻车：worker 用 `--from verify` 收口，
   Lead 指出"这不是完整一轮绿灯"）。
3. **检查越界**：`git status` + 写域清单逐条比对；越界即打回。
4. **抓假绿四类**：① 门只做正控；② 读数与结论不一致（"8 passed"实为 1 failed）；
   ③ 语义错配（PromQL `=~` 整串锚定 ⇒ 告警被静默关闭）；④ 门绿但运行态拒（端口名超长、`OnDelete` 不滚动、
   `phase==Running` 在 Terminating 期间也成立）。
5. **停手信号**：验收前确认 worker 已停手（明确说停 / `git status` 两次稳定 / 文件 mtime 早于验收开始），
   否则会验收半写树（真实：3 条"必修"是时序误报）。
6. **真基线**：判断"这红是我引入的还是存量"必须用干净基线——`git archive <sha> | tar -x -C /tmp/base` 后在同一门集上跑，
   或 `git worktree add /tmp/base <sha>`；口头归因（"可能他人在途"）不算（真实：Lead 三次归因全错，最后用 `HEAD~90` 基线
   才承认 8 条是自己引入的；`git archive` 也用于验收，避免读到半写树）。
7. **只提交绿的**：提交闸门写成 `if pytest …; then git commit; else 不提交; fi`；
   **禁止 `pytest | tail`**（退出码被掩掉，两次红门提交、一次五红提交）。
8. **失实即更正**：自己的提交说明写错，跟进更正 commit；不悄悄改。
9. **他证**：G1 级以上结论交 verifier；verifier 的"不同意"逐条裁决并留档；
   账本每条归宿的"谁跑的/命令/读数"必须先在 `run.md` 落行且有回执，否则不许写"非执行者取证"。

## 6. 账本与关条

- **单写者**：Lead 删条 + 写删除索引 + 重算 §0 计数，同批完成。
- **关条判据只由条目自己的验收门定义**；**每批必须报本条新增的可复跑读数**（没有新读数 = 不算关，
  真实：17 条"关闭"零新读数）。
- **关条触发**：取先到者——① 平台侧证据齐（命令 + 读数 + 非执行者复核）；② 模块边界。**不等窗口**。
- **下游锚点扫描**（真实翻车：关条把全绿契约门打成 4 failed/30 passed/9 skipped，两天未回绿）：
  `grep -rl "GAP-<id>" docs/ scripts/ deploy/`；有引用即同批改锚点 + 跑反查门集。
- **blocked 三要素**：阻塞物（谁/哪个仓/哪个窗口）+ 复现命令 + 复查日；缺一 = open。
- **accepted-risk 单列**：必须有接受人 + 复核日 + 重开条件；不计"未处理"，也不计"已解决"。
- **KILL / 裁决不做五条件**（真实：32 条"杀"里 17/17 正文仍写 blocked，4 条 P0/critical）：
  ① 能力/对象确实不存在（只读命令 0 命中）；② 证据当轮可复跑；③ 不由越权/无授权实验得出；
  ④ 判据不放宽；⑤ **merge 目标存活且 P0 未被静默降级**。`blocked` 状态与"已裁决不做"不能共存；
  KILL 行的状态用 `closed-by-decision:<原因>`，并在文末索引留 id。
- **判定必须可复现**：同一条目、同一证据，换框架重判导致结论翻转（真实：29 条 → 0 条 → 7/7 KILL）⇒
  第一次作废并复盘；两次判定差异 >50% 按事故记。
- **改措辞不算账本动作**：收缩阻塞说明、补记录、改状态标签都不产生净变化。
- **假关闭黑名单**：用 `blocked` 当出口、放宽判据、只写报告、"包全 done"。

## 7. 回合、批次与收尾信号（最关键的一条）

- **轮（round）= 一次 assistant 回合**；**批（batch）= 一个可独立验收的工作单元，跨多个回合**。
  不要把回合当工作单元（真实：18 轮墙钟 17.2 分钟、均值 0.96 分钟/轮）。
- **只有三种情况允许结束回合**：
  1. **批次闭环**：本批产出至少一项——**真关条（账本 −1，且有当轮新读数）** / 经运行态回读证实的生效项 /
     已过门并提交的施工单元。**其中"生效项/过门提交"算半信号：连续两批只有半信号 ⇒ 必须先尝试补一次真关条；做不到则转裁决点（②）。**
  2. **人类裁决点**：已逐条列出候选与否决理由，并提出**明确一问**；
  3. **30 分钟自查点触发**。
- **不是收尾信号**（遇到必须继续推进）：汇报进度、等 worker 回传、整理文档、改措辞、收缩阻塞说明、写报告、
  **删除/暂停自查机制**（真实：T123 删掉 30 分钟自查，自判空跑却不升级）。
- **连续 2 个回合达不成 ① ⇒ 不要转成一问**：把范围切到「下一个能拿真读数的最小切片」并跑完；只有缺用户才能给的输入且无其他切片可推进时，才问一次。
- **每轮头条是产品可感知变化**（平台/功能能不能真跑起来、用户现在能做什么，带命令与读数）；四数行附在后面作核对，不许当进展本体。
- **每轮固定四数**：派工数 / 验收通过数 / 提交数 / 账本净变化。四数全 0 的回合就是空跑（但自查判据
  不得以"提交数/派工数"作未空跑的正证据）。

## 8. 进度汇报（用户只认数字）

```
总数 N（起点口径：…）→ 已关 X / 剩余 Y（严重 Z；其中 blocked B / accepted-risk C）
本窗口：关条 a（逐条 id+读数）、生效 b、提交 c、派工 d
证据：<每条一行：条目 → 命令 → 读数>
未答 needs-decision：<逐条列，下轮优先清>
风险/时间门：<3 条以内>
```

**硬规则**

- 每个数字给**可复跑的口径命令**（`grep -c` / 门输出 / 查询）；"权威数字"必须带生成命令 + 时间戳。
- 不许用叙事代替数字；"已推进很多"不是汇报。
- 先回答用户的问题，再干活；不要用执行动作回避问题。
- 用户问"卡点是什么" ⇒ 给"哪个条目 / 缺什么 / 谁解锁 / 复现命令"。
- 计划/报告要写**具名 owner + 到岗兜底 + 失败分级**（真实：PLAN.md 很完整，但窗口 owner 从未具名、HANDOFF 0 提及）。

## 10. 抗上下文压缩（行为回退的唯一解）

压缩会丢"我为什么要这样干"，所以**规矩必须在磁盘上，且压缩后第一动作是读它**。

- **规则三载体**：任何新规则必须在**同一轮内**落到三处至少两处：① goal objective ② 宪章/纪律文件 ③ 门（机械判据）。
  只写在回复正文的规则按"未生效"处理（真实：铁律 4 版，只在对话里的 v0/v1.1 当日失效）。
- **每轮 S1 从磁盘恢复**：宪章尾 → 批次台账尾 → 账本 §0 → 板卡 → 相关包 `run.md`/`VERSION`。不吃对话记忆。
- **压缩后第一件事**：读宪章 §0/§6/§7 + 报四数。**不许**先干活再回忆。
- **标准恢复三连**：`grep -cE '^### GAP-'`（账本标题数）/ `git log -1`（树头）/ 一条集群只读 `get`。
- **口头决定无效**：任何裁决必须落进「裁决记录」或宪章，否则视为不存在。
- **幂等**：幂等键 =（卡, 切片, 证据命令）；重跑同一轮不得重复记账或重复提交。
- **压缩摘要不是状态真源**：任何摘要里的计数（开放数/包状态/窗口数）一律作废，四数现场重取；
  摘要里新立的规矩必须当轮落到宪章/门并附出处，否则按"未授权新规则"处理。
  **摘要的正确用法**：读它的"错误与修复"节（审计实测该类断言 93% 准确、且主动自曝），跳过它的"数字/状态"节（54%/0% 准确）。
- **周期性自检**：每 5 轮一行 + 每 30 分钟四问（是否推进 / 完成多少 / 是否陷细节 / 下一轮唯一动作）。
  连续 2 轮空转时**禁止删除自查机制**。可用 `schedule_create` 建提醒；结论要落盘。

## 12. 出口与交接

**出口判据（三行实数 + 一行四数，不许含糊）**

```
code-ready x/N_pkg  ·  窗口已生效 y 项  ·  外部 blocked z 项（每条三要素齐）
开放 N_gap 条 / 其中 blocked B / accepted-risk C / 累计关闭 D / 本会话真关条 E；非终态 0
唯一验证：开放条目逐条归宿可判（关闭有当轮读数 / blocked 有三要素 / accepted-risk 有复核日）
```

**宣布完成前必须**：同屏打印上面四个数；`N_gap>0` **不得**自行 complete；自撰出口条款标「待用户确认」；
与账本证据冲突取更严者。**"包全 done 但清单没关"不是完成**（真实：30/30 done 时 70 条 open）。

**交接报告 `HANDOFF.md`**：三行实数 + blocked 按"谁能解锁"分组（产品裁决 / 跨仓制品 / 凭据外部 / 观察窗口）+
每组给**可执行解锁动作** + **具名 owner + 到岗兜底 + 失败分级** + 窗口待办配方 + 真源回填清单 + 存量红清单。

**纯时间门**：写成"到点时间 + 判定命令 + 期望读数 + 谁执行"；不许写成 blocked 混在开放账里。
