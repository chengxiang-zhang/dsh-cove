# 测量证据（Capacity / Benchmark）

> 一句话：**一个数字不是结论；能被重复、能被环境解释、能被对抗组推翻过，才是结论。**
> 这一条来自真实翻车（2026-10-30..11-01）：同一个采集容器，先后得出结论 700 req/s → 2310 → 5.7 万事件/s → "2C2G 过度配置" → "1.5C/1.5G 最优" → 30 分钟持续压测 OOM 两次全部推翻。四次作废的共同原因都不是服务端，是**测量链没锁住**。

## 0. 出口判据（先写，后测）

在动手前写清三行：
- **被测对象**：镜像/commit/清单、requests=limits、节点、命名空间（禁止中途换）；
- **要回答的问题**：一个数（可持续 EPS？峰值吸收？膝点位置？）而不是"看看性能"；
- **判据**：什么读数算"成立/不成立"（例：三次重复离散度 <15%；持续 30 min 0 OOM 且积压不单调增长；发送-落盘误差 <1%）。

没有这三行，不许跑第一轮。

## 1. 先锁测量链（三个假瓶颈，按顺序排除）

1. **压测器自身上限**：单进程生成器常只有 ~700–1300 req/s。先做"多生成器并行 vs 单生成器"对照；总速率不翻倍 ⇒ 你在测压测器。
2. **入口限流/网关**：`limit_req`、429、连接数上限、连接池。先数状态码分布（非 204/非 200 计数），再看服务端指标。
3. **落盘/下游**：S3/MinIO 写入带宽、buffer `when_full=block`、积压是否已满。**开压前先清积压并记录它**，否则测到的是排盘速度。

任何一条没排除 ⇒ 结论只能叫"在测量链 X 受限下的数"，不能叫容量。

## 2. 环境健康门（每个数据点开压前跑）

- Pod `Ready` 且 `restarts` 未涨；
- Service 端点非空（`rollout status` 返回不等于端点已就绪）；
- buffer/积压 < 10%，磁盘/内存无顶格；
- 上一次压测的生成器进程已退出；
- 记录实际配置快照（CPU/mem/epr/并发/生成器数）。

任一不过 ⇒ 这个点**作废**，不要写进表里再解释。

## 3. 重复性与噪声

- 每点**至少 3 次**，先算离散度；>15% ⇒ 测量不可信，先修测量再谈配置。
- 异常点**复测**，不许"挑一个好看的"；也不许把异常点直接当结论。
- 记录 p50/p95/p99，不只平均吞吐。

## 4. 突发 ≠ 持续（最常被混淆）

- 45–60 秒短测只能给**突发容量**；
- **持续容量**必须跑够（≥30 min），看：OOM/重启、积压趋势（是否单调涨）、内存是否贴顶、性能是否衰减；
- 结论里必须写明"突发 X / 持续 Y"，并给出**可持续操作点**（通常是膝点的 70%），不是一个虚数。

## 5. 曲线而不是单点

- CPU：0.5 / 1 / 1.5 / 2 核（找"加核不再涨"的膝点）；
- 内存：1.5 / 2 / 2.5 GiB（判断内存是不是瓶颈）；
- 上报形态：1 / 5 / 10 / 20 / 50 / 100 事件/请求（事件吞吐靠批量放大，必须分开报）；
- 每条曲线固定其它维度；覆盖必须写进配置快照。

## 6. 守恒与对账（防"收下了没存下来"）

- 发送量 vs 落盘量，按 `run_id` 核对，误差 >1% 判失败；
- 失败/重试/丢弃计数必须为 0 或解释清楚；
- 端到端延迟分布（p99）单独报，不用吞吐掩盖。

## 7. 对抗组（防作弊）

至少一组"关掉非热路径能力"的对照（后台归档/对账/监控进程），量化它们吃掉的容量；生产是"全能力"，不许靠关能力刷好看数字。
另加：限流放开 vs 默认、cold start 之后 vs 稳态、单条 vs 批量。

## 8. 归因顺序（结论前必答）

> 这个数**能不能被测量链解释**？

按顺序答：压测器？限流？落盘？积压？内存顶格？后台任务抢资源？全部排除后才允许说"服务端能力 = X"。
若发现是代码/配置缺陷（如归档脚本 740 MB 常驻、Sink 吞吐不足），**登记问题 + 修**，不要用"加资源"掩盖。

## 9. 结论写法（模板）

```
对象：<镜像@digest / 清单 commit / ns / requests=limits>
突发：<epr 形态> → <X 事件/s>（3 次，离散度 <n>%）
持续：<Y 事件/s> 30 min，OOM 0 次，积压 1→1MB，p99 <…>
瓶颈归属：<测量链 / 落盘 / 内存 / 后台任务>（证据：<读数>）
建议操作点：<70% 膝点>；扩节点判据：<…>
未验：<…>（逐条列，不许省略）
```

## 10. 禁止

- 单次测量直接下结论；
- 不写配置快照就跨点比较；
- 把"我在压测器上看到的"当"服务端能力"；
- 用"加资源"替代定位（先证明是资源瓶颈）；
- 结论里省略"还没验的项"。
