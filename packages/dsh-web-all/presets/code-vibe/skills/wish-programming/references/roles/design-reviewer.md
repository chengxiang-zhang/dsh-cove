# design 内建自查清单 — 设计规范单自查

> 用途：本清单由**阶段 2 设计规范单 agent**（pro）在生成设计规范单后**内建自查**使用，替代原「派发 2 个非作者独立只读 subagent 对抗对、conductor 组装 review-design.md」的评审仪式（AI 评 AI 不产生质量后果）。自查须逐项覆盖下方清单（产品架构段 + UX 段），每条结论附证据/理由。
> 建议档位：阶段 2 agent 用同 provider 强档（默认继承；换档用同族兄弟档）。

## 公共输入
- `docs/wish/<id>/quote.md`（用户原话逐字转录，最高优先级，必读）
- `docs/wish/<id>/requirements.md`（必读）+ confirmation-pack.md（若存在）
- 仓库设计系统文档 / 既有页面设计包（检查是否对齐，而非另起炉灶）
- 历史失败样本（自声明已读）

## 自查清单（产品架构段 + UX 段，逐项 通过/问题+证据）

0. **原话对照（最高优先级）**：读 `docs/wish/<id>/quote.md`，逐句核对本包是否忠实——命中以下任一 → 记 blocker：① 用户原话中的限定词/前提在复述中丢失或被替换（如「在 X 基础上升级」变成「推倒重画」）；② 转述与原话语义冲突；③ 原话里未出现的新增定性词/范围扩大未标注「PM 推断」且未经用户确认。

### A. 产品架构
1. **信息架构**：导航层级/页面树/模块归属单独成节且合理？「管理功能」是否被默认塞进 admin？
2. **模块定位**：每页/每区块回答「承载哪条任务流」？有无大杂烩页面？
3. **任务流完整性**：核心端到端链路（如 SQL→存为数据服务→绑定凭证→消费）作为主线设计？
4. **收敛一致性**：与统一/收敛方向一致？引用旧文档结论是否标注收敛前/后时效？

### B. UX
5. **用户语言**：界面文案用用户词汇而非治理/工程词汇（scope 表单即反例）？
6. **交互规格**：关键页面逐页交互规格（状态机/二次确认/乐观更新/快捷键），非「布局+字段」线框？
7. **四态覆盖**：空/加载/错误/权限逐页设计？「已达标/复用现网」每处附实测证据路径？
8. **触发时机**：用户何时进入、带什么上下文？事件/任务驱动还是浏览型 KPI 墙？
9. **对标纪律**：对标产品是「从用户任务出发选择性借鉴」还是逐条搬运？每条标 adopt/adapt/defer+落地约束？
10. **一致性**：跨页概念（状态词/入口/权限口径）统一？

## 自查纪律（吸收自原对抗对的攻击性检查）
- **反事实**：对每条结论问一句「若 X 相反会怎样？」，结论须在反面论证下仍站得住。
- **补丁检测**：对每个设计决策问「这是在满足需求，还是在给系统打补丁？若是补丁，最短的正确设计动作是什么？」。
