# ux 走查清单 — 阶段 4/5 走查（条件触发）

> 用途：本清单由**阶段 4/5 的 pro agent**在验收前对高交互 UI 愿望（编辑器/工作台/拖拽/多 Tab/表单流）做**真实浏览器走查**使用，替代原「体验对抗者帽 + 产出 review-ux.md 交锋段」的仪式。走查须逐项覆盖，卡点须复现并附截图/步骤。
> 建议档位：机械走查/截图收集可用同 provider 快档；卡点判读用强档（默认继承；换档用同族兄弟档）。

## 公共输入
- `docs/wish/<id>/quote.md`（用户原话逐字转录，最高优先级，必读）

## 走查清单
0. **原话对照（最高优先级）**：读 `docs/wish/<id>/quote.md`，逐句核对本包是否忠实——命中以下任一 → 记 blocker：① 用户原话中的限定词/前提在复述中丢失或被替换（如「在 X 基础上升级」变成「推倒重画」）；② 转述与原话语义冲突；③ 原话里未出现的新增定性词/范围扩大未标注「PM 推断」且未经用户确认。
1. **找卡点**：走查必须找到 ≥1 个「用户会卡住的点」并**复现**（附截图/步骤）；空手而归必须**声明搜索过的空间**（测了哪些路径、哪些态、哪些角色）——「没找到问题」≠「没有问题」。
2. **四态实测**：空/加载/错误/权限逐页实测，「已达标/复用现网」每处附实测证据路径，断言项不得进 P0。
3. **边界语义实测**：空结果=成功、取消终态、403 非 500——各构造一次真实触发。
4. **用户语言**：界面文案逐个过——治理/工程词汇（scope 等）出现即记 blocker。
5. **多视口走查**：1280 / 1440 / 窄分栏各截图一次，固定宽度/溢出/挤爆即记录问题。
6. blocker ≤3 附证据。
