# pm 内建自查清单 — 需求理解（PRD）自查

> 用途：本清单由**阶段 1 需求理解 agent**（pro）在生成 `docs/wish/<id>/requirements.md` 后**内建自查**使用，替代原「派发 2 个非作者独立只读 subagent 对抗对、conductor 组装 review-pm.md」的评审仪式（AI 评 AI 不产生质量后果）。自查须逐项覆盖下方清单，每条结论附证据/理由。
> 建议档位：阶段 1 agent 用同 provider 强档（默认继承；换档用同族兄弟档）。

## 公共输入
- `docs/wish/<id>/quote.md`（用户原话逐字转录，最高优先级，必读）
- `docs/wish/<id>/requirements.md`（必读）
- `docs/wish/<id>/confirmation-pack.md`（若存在，交叉验证理解一致性）
- 仓库 `docs/product/` 已立项方向文档与模块 README（本 wish 是否与已定方向冲突）
- 历史失败样本（gap-register / decisions，自查时自声明「已读」）

## 自查清单（逐项 通过/问题 + 证据）
0. **原话对照（最高优先级）**：读 `docs/wish/<id>/quote.md`，逐句核对本包是否忠实——命中以下任一 → 记 blocker：① 用户原话中的限定词/前提在复述中丢失或被替换（如「在 X 基础上升级」变成「推倒重画」）；② 转述与原话语义冲突；③ 原话里未出现的新增定性词/范围扩大未标注「PM 推断」且未经用户确认。
1. **模块定位**：定位是否具体到是什么/服务谁/边界？与已立项方向（收敛/退役/迁移）对齐？
2. **用户画像**：≥2 行且覆盖人类用户+下游消费方双层？Job-to-be-done 证据来源必填或标 Unverified？
3. **场景旅程**：≥3 条含 when/why/what？覆盖消费主线与治理支撑？「何时使用」有答案？
4. **IA 与收敛**：UI 类 wish 有导航层级/页面树/模块归属？与收敛框架关系显式标注？
5. **产品原则**：≥1 条不可违背承诺？每条映射至少一个设计决策？
6. **语义不变量**：≥1 条？与历史决策记录一致（防语义回退）？
7. **范围纪律**：Out-of-scope 显式？无越界新功能蓝图？
8. **决策记录**：用户拍板/纠偏逐条登记且含反方最强论点？

## 自查纪律（吸收自原对抗对的攻击性检查）
- **反事实**：对每条结论问一句「若 X 相反会怎样？」，结论须在反面论证下仍站得住。
- **攻击面声明**：找不到问题时逐项说明「查过什么、风险面在哪、为何安全」，不得以「没发现问题」代替「没有问题」。
