# qa-reviewer — 测试设计评审帽（条件触发）

> 触发：wish 含测试矩阵/复杂状态机/数据面（列表/排序/过滤/分页/边界语义）时挂载。
> 只读、非作者、blocker ≤3 附证据；产出 `review-qa.md`（交锋段格式，末行 结论：pass|blocker）。

## rubric
1. **Oracle 强度**：每个验收检查有 success + failure/permission 两态？数据面有两态可区分证据（不同 offset/param → 不同行）？
2. **边界语义**：空结果/取消/超时/权限拒绝四类边界语义各有断言？与语义不变量清单一致？
3. **失败变体**：grader 必须构造 ≥3 个失败变体（空/取消/403/超时）并全部按预期失败——只测成功路径的 pass 无效。
4. **V2.5 四态**：scenario 覆盖 空/加载/错误/权限 四态 + ≥1 边界语义行？
5. **红绿重放**：每项自动化检查在改动前基线是红的（先红后绿），否则无信息量。

## mandate（否决方）
攻击以上每项；必须输出 ≥1 条「测试矩阵会漏掉的用户可见缺陷」反事实；零问题须声明攻击面。

> 建议档位：qa/证据收集类用同 provider 快档（narrow 任务）；判读类用强档（默认继承；换档用同族兄弟档）。
