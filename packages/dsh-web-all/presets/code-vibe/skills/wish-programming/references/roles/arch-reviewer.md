# arch 内建自查清单 — 技术架构附加自查

> 用途：本清单由**阶段 2 的 pro agent 仅对技术架构类愿望附加内建自查**使用（生成 `docs/wish/<id>/arch.md` 后、阶段 3 之前），替代原「派发 2 个非作者独立只读 subagent 对抗对、conductor 组装 review-arch.md」的评审仪式（AI 评 AI 不产生质量后果）。自查须逐项覆盖下方清单，每条结论附证据/理由。
> 建议档位：同 provider 强档（默认继承；换档用同族兄弟档）。

## 公共输入
- `docs/wish/<id>/quote.md`（用户原话逐字转录，最高优先级，必读）
- `docs/wish/<id>/arch.md`（必读）+ requirements.md（交叉验证技术方案是否违背语义不变量）
- 仓库 `docs/architecture/09-decisions/` 历史 ADR（防决策回退）
- 已立项产品方向文档（验证「方向对齐」段属实）

## 自查清单（逐项 通过/问题+证据）
0. **原话对照（最高优先级）**：读 `docs/wish/<id>/quote.md`，逐句核对本包是否忠实——命中以下任一 → 记 blocker：① 用户原话中的限定词/前提在复述中丢失或被替换（如「在 X 基础上升级」变成「推倒重画」）；② 转述与原话语义冲突；③ 原话里未出现的新增定性词/范围扩大未标注「PM 推断」且未经用户确认。
1. **现状盘点 vs 结论**：盘点真实（Verified/Unverified 标注）？有没有「用现状差异否定收敛方向」的反向结论？
2. **方向对齐**：逐条标 符合/偏离/缺口？「偏离」有显式论证与用户拍板记录？
3. **方案选项**：≥2 方案？权衡矩阵覆盖 用户影响/迁移成本/回滚能力/演进空间？有没有把「工程上最安全」当唯一方案？
4. **语义不变量违背检查**：违背 requirements.md §4 语义不变量（凭证零失效/外部集成零打断/数据可恢复/存量功能零丢失）？不可逆方案是否书面论证「零失效/可恢复方案为何不可行」？
5. **语义不变量**：实现是否保持产品语义（空结果=成功等）？有无为「机器可读性」牺牲用户语义？
6. **影响面**：调用方/接口/数据/回滚点列全？有「用户可见变化」一行（等待时间/体积/失败率/失效面）？
7. **ADR 完整性**：决策/背景/选项/后果/状态齐全？不可逆决策登记 `09-decisions/`？
8. **边界纪律**：跨面/跨域操作（SR 引擎面 vs 服务面）显式 Out-of-scope？「评估/降级/登记」弱化项逐条列明？
9. **架构定位四问**：归属/债务（预算+偿还时机）/路线图联动/前瞻扩展点——四问全部有答案？

## 自查纪律（吸收自原对抗对的攻击性检查）
- **反事实**：对每条结论问一句「若 X 相反会怎样？」，结论须在反面论证下仍站得住。
- **事故路径/补丁检测**：对每个方案问「让它在生产出事故的最短路径是什么？」「这是架构动作还是补丁？若是补丁，正确的最小架构动作是什么？」；找不到问题时逐项说明攻击面与事故路径为何走不通。
