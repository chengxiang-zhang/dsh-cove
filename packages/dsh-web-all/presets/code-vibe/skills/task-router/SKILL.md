# Task Router（分档开关）

入口唯一闸门：**先分档，再动手**。档位决定流程强度、工件、证据与预算；避免"小任务被流程化、大任务被裸干"。

> 一句话：**简单任务快、中任务稳、大任务才开环。** 档位是模型判断，不是问卷；用户可一句话改档。

## 0. 时机

```
T0 收到请求
T1 只读侦察（≤3 次：读需求/看目录/一条复现命令）——禁止写文件、禁止 spawn
T2 * 分档（本 skill）——写任何文件/派任何 agent 之前的唯一闸门
T3 宣告（4 行）→ 用户可一句话改档
T4 按档执行（加载对应路径 skill）
T5 重估：每 5 轮 / 每里程碑 / 每次压缩后 / 触发升级条件 → 回到 T2
```

## 1. 档位判定（5 维，每维 0/1/2，合计 0–10）

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| D1 交付物 | 答案/解释 | 一处可运行变更 / 文档 | 多模块系统 / 清单收口 |
| D2 触达面 | 0 文件 | ≤2 文件 / 单模块 | ≥3 文件 / 跨模块 / 跨仓 / 改契约·数据·权限 |
| D3 不可逆性 | 纯只读 | 本地可回滚 | 动环境/数据/生产/外部系统 |
| D4 判据清晰度 | 验收门现成 | 可推导（写 1–3 条） | 需用户拍板 / 无判据 |
| D5 时长与并行 | ≤10 分钟 | ≤3 小时 / ≤10 轮 | >1 天 / 需 ≥2 agent |

| 总分 | 档位 |
|---|---|
| 0–1 | **T0 Answer** |
| 2–3 | **T1 Fix** |
| 4–6 | **T2 Change**（spec / wish / ops 三变体） |
| 7–10 | **T3 Program**（program / wish 两变体） |

**三条覆盖规则（优先于总分）**

1. **D3=2 ⇒ 最低 T2**，且必须有回滚 + 真人授权；
2. **D1=2 且 D2=2 ⇒ 直接锁 T3**（防大任务裸干）；
3. **D4=2 且要拍板 ⇒ 先人闸**，不许带进 T3 长跑。

**默认不对称**：不确定时，仅当 **D3≥1 或 D2=2** 升一档；纯本地可回滚单文件保持低档。
**单向锁**：T3→T0/T1 的误判不允许——D1=2 且 D2=2 时不得自行降档。

## 1.5 设计意图（DESIGN INTENT，不是第六维）

命中以下任一 ⇒ `design=on`，先加载 `design-orchestrator`（再由它分派 8 个领域设计 skill）；否则 `design=off`，不许产出设计件：
- 请求含设计意图词：设计/方案/架构/IA/信息架构/交互/视觉/用户体验/研究/选型/对比/迁移/重构/商业模式/定价；
- 判档 ≥T2 且涉及结构（跨模块/跨仓）、契约/数据/权限、用户可见面变化、不可逆动作。

`design=on` 时先声明：`设计层=<命中层> · 档=<L1/L2/L3> · 必做件=<…> · 评审=<角色> · 冻结=<何时>`，然后**必须加载 `design-orchestrator` 并写出该档最小件**（至少 `docs/design/<id>/brief.md` + 对应层最小文件）。
**只给口头建议、不落设计件 = 违规**（设计意图命中时的硬规则；除非用户明确说"只要口头结论/先别落文件"）。
反例（design 必须 off）：既有模式复制、单文件可回滚小修、纯调研、设计已冻结直接施工。

## 1.6 执行体路由（谁来执行，不是"多大任务"）

**判据：这件事的判据是否已经完备。** 判据不完备 ⇒ 差距在推理深度上，派强模型；判据完备 ⇒ 本栈直接做。
不按任务大小判：一个两行的鉴权改动可以从"完备"变成"不完备"。

| 任务形态 | 判据完备？ | 执行体 |
|---|---|---|
| 架构设计 / 技术选型 / 新结构 / 跨模块契约 | 否 | **强模型档**（顺序见下），本栈负责写件、验证、合成 |
| 复杂排障 / 根因未知 | 否 | **强模型档**出竞争假设集与证伪实验，**本栈执行实验**并收敛 |
| 规格完备的实现 / 多文件改动 / 长跑迭代 | 是 | **本栈**（实现不派出去） |
| 探索 / 搜索 / 大文件摘要 / 批量小改 | 是 | 本栈（或便宜档子代理扇出） |
| 一致性 / 契约 / 交叉引用审计 | 是 | 本栈 fresh 子代理 |

**强模型档内的固定顺序（不许自选）**：`subagent_astra`（codex + ChatGPT 订阅）→ `subagent_opus55`（claude code + opus 5.5；**订阅断了直接换这个**）。

路由纪律：
- **派一次就够**，默认单路；第二路只在带**不同攻击切片**时开。
- 派发内容与格式见 `design-dispatch`。
- 每个强模型派发都记一行 `escalation_reason`（判据不完备 / 订阅不可用 / 需要外部视角），月底看这个分布：多数失败是"packet 没写清"就改 packet，不是多派。

## 2. 上下文可容性（规划门，不计分）

估算：`固定 19K + 读取(行×12~15) + 工件(0.5–2K/件) + 证据(≤2K/条) + 轮数×3~5K`。

| 分类 | 估算 | 动作 |
|---|---|---|
| `fit` | ≤250K | 主会话单弧完成 |
| `slice` | 250–400K | 切 2–4 段 + 检查点（段间写 STATE） |
| `delegate` | >400K | 不在主会话读：拆 fresh subagent（每个 ≤150K），只收摘要+证据指针 |
| `program` | >400K 且 ≥10 条/≥3 模块 | T3 + 分阶段换会话 |

**主会话区段**：绿 ≤250K / 黄 250–400K（停大读取、卸载/派工、写检查点）/ 橙 400–550K（写 HANDOFF，优先换会话）/ 红 >550K（禁止新工作）。
**硬规则**：主会话不通读大语料（>2K 行目录、全量日志、全仓 grep 结果）；大读取一律委派。

## 3. 并发图（规划门，不计分）

**并行六判据（全满足才并行）**：写域不相交 / 无共享写者 / 无环境窗口重叠 / 无相互依赖 / 各自独立验收 / 失败不互相污染。

**必须串行**：需求与设计决策、用户门、环境写（apply/DDL/重建/rollout）、共享文件（账本/INDEX/宪章/批次/板卡/commit）、同文件编辑、有依赖的步骤、验收与提交。

**波次**：W1 并行（只读/独立切片）→ W2 串行（决策/用户门）→ W3 并行（写域不相交）→ W4 串行（独立验收→过门→提交）。
**上限**：`max_parallel = min(运行时上限（实测 5）, 独立写域数, 环境窗口数)`；只读扇出 ≤8/波且有汇总去重。
**只读不占 lane**：只读/取数/调研/分析/量测类并行不需要工作树隔离——没有仓内写入就不建 lane，中间产物写 `/tmp` 或仓外；lane 只在「同一仓 2+ 个独立**写**任务并行」时成立（硬门见 `lane-worktree`）。被 checkout 占用门拒绝时先答一个问题「我到底要不要写这个仓」：不写就换仓外路径重试，不要为拿一个干净工作树去建 lane。

## 4. 宣告（4 行，必贴）

```
【档位】T2-spec（D1=1/D2=2/D3=1/D4=1/D5=1 → 5 分）
【上下文】estimate=60K · zone=green · checkpoints=[W2,W3] · handoff_at=400K
【并发】W1 只读×3 ∥；W2 决策（串行）；W3 实现×2 ∥（写域不相交）；max_parallel=2
【工件与门】spec/tasks/acceptance（含 Plan Card）；目标测试+负控+独立复跑；2–4h / ≤12 轮
```

**override 词表**：用户说"直接做/简单点/别搞流程" ⇒ 降 1–2 档；"按程序来/开环/带团队/上账本" ⇒ 升 T3；
"先调研" ⇒ 先 TR。用户 override 高于模型判断，必须记录一行。

**换档日志**：`docs/changes/<id>/triage.log`（T2）或宪章轮日志（T3）：
`T5 T1→T2 触发=第 3 个文件；新工件=acceptance.md`。

## 5. 升降级触发器

| 触发 | 从→到 | 动作 |
|---|---|---|
| 第 2 次失败 / 波及第 3 个文件 / 发现契约·数据·权限影响 / 需设计选择 | T1→T2 | 停手，补 acceptance+plan；保留 diff 作证据 |
| ≥10 条 open / ≥3 模块 / >1 天 / 需 ≥3 并行 / 第二次压缩 / 出现外部账本 | T2→T3 | 先过价值门与合并设计，再开环 |
| 设计规范单 >4 页面族/模块 | T2-wish→T3 | 拆 wish 的 WHAT + program 的 HOW |
| 剩余 ≤2 条且 ≤1 模块 | T3→T2 | 收尾降档：保留四数与 HANDOFF，停止开新卡 |
| 生产/预发不可用、数据损坏、安全 | any→TX | 止血优先：回滚/隔离 → 报用户要授权 → 再根因 |
| 调研结论要求实施 | TR→T2/T3 | 先交 findings+gap+handoff |
| 用户说"直接做/简单点" | 降 1–2 档 | 立即改档并记录 |
| 用户说"按程序来/开环/带团队" | 升 T3 | 立即改档 |
| 结论要冻结/进 ADR，或本地两轮无新证据 | 升级复审 | 加载 `design-dispatch`：默认只派 **一路** 外部强 agent（`subagent_astra` 结构化审阅 / `subagent_opus55` 探查），finding 本地复现才计入；别用同一份 packet 跑两路 |

## 6. 各档最小契约（细节在对应路径 skill）

| 档 | 路径 skill | 最小工件 | 证据下限 | 预算 |
|---|---|---|---|---|
| T0 | 无（本 skill 规则） | 无 | E1（事实） | ≤2 轮 |
| T1 | `fix-loop` | 3 行报告 + diff | E1（先红后绿） | 15–30 分钟 / ≤4 轮 |
| T2 | `change-spec`（spec/wish-lite/ops） | spec+tasks+acceptance（含 Plan Card） | E2 + 负控 | 2–4h / ≤12 轮 / 1–2 agent |
| T3 | `large-backlog-program` + `agent-team-project-loop`；T3-wish 用 `wish-programming` 全路径 | 账本+宪章+批次+板卡+HANDOFF | E2+E3 | 轮数推导 + 2×硬顶；单会话 ≤60–80 轮 |
| TR | `research-brief` | findings + gap | 来源+覆盖 | 按问题 |
| TX | `incident-runbook` | incident + 复盘 | 止血读数 | 立即 |

## 7. 常见误判（反例）

| 误判 | 后果 | 纠正 |
|---|---|---|
| 按关键词触发产品门（页面/设计） | 20 分钟小改也要确认包 | 先看 D1/D2：单页面族小改走 T2-wish 短路径 |
| 看到"重构/迁移"就上 T3 | 仪式化、空转 | 看 D1/D2：单模块 ≤2 文件走 T2；≥3 模块才 T3 |
| 大任务当成 T1 裸干 | 半成品/上下文爆 | 单向锁 + 第 3 个文件触发器 |
| 把"调研"做成"边调研边改" | 产出越界、无 handoff | 先 TR，findings 后转档 |
| 只读分析任务撞上 checkout 占用门就去建 lane | 建 lane 后仍无写入点，还会在消费仓里找不到脚本而空转 | 先判有没有仓内写入：无写入就把产物放 `/tmp` 或仓外重试，不建 lane（见 `lane-worktree`） |
| 不等确认就动生产 | 不可逆 | D3=2 ⇒ 最低 T2 + 授权 |

## 10. 路径补充（2026-11-01，来自真实会话审计）

| 触发 | 路径 | 为什么不能裸干 |
|---|---|---|
| 容量/压测/规格/吞吐/延迟/p99/"为什么性能这么差" | `measurement-evidence` | 单次读数不是容量：测量链（生成器/限流/落盘）、重复性、持续 vs 突发、守恒、对抗组缺一就出假结论 |
| "完成了吗 / 现在还有什么问题 / 能宣布完成吗" | `ledger-close-not-construction-done` | 施工完成 ≠ 关条；关条三元组（条目 + 自证门 + 本轮读数）缺一即未关 |
| 架构/产品/IA/交互/选型/设计方案 | `design-orchestrator`（先判 L1/L2/L3） | 领域设计 skill 不能替代编排：未判层就会给出过度/不足的设计件，且绕开冻结门 |
