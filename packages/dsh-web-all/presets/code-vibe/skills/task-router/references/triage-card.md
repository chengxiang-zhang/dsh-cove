# 分档卡（Triage Card）

## 评分

| 维度 | 0 | 1 | 2 | 本题得分 |
|---|---|---|---|---|
| D1 交付物 | 答案 | 一处可运行变更/文档 | 多模块系统/清单收口 | |
| D2 触达面 | 0 文件 | ≤2 文件/单模块 | ≥3 文件/跨模块/跨仓/改契约·数据·权限 | |
| D3 不可逆性 | 只读 | 本地可回滚 | 动环境/数据/生产/外部 | |
| D4 判据清晰度 | 门现成 | 可推导 | 需用户拍板 | |
| D5 时长与并行 | ≤10 分钟 | ≤3 小时/≤10 轮 | >1 天/需 ≥2 agent | |

合计：___ / 10 → 档位：T0(0–1) / T1(2–3) / T2(4–6) / T3(7–10)

覆盖规则：D3=2 ⇒ 至少 T2；D1=2 且 D2=2 ⇒ 锁 T3；D4=2 ⇒ 先人闸。

上下文：估算 ___K → fit/slice/delegate/program；区段：绿/黄/橙/红。

并发：W1 ___ ∥；W2 ___；W3 ___ ∥；serial=___；max_parallel=___。

## 例子 1：修测试（T1）

- 任务："把 test_orders 修绿"
- 评分：D1=1（一处变更）/D2=1（1 测试+1 实现，≤2 文件）/D3=1（可回滚）/D4=0（测试现成）/D5=0（分钟级）→ **3 → T1**
- 上下文：~15K → green
- 并发：单线程
- 宣告：T1；无工件；pytest test_orders；15–30 分钟

## 例子 2：加筛选（T2-spec）

- 任务："orders 接口加 status 筛选"
- 评分：D1=1/D2=2（路由+服务+测试，3 文件）/D3=1/D4=1（需写 3 条判据）/D5=1（小时级）→ **6 → T2-spec**
- 三事实：gaps=无 / irreversible=无 / footprint=3 文件
- 上下文：60K → green；checkpoints W2/W3
- 并发：W1 读×2 ∥；W2 决策；W3 实现+独立验收（基本串行）；max_parallel=2
- 宣告：T2-spec；spec/tasks/acceptance；目标测试+负控+独立复跑

## 例子 3：收 40 条 gap（T3-program）

- 评分：D1=2/D2=2/D3=1（树内）/D4=1/D5=2（多天）→ **8 → T3-program**
- 三事实：gaps=有（产品裁决 9 条）/ irreversible=有（窗口）/ footprint=全仓
- 上下文：>400K → program；分阶段换会话
- 并发：4 个方案组中写域不相交的可并行；账本/提交串行
- 宣告：账本+宪章+批次+板卡+HANDOFF；四数；轮数推导（如 40×3÷3×1.3≈52 轮，硬顶 104）
