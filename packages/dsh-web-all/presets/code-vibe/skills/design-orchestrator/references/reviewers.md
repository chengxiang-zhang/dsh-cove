# 设计评审角色（agent 扮演）

每个角色只看自己层、只给判据结论，不替代其他角色。

| 角色 | 看什么 | 判据（逐条） | 输出 |
|---|---|---|---|
| `pm-reviewer` | 商业/产品 | 目标与范围、Out 清单、优先级依据、GWT 可验收、度量可采、未决有归属 | 通过/带条件/退回 |
| `ux-reviewer` | UX/可用性 | 研究问题可回答、方法-问题匹配、样本与偏差、发现可追溯、含义可执行 | 同上 |
| `ia-reviewer` | IA | 树层级、命名可理解、归属唯一、跨页规则、测试计划可执行 | 同上 |
| `design-reviewer` | 交互视觉 | 状态齐全（空/载/错/满/无权限）、载体有判据、视觉方向一致、token 化、渲染证据真实、生成感/可读性 | 同上（主观项写明理由） |
| `arch-reviewer` | 架构 | 决策边界、备选与否决理由、质量属性预算可验证、边界/依赖、演进信号读数、回滚可行 | 同上 |
| `sre-reviewer` | 运行/可靠性 | 容量/延迟/SLO、故障域、部署与回滚、可观测 | 同上 |
| `security-reviewer` | 安全 | 权限/数据边界、密钥、供应链、攻击面 | 同上 |
| `tech-lead-reviewer` | 技术设计 | 接口冻结、数据迁移可逆、负控可执行、实现风险 | 同上 |

**规则**：
- 每份结论必须引用工件位置（`docs/design/<id>/...`) 与具体条目；
- 机械可查项（文件/字段/ADR 状态/freeze 哈希）由门禁查，**reviewer 不重复查**；
- reviewer 不得改写设计件，只写 `review.md` 的结论段；
- L2/L3 的最终确认由用户给出，记录在 `freeze.md` 的 `user_confirmation`。
